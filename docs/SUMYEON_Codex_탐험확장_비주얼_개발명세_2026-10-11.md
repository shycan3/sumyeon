## 1. 목표와 사용자 피드백

### 1.1 실제 플레이 관찰

사용자는 직접 탐험하면서 **예상보다 길찾기가 어렵다**고 평가했다. 수평적 화살표 탐험에서 공간을 머릿속에 기억하기 어렵고, 탐험이 노드 버튼 선택의 연속처럼 느껴지는 것을 개선하고자 한다.

### 1.2 이번 확장의 경험 목표

- **과거:** 지나온 위치·연결을 기록해 불필요한 길찾기 기억 부담을 줄인다.
- **현재:** 네 방향에서 들리는 소리·보이는 현상·느껴지는 변화가 실제 공간처럼 느껴지게 한다.
- **미래:** 징후를 근거로 미탐사 통로의 위험·보상·이상현상을 *추측*한다.
- **결과:** 방에 진입해 단서를 확인하고, 선택형 사건에 대응하고, 덱·체력·탐험 시간을 관리한다.
- **캐릭터:** 서브컬처 게임답게 동료가 가끔 자연스러운 감정·성격 중심 대사로 반응한다.
- **세계관:** 심층별로 공개된 환경 법칙이 탐험/전투의 선택을 바꾼다.
- **미술:** 일부 장소의 아트·UI·초상화를 통해 *실제 완성 게임에 가까운 장면*을 소규모로 검증한다.

**성공 판단:** 더 많은 시스템을 넣었는지가 아니라, 플레이어가 징후를 기억하고 경로를 선택하며, 발견을 납득하고, 동료의 개성을 느끼고, 공간을 시각적으로 구분할 수 있는가.

## 2. 방문 경로 지도 및 빠른 이동

### 2.1 기록/표시 [확정]

1. 현재 심도에서 **직접 들어가 본 방**을 지도에 표시한다.
2. 실제로 이동하여 확인한 **방 사이의 경로**를 자동 기록한다. 재방문해도 기록은 남는다.
3. **미방문 방의 내부 콘텐츠·정확한 이름·연결구 위치를 공개하지 않는다.** 현재 위치에서 연결된 미탐사 출구는 `?`나 짧은 열린 통로 표시로 구분 가능하다. 아직 접근하지 못한 더 먼 전체 맵은 숨긴다.
4. 현재 위치, 방문한 방, 확인된 통로, 미탐사 출구, 이미 드러난 조사 대상/해결 여부를 시각적으로 구분한다.
5. 지도 열람은 **시간 0 / HP 비용 0**이다. 미니맵 또는 접이식 요약 표시는 UI 공간·모바일 레이아웃을 고려해 우선순위를 정한다. 전체 발견 지도의 가독성 개선은 필수다.
6. 심도별 발견 지도는 현재 저장 구조와 같이 구분 유지한다. **지나간 심층으로 무료 역이동하는 기능은 포함하지 않는다.**

### 2.2 이동의 비용 — 가장 중요한 확정 규칙

| 행위 | 시간 비용 | 자연 회복 | 비고 |
|---|---:|---|---|
| 화살표로 **미방문 방**에 직접 이동 | 기존 `moveCost` | 시간 지불분에 비례 | 기존 `Session.move()` 규칙 유지 |
| 화살표로 **방문한 방**에 직접 이동 | 기존 `moveCost` | 시간 지불분에 비례 | **절대 무료로 바꾸지 말 것** |
| 지도에서 방문한 방으로 **빠른 이동** | **0** | **없음** | 확인한 경로만 이용, 즉시 도착 |
| 시간이 0일 때 직접 이동 | 시간 부족분에 따른 기존 HP 비용 | 자연 회복 없음 | 기존 시간→HP 시험 정책 유지 |
| 시간이 0일 때 지도 빠른 이동 | **0** | **없음** | 확인된 경로라면 가능 |

**사용자 의도:** 플레이어는 동일한 방문 경로를 **무료로 건너뛰어 시간을 절약**할 수도 있고, **화살표로 일부러 왕복하여 시간을 체력 회복으로 교환**할 수도 있다. 이 둘이 서로 다른 전략이라는 점을 반드시 보존한다.

**주의: 사용자에게 선택형 '유료 자동 도보 이동' 버튼을 추가하는 이전 제안은 명시적으로 채택되지 않았다.** 이번 단계에서는 구현 범위에서 제외한다. 지도 클릭 = 무료 빠른 이동. 화살표 클릭 = 비용 있는 실제 이동.

### 2.3 빠른 이동의 경로 검증 [확정 + 구현 정책]

- 허용 조건: 현재 원정의 현재 심도, 탐험 진행 상태 `EXPLORING`, 유효한 대상 노드, 과거에 방문한 대상, **실제로 밟아 확인한 통로들만** 이용한 연결 경로가 존재함.
- 빠른 이동은 단순히 `run.nodeId = targetId`만 하는 무검증 텔레포트가 아니다. 발견된 경로 그래프 위에서 BFS를 계산하고 실행 전에 목적지의 유효성을 재검증한다.
- 최초 구현에서는 *실제 통과한 간선*을 기록(`traversedEdges`)하여 그 간선으로만 경로를 구성하는 보수적 정책을 권장한다. 이미 방문한 양쪽 방 사이에 통로가 있다는 사실만으로 그 통로를 실제로 지난 것으로 간주하지 않는다.
- 미방문 노드, 미발견 연결구, 잠긴 경로, 해결하지 않은 **이동 차단 장애물**을 건너뛰면 안 된다. 현재 게임의 선택형 전투는 기존처럼 회피 가능하고, 연결구 수문장은 **하강 시에만** 필수이므로, 단순 통과를 막는 규칙을 임의 추가하지 않는다.
- 빠른 이동 자체에 새로운 조사·보상·전투 진입·HP회복·시간 소모·일반 화살표 이동 카운터(`moves`)나 오퍼레이터 발신 트리거를 발생시키지 않는다. 단, `fast-travel` 고유 로그 및 위치 갱신은 기록한다.
- `COMBAT` / `REWARD` / 귀환·실패 상태에서 이용할 수 없다. 강제 이벤트 중에는 상태상 이동을 막는다.
- **시간=0에서도 무료 빠른 이동 가능.** 이를 이용해 HP를 회복하거나 자원을 재생성할 수 없도록 한다.
- 방문한 방을 목적지로 지도에서 클릭·터치 및 키보드로 선택한다. `현재 위치로 이동`은 아무 변화 없는 조작으로 처리한다.
- 기존 `returnHome()`의 현 위치 무료 귀환은 그대로 유지한다.

### 2.4 저장 구조와 마이그레이션 [필수]

현재 `map.nodes[].visited`는 존재하지만 **간선 통과 여부는 별도로 저장하지 않는다**. 따라서 새 저장 스키마는 이전 버전과 호환되게 설계한다.

- 권장: 심도별 맵에 `traversedEdges`를 저장하거나 원정별 `traversalByDepth`를 사용한다. 간선은 두 노드 ID를 정렬한 안정적인 키로 중복 없이 기록한다.
- 기존 저장을 복구할 때 **방문한 두 방 사이의 모든 연결을 이미 통과했다고 임의 추정하지 않는다.** 기존 `telemetry`의 `move` 이벤트(이전/이후 노드 정보로 복원 가능한 범위)를 활용하거나, 불가능하면 해당 구간의 무료 이동을 보수적으로 제한한다. 저장이 유효한데도 전체 초기화하도록 만들지 않는다.
- `Session.assert()`, `canonicalMap()`의 정적 맵 비교, `staticMap()`의 동적 상태 제거 대상에 새 필드를 반영한다. 맵 재생성 검증을 훼손하지 않는다.
- `r.moves`가 무전 힌트를 4회마다 트리거하는 현행 구조를 유지하고, 빠른 이동이 이를 반복 발화시키지 않도록 테스트한다.

## 3. 공간 징후 — 방향별 짧은 문장

### 3.1 기본 계약 [확정]

- 현재 방에서 **실제로 통로가 있는 동·서·남·북 각 방향**에 대해, 그 방향 너머에서 감지되는 특징을 **짧고 자연스러운 한국어 문장(기본 1~2문장)**으로 제공한다.
- 감각적 묘사 중심: 소리, 빛, 냄새, 온도, 진동, 기류, 공간, 시간, 생물의 흔적, 술식 흔적 등.
- **환경 징후의 텍스트는 실제 목표 방의 콘텐츠와 인과적으로 연결**되어야 한다. 보물·전투·사건 분류 결과를 직접 알려주는 `위험`, `보상`, `전투 확정` 등의 메타 태그를 플레이어에게 붙이지 않는다.
- **징후는 불완전한 단서일 수 있지만 무작위 거짓 정보여서는 안 된다.** 오해가 가능한 상황에서도 플레이어가 나중에 그 문장의 근거를 납득할 수 있어야 한다.
- 방문·해결한 방향에는 기존 장소 이름과 확인된 정보(조사 완료, 해결한 위협 등)를 우선 표시한다. 미방문 방향에서는 결과를 미리 누설하지 않는다.
- **같은 세계/시드/노드/방향/사건 상태라면 같은 징후가 보인다.** 출입 때마다 새 문장을 재추첨하지 않는다.
- 여러 징후가 있는 특별한 방에는 간혹 복합 징후를 제공한다. 모든 문에 장문 두 개 이상을 강제하지 않는다.
- 사건 해결 이후 실제 환경 상태가 변화했다면 징후가 적절하게 달라질 수 있으며 그 이유가 기록상 일관적이어야 한다.
- 징후를 읽는 데 별도 자원 소모가 없다. 시간을 써서 정밀 관측하는 추가 미니게임/게이지는 **이번 단계에 넣지 않는다**.

### 3.2 ‘5종 vs 10종’ 최종 설계 구분

**5개만 만들자는 뜻이 아니다.** *게임 내부 의미*와 *표현 형태*를 나눌 것.

- **게임플레이 의미 계층:** 약 **5~6개** 내부 그룹부터 시험. 예: `threat`(생명·위협), `resource`(자원·술식), `safe`(안정·시설), `anomaly`(공간·변칙), `unknown`(미확인), 필요 시 `narrative`(서사적 흔적). 내부 분류 수는 콘텐츠/보상 설계에 따라 조정 가능하다.
- **감각·표현 계층:** 최소 **10개 계열**을 고려. 소리 / 빛 / 냄새 / 온도 / 진동 / 기류 / 공간 / 시간 / 생물학적 흔적 / 술식 반응.
- **초기 실험 문장 풀:** 약 **30~50문장**을 데이터로 관리하고, 병원·도시·역 각 테마의 어휘와 소품을 달리한다. 이 수량은 출시 분량이 아닌 [시험] 범위다.
- 내부 의미 분류나 감각 분류를 그대로 플레이어에게 노출하는 UI는 기본 제공하지 않는다. 플레이어는 문장을 직접 읽고 추측한다.

```js
  biomeIds: ['hospital'],
  semanticGroup: 'threat',      // 플레이어에게 노출하지 않음
  sensoryMode: 'sound',        // 플레이어에게 노출하지 않음
  requires: ['adjacent-encounter'],
  text: '문 안쪽에서 무언가 바닥을 긁는다. 소리가 문 바로 앞에서 멈춘다.',
  rarity: 'common',
  stateVariant: 'unresolved'
}
```

- `adjacent-encounter`, `interaction-record`, `event-type`, `lawId`, `resolved` 등 **실제 생성된 콘텐츠**로 문장 후보를 결정한다.
- 문장 풀 선정은 별도의 결정론적 해시(`seed + depth + fromNodeId + direction + stateVersion`)로 계산해 카드 보상·조우·맵 생성용 RNG 흐름을 바꾸지 않는다.
- 사물이나 조우가 없는 방에도 분위기 단서는 존재할 수 있다. 다만 보상이나 적을 *약속하는 문장*은 실제 보상/적과 연결한다.
- 숨은 맵 정보를 활용해 문장을 생성하는 것은 허용하지만, 해당 정보는 전송/노출 경계를 구분한다. 기존 브라우저 단일 런타임 특성상 클라이언트에 전체 시드 맵이 있어도 **UI에서 스포일러를 노출하지 않는 것**이 요구사항이다.

### 3.4 화면 예시 [콘텐츠 시험안]

**북쪽 — 수술실:** “꺼진 수술실에서 금속을 내려놓는 소리가 들린다. 잠시 뒤 같은 소리가 반복된다.”  
**동쪽 — 어두운 복도:** “문 너머에서 무언가 바닥을 긁는다. 발소리인지는 알 수 없다.”  
**남쪽 — 병실:** “오래된 약품 냄새가 새어 나온다. 문틈에는 희미한 불빛이 보인다.”  
**서쪽 — 이미 방문한 대기실:** “조사를 마친 대기실로 이어진다.”

문장, 방 이름, 캐릭터 대사는 예시이며 고정 스토리 캐논이 아니다.

### 3.5 오퍼레이터와 역할 구분 [확정]

- **공간 징후:** 가까운 통로의 환경 단서(상시 표시, 재열람 가능).
- **지상 오퍼레이터:** 기존 무전에서 연결구 방향 등 넓은 범위의 정보를 제공. 현재 `updateHint()`/`hintHistory` 흐름과 공존한다.
- **동료 대사:** 징후에 대한 개인적인 감정·성격 반응. 아래 §5 참조. 오퍼레이터의 전문 분석과 동료 일상 대사를 혼동하지 않는다.

## 4. 심층별 「수면의 법칙」

### 4.1 공개 방식 [확정]

- **해당 심층에 진입하는 즉시 법칙을 공개한다.** 탐험하며 숨겨진 규칙을 추리해야 하는 설계는 채택하지 않는다.
- 진입 연출/패널에 **법칙명, 정확한 게임 효과, 적용 대상(아군/적/탐험), 발동 조건, 수치**를 보여준다.
- 탐험 화면과 전투 중 언제든 다시 열어 확인할 수 있다. 반복 원정에서는 연출 건너뛰기/축약을 지원한다.
- **수면의 근본적 정체와 서사적 비밀**은 여전히 비공개일 수 있다. **숨기는 것은 스토리이지 전투 규칙이 아니다.**
- 심도가 깊어지는 의미를 단순한 적 수치 상승이 아닌 게임 규칙 변화로 표현한다.

### 4.2 첫 실험용 법칙 후보 [시험 — 수치/내용 미확정]

| lawId 후보 | 가칭 | 작동 방식 예시 | 설계 의도 |
|---|---|---|---|
| `residue` | 잔류 | 라운드 종료 뒤 남은 보호막의 일정 비율 유지. 아군·적 모두 해당 | 방호 카드의 가치와 대처 변화 |
| `excess` | 과잉 | 아군·적의 직접 피해가 함께 증가 | 공격적 전술과 위험 관리 교환 |
| `stasis` | 정체 | 조사 시간 감소, 시간에 따른 자연 회복 효율도 감소 | 탐험·회복 선택 변화 |

- 상기 내용은 **실험 후보**다. 예시의 ‘보호막 50%’ 같은 수치는 확정값이 아니다.
- 초기에는 **심층당 법칙 1종**을 권장한다. 3종 모두 데이터와 개별 테스트를 갖춰 실험하되, 조합법칙/3단계 난도 확대는 사람 플레이 이후 판단한다.
- 법칙은 특정 카드 계열에만 주는 단순 보너스가 아니라 환경 규칙이어야 한다. `residue`와 `excess`처럼 아군·적에 대칭 적용되는 경우를 우선 고려한다.
- 작동 시 로그·전투 상세 정보에 **어떤 법칙이 어떻게 수치에 영향을 줬는지** 검증 가능하게 표시한다. 기존 `PartyExpedition.Battle`을 무분별하게 변형하지 않고 새 탐험의 어댑터/분리 모듈에서 적용한다.
- 법칙으로 비용이 0이 될 때도 기존 전투 시간 정지, HP 소수 버퍼, 전투불능 회복 금지, 위험행동 확인 등의 불변식을 회귀시키지 않는다.
- **법칙의 적용은 같은 시드·심도에 대해 결정론적이고 저장/복원 이후 동일**해야 한다. 심층 진입 전에 다음 법칙을 미리 공개하는 기능은 이 단계에서 요구하지 않는다.

### 4.3 법칙과 징후의 관계 [확정 방향 / 제안 세부]

같은 감각 징후도 현재 공개된 법칙 때문에 다른 의미를 가질 수 있다. 예를 들어 「잔류」 심층에서는 발소리가 현재의 적이 아니라 과거 움직임의 흔적일 수 있다. 이는 **공개된 법칙에 따른 해석 차이**이며 단서를 임의로 속이는 핑계가 아니다.

## 5. 캐릭터의 탐험 반응 — 성격 중심

### 5.1 절대 우선 규칙 [확정]

> **캐릭터의 일반 탐험 대사는 고유 술식의 작동을 설명하는 기술 해설이 아니다. 캐릭터의 성격, 감정, 경험, 관계에 따른 평범한 말로 작성한다.**

- 고유 술식과 삶의 경험은 성격의 배경일 수 있지만, 대화마다 “정박점·공간 정합성·보호영역·술식 파장” 같은 전문 용어를 등장시키지 않는다.
- 탐험 반응은 **동료가 함께 걷고 있다는 느낌**이 목적이지 적 탐지 레이더나 튜토리얼 강의가 아니다.
- 공포, 농담, 짜증, 신중함, 호기심, 침묵, 서로를 걱정하는 말 등 자연스러운 반응을 사용한다.
- 같은 캐릭터라도 늘 동일한 농담이나 태도를 반복해서 캐리커처처럼 만들지 않는다. 긴박한 상황에서는 평소 농담하는 인물도 침묵할 수 있다.
- 실제 인물 성격·말투가 충분히 확정되지 않은 경우, 샘플 대사를 **임시 콘텐츠**로 명시한다. 단순 역할 이름 `navigator` 등 현재 코드의 여섯 전투 직군을 곧바로 스토리 인물 김도윤·정하린·최서윤으로 단정하거나 일괄 개명하지 않는다. **캐릭터 실체와 직군 ID의 매핑은 [미결]**이다.

### 5.2 발생 시점 [확정 방향]

1. **특별한 사건이 있는 방에 진입하기 직전:** 우선순위 높음. 다만 매번 발생시키지 않는다.
2. **심층 법칙 또는 기묘한 환경이 두드러지는 장소:** 우선순위 높음.
3. **별다른 보상·위험이 없는 일반 탐험:** 가끔 대사 발생. ‘대사가 나왔으므로 다음 방은 특별하다’는 신호를 방지.
4. **사건 직후:** 느꼈던 감정이나 뒤늦은 이해를 표현.
5. **동료 사이 관계성:** 드물게 1~2회 대화. 모든 이동에 대사를 연속 표시하지 않는다.

- 심층당 **약 2~3회** 반응은 [시험] 목표 빈도이지 강제 할당이 아니다.
- **같은 원정에서 같은 트리거/대사는 중복 재생하지 않는다.** 재방문, 빠른 이동, 저장/복원 뒤에도 재생 금지.
- 인접 방에 특별 이벤트가 존재하더라도 **반드시 대사가 나온다는 보장**은 없다. 반대로 평범한 통로에서도 등장할 수 있다.
- 일반 반응은 보통 **한 명의 짧은 대사**, 관계성 이벤트에는 두 명이 참여 가능. 현재 편성된 인물만 발화한다.
- 대사의 화자 선정과 빈도는 별도 시드와 쿨다운/최근 화자 이력을 사용하여 결정론적으로 관리한다. 캐릭터 반응이 주요 랜덤 보상 분포를 변경하면 안 된다.

### 5.3 표현 [확정 방향]

- 탐험을 강제 정지시키지 않는 짧은 비차단 대사창을 사용한다.
- 캐릭터명·작은 초상화·텍스트를 표시하되 화살표/징후 버튼을 가리지 않는다. 지나간 대사는 탐사 기록에서 확인 가능하다.
- 서사적으로 중요한 사건에서는 별도의 차단형 대화창을 사용할 수 있지만 일반 징후 반응을 모두 컷신으로 만들지 않는다.
- 표정 변형은 처음엔 기본/긴장/미소 등 소수로 제한한다. 초상화 부재 시 명확한 임시 표현을 사용한다.

### 5.4 대사 예시 — **확정 캐논 아님**

징후: “문 너머에서 세 번의 노크가 반복된다.”

- 김도윤: “……우리보고 열어달라는 건가?”
- 정하린: “예의는 바르네. 문까지 두드리고.”
- 최서윤: “열어주지는 말죠. 적어도 지금은요.”

이 예시의 핵심은 **전문 기술 용어 없이 성격 차이**를 보이는 것이지, 위 캐릭터의 성격·대사 톤을 최종 확정하는 게 아니다.

## 6. 선택형 조사 사건

### 6.1 기본 계약 [확정 방향]

- 현재 조사 오브젝트(`cache`, `record`, `workbench`, `shelter`)만 반복되는 탐험에 **소수의 선택형 특수 사건**을 더한다.
- 징후를 따라 진입한 방에서 실제로 그 징후와 관련된 물체·현상·장면을 발견해야 한다.
- 사건에서 가능한 선택은 시간/HP/골드/카드 보상, 선택형 전투, 정보/스토리 발견처럼 **기존 자원과 기능**을 우선 재사용한다. 정신력·관측 게이지 등 새 영구 자원은 추가하지 않는다.
- 위험한 선택에는 결정에 필요한 비용과 위험 범위를 충분히 알려준다. 감당 불가능한 치명 비용은 현행 `costly()`/치명행동 확인 정책과 일관되게 처리한다.
- 일부 장소는 기묘한 장면이나 서사적 발견만 남기고 보상 없이 끝날 수 있다. 다만 과도한 빈도로 시간을 낭비하게 해서는 안 된다.
- 사건은 원정/심도/노드 기준 한 번 해결하면 반복 수령할 수 없다. 선택·해결·보상·전투 후 복구 상태가 저장돼야 한다.

### 6.2 초기 콘텐츠 [시험]

서로 다른 선택 구조를 가진 **4~5개** 사건부터 수직 슬라이스로 검증한다. 가칭 예시:

| 사건 | 접근 전 징후 | 가능한 선택 구조 (예시) |
|---|---|---|
| 열두 번째 기침 | 정확히 같은 기침이 주기적으로 반복 | 시간 들여 장치 조사 / 파괴 후 위험 감수 / 무시 |
| 작동하지 않는 수술대 | 금속을 내려놓는 소리가 반복 | 안전 회수 / 술식 기록 해석 / 가동해 전투 감수 |
| 거꾸로 울리는 안내 방송 | 정차하지 않은 열차의 안내음 | 녹음 회수 / 안내를 따라감 / 기록만 남김 |
| 비어 있는 자판기 | 아무것도 없는 기계에서 동전 소리 | 기계 분해 / 대기 / 무시 |
| 그림자가 하나 더 많은 문 | 실제 문과 그림자 수가 다름 | 안전한 경로 / 변칙 조사 / 철수 |

**주의:** 위는 창작 샘플이며 실제 보상 테이블과 확정 스토리 사건으로 취급하지 않는다. 첫 구현은 테마/시드 분배와 보상 분기 검증에 충분한 2~3개를 먼저 만들고, 성능·재미 확인 후 4~5개로 늘려도 된다.

### 6.3 전투/보상 연결

- 사건 결과가 전투라면 기존 전투 어댑터를 통해 들어간다. 강제 전투/선택 전투를 혼동하지 않는다.
- 현재 `Session.inspect()`의 `kind` 고정 검증, 원자적 트랜잭션, `REWARD` phase, `Session.assert()`, `M.validate()`를 고려해 새 event 구조/상태를 분리하거나 명시적으로 확장한다.
- 동일 선택을 반복 제출하거나 새로고침 직후 클릭해 보상을 두 번 받는 문제가 없어야 한다.
- 맵의 ‘조사 완료’와 사건의 ‘선택 보류/완료’를 구분한다.

## 7. 비주얼 개발 — 지금 시작하되, 대량 생산은 금지

### 7.1 현재 단계에 대한 결정 [확정 방향]

**지금 비주얼을 검증할 시점이다.** 그러나 캐릭터 전체 일러스트·모든 배경·전투 이펙트·Live2D를 양산할 단계는 아니다. **작게 완성된 장면(버티컬 슬라이스)을 만들어 제작 가능성 및 탐험 개선 효과를 확인**한다.

주요 이유: 현행 `.scene.hospital/.city/.station` CSS 배경은 테마별 색감은 있으나 각 방의 개성이 약하다. 실제 사용자가 느낀 길찾기 어려움에는 공간 표식의 부족도 기여할 수 있다. 지도 개선뿐 아니라 장소마다 기억할 수 있는 시각적 구별이 필요하다.

### 7.2 비주얼 바이블 제작 [필수 산출물]

Codex는 `docs/` 아래에 별도 **`비주얼_바이블_초안.md`**를 생성하거나 동등한 명세를 작성한다. 포함할 필드:

1. **공통 화풍:** 서브컬처 2D 게임의 캐릭터/배경 표현 방향, 선화 밀도, 도색 방식, 명암 수준, 배경/인물의 스타일 호환 기준.
2. **지역별 테마:** 병원/도시/기차역의 공통 팔레트, 광원, 구조물, 시대감, 반복 소품, 이상현상 표현, 금지 사항.
3. **캐릭터별 앵커 규정:** 얼굴/머리/의상 실루엣/색/비율/반드시 유지할 형태/표정 세트. **아직 정하지 않은 구체적 외형을 공식 설정으로 꾸며내지 말 것.** 임시 콘셉트는 별도 표기.
4. **시점 규칙:** 탐험 배경은 1인칭 일정한 눈높이와 시야각·소실점, 출입 방향 표시 가능 영역. 이벤트 CG는 별도 자유 구도.
5. **UI 규격:** 화면의 정보 위계, 네 방향 징후·조사·캐릭터 반응·심층 법칙·지도·체력·시간의 배치, PC/모바일 대응, 텍스트 가독성·명암 대비.
6. **에셋 규격:** 해상도, 종횡비, 투명 배경, 명명 규칙, 파일 포맷, 레이어 분리, 파일 크기 목표(측정 후 확정).
7. **제작/수정 파이프라인:** 기준 이미지, 파생 이미지 제작, 품질 검수, 리젝 사유, 수정 이력, 생성 도구/참조 에셋의 권리·출처 기록.

### 7.3 AI 이미지 일관성 확보 — 필수 생산 규칙

1. **기준(앵커) 이미지를 먼저 승인한다.** 캐릭터는 얼굴/의상/기본 표정과 주요 각도, 지역은 대표 배경과 광원/팔레트를 소수 확정한다.
2. 새로운 자산은 가능하면 **기준 이미지 참조/편집**으로 만들고, 독립 텍스트 생성만을 반복하는 방식을 피한다.
3. **프롬프트를 모듈화**한다: 공통 스타일 + 캐릭터 또는 지역 고정 요소 + 샷/카메라 + 장면 변형 + 금지 조건. 버전 관리한다.
4. **캐릭터·배경·특수 이펙트·UI를 분리 제작**해 런타임에서 합성한다. 완성된 UI가 포함된 이미지 한 장을 모든 방에 넣지 않는다.
5. 가능한 한 자산 유형별 **일관된 생성 모델/버전/워크플로**를 사용한다. 단, 텍스트 프롬프트나 동일 시드만으로 정확한 동일인/동일 화풍이 보장된다고 주장하지 않는다.
6. 인물 얼굴·헤어·의상 문양·비율의 동일성, 배경 원근·원색·광원의 일관성, UI와 합성했을 때의 가독성을 **체크리스트로 검수**한다.
7. **프롬프트, 도구 및 버전, 기준 이미지 ID, 편집 기록, 라이선스/출처, 검수 상태**를 자산별 매니페스트에 남긴다. 타인의 저작권 보호 캐릭터나 특정 작품 화풍 복제 지시를 기준으로 고정하지 않는다.
8. 품질이 낮거나 캐논과 어긋나는 이미지는 과감히 폐기한다. “한 장이 예쁘다”보다 **동일 품질로 10장 이상 계속 생산 가능한가**를 확인한다.
9. Codex가 현재 사용할 수 없는 이미지 생성 도구가 있다면 **자산과 구현 지시를 위한 프롬프트/매니페스트/플레이스홀더만 준비**하고, 사용 불가능한 도구로 이미지를 생성했다고 주장하지 않는다.

### 7.4 최초 버티컬 슬라이스 [시험 범위]

**병원 테마의 대표 3~5개 장소**, **주요 캐릭터 초상화 2~3명(기준 캐릭터 외형 확정 시)**, **공간 징후 UI**, **짧은 캐릭터 반응**, **선택형 사건 1개**, **탐사 지도**, **법칙 진입 패널**을 하나의 원정 흐름에 적용한다.

권장 장소의 기능적 구별 예:

- 긴 복도: 빨간 비상등 또는 고장 난 형광등.
- 간호사 대기실: 책상/기록물 등 독자적인 실루엣.
- 수술실: 금속성 의료 장비와 이상하게 반복되는 움직임.
- 계단실: 방향 감각을 자극하는 비정상적인 구조.
- 연결구 접근 공간: 강렬한 시각적 표식, 단 실제 위치를 사전에 지도에 표시하지 않음.

**아직 최종 아트를 제작하지 않았거나 얼굴 디자인이 미정이면 플레이스홀더로 먼저 UI/레이어 구조를 검증한다.** 한 장의 고품질 컨셉 아트가 전체 제작 가능성을 증명하지 않는다.

## 8. 통합 UX 원칙

### 8.1 화면 정보의 우선순위

- **상시:** 배경 장면, 방향 버튼, 주요 징후 짧은 문장, 시간, 현재 파티 체력, 조사 대상.
- **요약/접기:** 방문 지도, 현재 심층 법칙의 짧은 이름, 상세 기록.
- **조건부:** 캐릭터 반응 대사, 사건 선택지, 연결구·필수 전투, 경고 모달.
- **오버레이에서 확인:** 법칙의 정확한 수치, 지도 전체, 상세 탐사 로그.

캐릭터 반응 빈도 때문에 플레이어가 계속 문장을 읽느라 이동하지 못하는 구조를 피한다. 방향 화살표 위 징후 1~2줄을 보여주되, 화면이 좁으면 짧은 핵심 문구와 펼쳐보기 패턴을 비교 검증한다. 캐릭터 대사는 이동을 강제로 정지시키지 않는다.

### 8.2 서브컬처 정체성

- 캐릭터를 고유 술식의 기능 안내문이 아니라 감정·판단을 가진 인물로 표현한다.
- 탐험 중 주요 배경은 장면 일러스트이며 초상화는 반응 시에만 짧게 등장한다.
- 반복 대사의 적은 양보다 **인상 깊은 상황에 맞는 반응의 질**을 우선한다.
- 정보의 신뢰와 세계의 불가해함은 구분한다: **법칙의 게임 메커니즘은 공개**하지만 개별 사건의 모든 결과는 공개하지 않을 수 있다.

## 9. 기존 코드의 참고 지점

검토 기준 커밋에서 다음 구조를 확인했다. Codex는 작업 직전 다시 HEAD를 점검한다.

| 파일 | 기존 책임 | 이번 확장 시 변경 포인트 |
|---|---|---|
| `prototype/exploration-map.js` | 격자 그래프/시드 생성/BFS/방문 기록/지도 검증 | 이동 간선 기록 검증, 인접 징후 생성, 사건 노드와 법칙 배정 또는 모듈 위임 |
| `prototype/exploration-core.js` | `Session`, 탐험 비용, `move`, `inspect`, 전투·귀환·저장 | `fastTravel()`, 방문·징후·대사/사건 상태, 법칙 상태, 복구/검증/마이그레이션 |
| `prototype/exploration-combat.js` | 기존 전투 상속, 덱 특성 계산 | 전투에 영향 주는 심층 법칙 효과, 로그와 프리뷰 일관성 |
| `prototype/exploration-app.js` | 탐험 UI, `showMap`, 무전, 카드·전투·패널 | 지도 클릭, 방향 징후, 캐릭터 대사, 법칙 패널, 사건 선택 UI |
| `prototype/exploration.css` | CSS 배경, 이동 버튼, 레이아웃 | 배경 레이어/사물 실루엣/징후·대사 가독성/모바일 대응 |

| `prototype/exploration-check.cjs` | 탐험 계약/경제/맵/저장 검사 | 새 비용/빠른 이동/징후/법칙/사건 불변식 |
| `prototype/exploration-browser-check.cjs` | Playwright PC·모바일 동작 검사 | SVG/HTML 지도 인터랙션, 320·390px 가독성, 대사/패널 접근성 |
| `prototype/exploration-study.cjs` | 규칙 기반 자동 원정 | 밸런스 회귀 참고. 숨은 맵을 알고 경로 선택하는 시뮬레이터로서 실제 사람 길찾기를 대표하지 않음 |

**중요 기술 주의점:**

- 현 맵 생성은 연결구까지 향하는 주경로를 `east`/`north`로만 구성한다. 징후·지도·법칙을 추가해도 목표 방향이 쉽게 예측되는 문제는 남는다. 이번 작업에 대규모 맵 알고리즘 개편을 섞기보다 별도 이슈로 기록하고, 개선한다면 BFS 최단거리 하한·역방향 연결·결정론적 생성 검사를 반드시 유지한다.
- `map.validate()`의 허용 조사 `kind`가 현재 네 가지로 고정되어 있다. 사건용 객체를 추가하면 검증도 함께 갱신해야 한다.
- `Session.assert()`는 지도 상태와 결정론적 생성 맵의 일치를 검증한다. 동적 상태를 생성형 맵과 잘못 비교해 기존 저장을 깨지 않도록 한다.
- 카드의 덱 특성 수치는 현재 원정 덱의 **사본 장수**다. 카드 이름의 유일 종류 수, 손패 카드 수, 누적 플레이 수가 아니다. 이번 확장에서 변경하지 않는다.
- 지상 골드 뽑기는 카드 **정의의 영구 해금**이며 출발 덱에 해당 카드를 추가하는 기능이 아니다. 이번 확장에서 변경하지 않는다.

## 10. 단계별 구현 계획 및 단계 관문

### P0 — 사전 감사와 규칙 스냅샷

**작업:** 현재 HEAD와 저장 키/버전/테스트를 확인하고, 각 요구사항의 현 구현·미구현·충돌 목록을 짧게 문서화한다. 기존 플레이가 정상 작동하는 기준 상태를 확보한다.

**완료 조건:** 기존 탐험 도메인 검사 및 실행 가능한 브라우저 검사 결과 기록. 자동 검사 실행 불가 시 사유와 미실행 항목을 명시한다.

### P1 — 경로 기록·지도·무료 빠른 이동 (우선 구현)

**작업:** 방문 간선 기록, 지도 시각 구분, 지도 목적지 클릭/터치/키보드, 정당한 경로 BFS, `Session.fastTravel`과 영속성, 상태 검증/마이그레이션.

**완료 조건:** 무료 빠른 이동은 시간/HP/회복/일반 이동 횟수 무변화. 화살표의 방문 경로 재이동은 **시간 소모 + 생존자 자연 회복** 유지. 사용자는 현재 심도에서 확인한 길만 이용한다. 0시간 상태의 두 이동 구분 테스트 통과.

### P2 — 공간 징후 + 소수 선택형 사건

**작업:** 방 콘텐츠 근거의 시드 고정 방향별 징후, 테마별 초기 문장 데이터, 사건 2~3종의 선택/정산/저장/표시, 본문 징후-사건 대응.

**완료 조건:** 같은 시드/방/방향/상태의 문장은 재진입·재로드 후 안정적. 징후가 없는 통로에는 징후를 허위로 표시하지 않는다. 미탐사 보상/연결구 위치 유출 없음. 사건 보상 중복 없음. 캐릭터 대사는 이 단계에서 필수 아님.

### P3 — 심층 법칙 진입 공개 및 효과 검증

**작업:** 심층 법칙 데이터, 진입 시 공개 UI 및 재열람, 전투/탐험에 적용 가능한 소수 법칙의 최소 구현, 로그/프리뷰, 동적 상태 영속성.

**완료 조건:** UI에 표시한 효과 수치와 실제 적용 수치가 같다. 법칙은 저장/복원 후 동일하며 심층 전환에 따라 정상 갱신된다. 법칙의 능력 제한 및 전투 전후 원정 상태가 기존 엔진과 충돌하지 않는다.

### P4 — 캐릭터 대사·서브컬처 경험

**작업:** 성격 중심 대사 이벤트, 희소한 발생 시점, 일상적 비사건 대사, 직전/직후 대사, 파티 화자, 재방문 중복 방지, 탐사 대사 기록 및 최소 초상화 UI.

**완료 조건:** 사건 여부가 대사 등장만으로 드러나지 않는다. 미편성 인물이 말하지 않는다. 전문 술식 해설을 기계적으로 출력하지 않는다. 저장/복원·빠른 이동에서 대사 중복 없음. 대사는 비차단·접근 가능.

### P5 — 비주얼 바이블 + 1개 지역 수직 슬라이스

**작업:** 색채/캐릭터/원근/레이어/UI/에셋 매니페스트/프롬프트 규격 문서 작성, 승인 가능한 앵커 선택 절차, 병원 3~5개 장소의 시각적 구별, 대표 이벤트 장면과 캐릭터 대사 UI 적용.

**완료 조건:** 임시 이미지만으로도 레이아웃·표현 규칙이 검증 가능. 이미지 생성 도구와 승인 에셋이 있을 경우 동일 스타일 추가 생산 테스트 기록. 1242px, 390px, 320px 화면 확인. **대량 아트 제작 자동 진행 금지** — 생산 가능성과 사용자의 아트 승인 이후 별도 단계로 전환.

**운영:** 단계별 커밋 또는 명확한 작업 구간, 테스트 결과, 핵심 스크린샷(저장소 정책상 QA 스크린샷 제외 가능), 변경된 파일, 알려진 위험을 보고한다. P5 이전에도 필요하면 간단한 임시 UI 색감 보정은 허용한다.

## 11. 회귀·신규 테스트 명세 (최소)

### 11.1 이동과 지도

- **MAP-NEW-01:** 미방문 방 화살표 이동은 시간 1(기본 시험값), HP 자연 회복 반영.
- **MAP-NEW-02:** 방문했던 방으로 화살표 재이동도 동일 비용/회복.
- **MAP-NEW-03:** 지도 무료 빠른 이동 전후 시간, HP, 소수 회복 버퍼, 골드, 덱, 이동 카운터가 같다.
- **MAP-NEW-04:** 원정 시간 0에서 화살표 이동은 기존 HP 비용 정책, 빠른 이동은 완전 무료.
- **MAP-NEW-05:** 미방문·현재 심도 외·미통과 간선·전투 중·보상 화면의 빠른 이동은 거부됨.
- **MAP-NEW-06:** 시드/기존 지도 검증/저장·복원/심층 전환/다중 탭 충돌 검증.
- **MAP-NEW-07:** 빠른 이동 여러 번 반복해도 HP/골드/보상/무전/대사 발동을 중복 생성하지 않음.
- **MAP-NEW-08:** 포털 수문장을 처리하지 않은 상태에서 빠른 이동만으로 하강 불가.
- **MAP-NEW-09:** 기존 저장 파일을 복원하거나, 기록 부족 시 안전하게 기능 제한·설명. 파괴적 초기화 금지.

### 11.2 징후·사건·법칙

- **SIGN-01:** 실제 출구 수와 징후 표기 수 일치; 없는 방향의 문구 없음.
- **SIGN-02:** 같은 시드/노드/방향/상태는 재방문·새로고침 후 같은 징후.
- **SIGN-03:** 미방문 지점에서 정확한 보상/적의 정체/연결구 ID 등 비공개 정보를 누설하지 않음.
- **SIGN-04:** 의미 분류와 문장 표현이 분리되고, 사건/실제 환경과 문구가 모순되지 않음.
- **SIGN-05:** 사건 해결 뒤 상태/징후/지도 기록이 정상 전환됨.
- **EVENT-01:** 각 선택별 비용·보상·상태가 한 번만 적용; 새로고침·연속 클릭 방지.
- **EVENT-02:** 선택형 전투/REWARD 전환 및 미선택 귀환이 기존 `phase` 제약과 충돌하지 않음.
- **LAW-01:** 새 심층 진입 직후 이름·정확한 효과 공개, 언제든 재열람 가능.
- **LAW-02:** 법칙별 효과 로그·프리뷰·전투 실제 결과 일치.
- **LAW-03:** 다른 시드/심층 전환·복원 후 법칙 재현; 기존 전투 단독 모드 불변.

### 11.3 캐릭터/비주얼/UX

- **CHAR-01:** 심층당 대사 빈도 시험 및 화자 최근 반복 억제.
- **CHAR-02:** 특별 이벤트 없는 방에서도 일부 대사 발생하고 특별 이벤트가 있어도 대사가 항상 나오지는 않음.
- **CHAR-03:** 미편성 인물 발화 없음, 대사/트리거 저장 복구 후 재생 중복 없음.
- **CHAR-04:** 캐릭터 반응 기본 문장에 전문적인 고유 술식 설명을 강제하는 템플릿이 없음.
- **UI-01:** PC/모바일에서 방향 버튼, 징후, 조사 대상, 대사가 겹치지 않음.
- **UI-02:** 지도 목적지 키보드 접근, 포커스 표시, 대사와 상태 표시 접근성.
- **ART-01:** 바이블과 자산 매니페스트 검수 기록(앵커 참조, 시점, 팔레트, 파일 규격, 권리/출처, 승인).


## 12. 직접 플레이 관찰 계획

신규 시스템 도입 전후에 같은 시드/조건 또는 비교 가능한 원정을 짧게 2~3회 플레이하고 아래를 관찰한다.

1. **지도:** 돌아갈 길을 찾는 데 막히는 순간이 줄었는가? 방문 여부 표시가 명확한가?
2. **자원 선택:** 무료 빠른 이동과 유료 직접 이동을 의도에 맞게 구분해 활용하는가? 수동 왕복 회복이 전략으로 느껴지는가, 반복 노동인가?
3. **징후:** 이동 전 징후를 실제로 읽고 경로 선택 근거로 사용하는가? 문장과 방문 결과가 연결되는가?
4. **법칙:** 진입 시 공개된 법칙을 이해하고 덱·파티·탐험 행동을 바꾸는가?
5. **사건:** 조사 결과의 선택이 의미 있었는가? 강제/선택 교전을 혼동하지 않았는가?
6. **캐릭터:** 동료 대사가 자연스럽고 드물게 느껴지는가? 특정 캐릭터와 탐험하는 인상이 생기는가?
7. **비주얼:** 장소를 구분하거나 기억하기 쉬운가? 표정/배경/버튼의 스타일이 하나로 보이는가?
8. **피로:** 징후를 매 방에서 읽느라 피곤하지 않은가? 대사가 화살표 조작을 방해하지 않는가?

관찰 결과는 ‘좋음/나쁨’ 단정 대신 실제 행동, 관찰 당시 남은 시간/체력, 클릭 반복 횟수, 읽지 않은 징후 비율, 기억에 남은 사건 등을 기록한다.

## 13. 이번 범위에서 절대 혼동하지 말 것

| 오해 | 올바른 해석 |
|---|---|
| 방문한 길은 화살표 이동도 무료다 | **틀림.** 화살표 이동은 방문 여부와 관계없이 시간 소모·회복 처리. **지도 빠른 이동만 무료** |
| 지도 빠른 이동으로 체력을 회복할 수 있다 | **틀림.** 시간·HP·회복 모두 0 변화 |
| 지도에서 유료 자동 도보 이동도 제공해야 한다 | **이번 단계 제외.** 사용자가 해당 1번 추가 기능을 채택하지 않음 |
| 징후는 정확히 다섯 종류다 | **틀림.** 내부 의미 5~6종과 감각 표현 10종 이상을 분리 |
| 징후 텍스트와 이벤트는 별도 랜덤이다 | **틀림.** 징후는 실제 인접 콘텐츠에서 파생 |
| 캐릭터마다 자기 술식을 분석해 준다 | **틀림.** **성격·감정·관계 중심의 자연스러운 일상 대사** |
| 캐릭터 대사는 이벤트 직전에만 나온다 | **틀림.** 이벤트 없는 곳/사건 이후에도 가끔 나와야 메타 신호가 되지 않음 |
| 깊은 심층 법칙은 탐험으로 알아내야 한다 | **틀림.** **진입 즉시 효과와 수치를 공개** |
| 심층 법칙 예시 3개는 출시 확정이다 | **틀림.** 최소 실험용 후보, 수치 미확정 |
| 이미지 몇 장만 뽑으면 비주얼 개발 완료다 | **틀림.** 기준/일관성/재생산성/권리/수정 파이프라인 검증 필요 |
| 새로운 캐릭터 외형·성격·직군 매핑을 마음대로 확정한다 | **금지.** 사용자 합의/기존 캐논 확인 전 임시안으로 표시 |
| 자동 테스트 통과 = 게임이 재미있다 | **틀림.** 실제 사용자 관찰과 별도 |

## 14. 아직 미결인 질문 — 임의 확정 금지

1. 최종 아트 스타일과 공식 캐릭터 외형·복장·눈/머리 세부 설정 및 등장 캐릭터와 기존 6개 직군 ID의 매핑.
2. 수면 법칙의 실제 효과·수치·출현 분포·심도별 중첩 여부(현재는 심층당 1개 시험).
3. 징후 의미 분류의 최종 종류와 규모, 특정 징후의 신뢰도 및 복합 징후 비율.
4. 정식 사건의 스토리·선택지·보상 수치·빈도.
5. 완성 게임에서 허용할 아트 도구·상업적 사용 라이선스·생성 이미지 검수 방식.
6. 실제 플레이 후 빠른 이동이 시간 경제에 미치는 영향을 어떻게 재조정할지(기본 시간 65 등 현재 수치는 시험값).
7. 북/동 편향 맵 생성 알고리즘의 개선 시점 및 새로운 경로 다양화 목표.

위 항목은 **데이터/설정 교체 가능**하도록 설계하고, 미결 때문에 필수 기능 전체가 멈추지 않게 소규모 플레이스홀더를 사용할 수 있다.
