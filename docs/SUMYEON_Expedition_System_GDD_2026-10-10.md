# 《수면》 원정·탐험·덱 특성 시스템 통합 설계서

**버전:** Exploration GDD 0.1 · **작성일:** 2026-10-10<br>
**대상:** 개발 담당 Codex / 기획자<br>
**문서 목적:** 지금까지 합의한 설계를 실제 게임에 안전하게 통합하기 위한 기능 명세, 데이터 계약, 개발 순서 및 검증 기준.

> **중요: 이 문서가 승인되지 않은 수치·콘텐츠를 확정하는 것은 아니다.** `[확정]`은 사용자가 직접 결정한 원칙, `[시험값]`은 조정 가능한 프로토타입 수치, `[제안]`은 구현 편의를 위해 추천한 기본 동작, `[미결]`은 구현 전 결정하거나 설정으로 분리해야 할 항목을 뜻한다. Codex는 `[미결]` 항목을 영구 규칙으로 독단 확정하지 말고 설정값과 명확한 임시 처리로 구현한다.

## 0. 반드시 먼저 읽을 요약

《수면》은 **4인 공용 덱 카드 전투를 보존하면서**, 2D 고정 배경에서 화살표로 장소를 이동하는 **절차적 노드 탐험**을 추가하는 게임이다. 플레이어는 매 원정 제한된 탐험 시간 안에 조사·전투·하강을 반복하며 더 깊은 심층에서 더 가치 있는 자원을 찾는다.

- `[확정]` 수면 내부의 각 심층에는 **다른 2D 배경 테마와 별도 절차적 맵**이 생성된다. 이미 방문했던 구체적인 세계를 다시 방문하기는 매우 어렵다.
- `[확정]` 맵 시작점부터 **다음 심층 연결구까지의 최단 이동 횟수에는 하한 N이 존재**한다. N=15는 **예시**이고 확정 수치가 아니다.
- `[확정]` 방 이동, 조사, **전투 진입**은 탐험 시간 비용을 가진다. **전투 내부의 턴·카드 사용·라운드는 탐험 시간을 소비하지 않는다.**
- `[확정]` 시간이 남아 있는 탐험에서는 지나간 탐험 시간에 비례하여 항해사 체력이 자연 회복된다. **전투 턴 넘기기로 자연 회복할 수 없다.**
- `[확정]` 탐험 시간이 0이면 강제 종료되지 않는다. 이후 탐험 비용을 **체력으로 지불**하면서 더 조사할 수 있다.
- `[확정]` 지상에 연락해 현 위치에 귀환 포털을 열도록 하는 **원클릭 귀환**이 존재한다. 지나온 길을 역행할 필요는 없다.
- `[확정]` 원정 실패 시 이번 원정의 골드 등 획득 자원 **일정 비율만 손실**한다. 전액 몰수하지 않는다.
- `[확정]` 원정 중 추가·강화한 **카드는 원정 종료 후 초기화**된다. 지상에서 골드로 카드 *해금 뽑기*를 진행하면 카드가 **향후 원정의 보상 후보 풀**에 영구 등록된다. 카드 자체를 영구 출발 덱에 지급하는 것이 아니다.
- `[확정]` 카드에는 **계열(특성 분류)**이 있다. **현재 원정 덱에 들어 있는 카드 사본 수**로 TFT식 덱 특성 수치를 계산한다. 카드 이름의 중복 여부와 카드 사용 횟수는 무관하다.
- `[확정]` 원정 출발 전 **선호 계열 0~3개**를 선택해, 선택한 계열이 원정 중 카드 보상에 나타날 확률을 높인다. 이것은 특성 카운트를 직접 올려주지 않는다.
- `[확정]` 지상의 오퍼레이터는 간헐적인 무전으로 다음 연결구의 대략적 방향에 대한 **신뢰 가능한 힌트**를 제공한다. 플레이어의 경로 선택까지 대신하지는 않는다.
- `[확정]` 기존 4인 공용 덱 전투 검증(P0~P6)을 파기하지 않는다. 새로운 탐험은 **별도 진입점/기능 플래그로** 개발해 비교·통합한다.

### 문서 내 결정의 우선순위
1. **본 대화에서 사용자가 확정한 최신 규칙**.
2. 기존 《수면》 최신 카드 전투 설계(2026-10-09, 「한 손패로 움직이는 네 사람」)에서 충돌하지 않는 규칙.
3. 이 문서의 `[제안]` 기본값. 사용자의 확인이 필요한 사항은 나중에 교체 가능하도록 구현.

## 1. 경험 목표와 성공 조건

**핵심 루프:** `지상 준비 → 입수 → 절차적 장소 탐험 → 조사/전투/보상 → 연결구 탐색 → 더 깊은 심층 또는 귀환 → 보상 정산 → 카드 해금 → 다음 원정`.

**플레이어가 반복적으로 내려야 할 결정:**
1. 지금 눈앞의 보상을 조사할지, 다음 연결구를 찾으러 갈지.
2. 현재 HP·덱 구성으로 더 강한 적을 만날 위험을 감수할지.
3. 시간 소진 이후 HP를 써서 한 번 더 조사할지, 즉시 귀환할지.
4. 카드 자체의 성능과 **덱 특성 단계 달성** 중 무엇을 우선할지.
5. 원정 전에 어느 **0~3개 계열의 등장 확률**을 높일지.

**별개의 두 재미:** 탐험에서는 **시간/경로/미지의 정보 관리**, 전투에서는 **카드→실행자→대상 선택과 HP 생존 관리**를 제공한다. 게임의 시간 자원을 전투 턴에 적용하지 않는다.

**실패 신호:** (i) 연결구까지 무의미하게 화살표만 연타함, (ii) 시간·HP 선택이 사실상 자동임, (iii) 선호 계열 하나만 매번 선택해야 함, (iv) 특성 시너지가 카드 운영 없이 상시 화력 보너스만 제공함, (v) 원정 보상 뽑기를 위해 반복 골드 파밍이 필수가 됨.

## 2. 전체 모드와 플레이 흐름

### 2.1 지상 허브

- 출전할 **4인 파티**와 시작 덱을 확인한다. 기존 공용 덱·캐릭터 전문성 규칙 보존.
- 영구 해금된 카드 목록을 확인한다.
- 출전 전에 **선호 계열을 0개, 1개, 2개 또는 3개** 고른다. 선택은 해당 원정에서만 유효.
- 골드로 **카드 해금 뽑기**를 수행한다. 신규 카드 획득은 영구 해금 목록에만 기록한다.
- 원정 시작: 시드를 결정하고 첫 심층 맵을 생성한다.

### 2.2 수면 원정

`EXPLORING → (COMBAT → REWARD → EXPLORING) ↔ (INVESTIGATING → EXPLORING) → (DESCEND → EXPLORING) → RETURN / FAIL`

- 자유로운 WASD 이동이 아니다. **정면 2D 배경 위의 이동 화살표**만 눌러 연결된 노드로 이동한다.
- 방문 노드/발견 경로는 현재 원정 동안 기록된다. 미탐사 구역은 가린다.
- 연결구는 발견 후 플레이어가 선택해 진입한다. 발견 즉시 자동 하강하지 않는다.
- 연결구 이용 시 새 **테마·별도 노드 그래프**로 전환한다. 원정 시간·파티 HP·원정 덱·획득 자원은 이월한다.
- **귀환 버튼**은 안전한 탐험 상태에서 원클릭 처리한다. 포털 연출 → 결과 화면 → 지상 허브.
- `[미결]` 전투 중 즉시 귀환/도주를 허용할지. **시험 구현에서는 전투 도중 귀환 금지**(기존 전투 패배 위험을 무효화하지 않음).

### 2.3 수작업 스토리 맵과 원정 맵

- **메인 프롤로그:** 기존 스토리 연출/스크립트/수작업 장면을 파괴하지 않는다.
- **반복 심층 탐험:** 동일한 노드 UI와 전투 엔진을 사용하는 절차적 생성 맵을 주 무대로 한다.
- 이후 필요하면 스토리 맵을 고정된 노드 그래프로 표현해 탐험 컴포넌트를 재사용한다. 첫 구현에서 프롤로그 전체를 절차적 맵으로 자동 변환하지 않는다.

## 3. 탐험 시간과 체력: 정확한 의미

### 3.1 서로 다른 시계

**원정 시간(`timeRemaining`)**은 플레이어가 탐험 행동에 쓸 수 있는 *단위 예산*이다. 실세계 초, UI 애니메이션 지속 시간, 전투의 라운드 수와 무관하다.

| 행위 | 시간 > 0 | 시간 = 0 | 비고 |
|---|---|---|---|
| 연결된 방으로 이동 | 시간 지불 | HP 지불 | 유효 출구만 허용 |
| 현재 방 사물 조사 | 시간 지불 | HP 지불 | 조사 소모품 상태 유지 |
| 전투에 최초 진입 | 시간 지불 | HP 지불 | **한 전투당 1회만** |
| 카드 사용/턴 종료/적 턴 | 탐험 시간 변화 없음 | 탐험 시간 변화 없음 | 자연 회복 없음 |
| 카드 보상 선택 | 추가 시간 없음 `[제안]` | 추가 HP 없음 `[제안]` | 보상 메뉴 비용 없음 |
| 다음 심층 연결구 사용 | 비용 설정형 `[미결]` | 비용 설정형 `[미결]` | 이동 비용을 0/1 등 설정 가능하게 |
| 지상 귀환 | 무료 `[제안]` | 무료 `[제안]` | 안전 상태에서 원클릭 |

**초기 설명용 숫자(확정 아님):** `timeBudget=250`, `moveCost=1`, `inspectCost=1`, `combatEntryCost=3`, `regenRate=0.005×maxHP / 시간 단위`.

> **밸런스 경고:** 최소 경로 15칸과 시간 250을 그대로 결합하면 압박이 거의 없을 수 있다. 출시값을 추론해서 고정하지 말고 시뮬레이션과 플레이 테스트로 조정한다.

### 3.2 시간→HP 교환 규칙

`[제안 — 테스트 기본 정책]` 모든 비용 행동은 다음 하나의 **원자적 비용 트랜잭션**으로 처리한다.

1. 행동 비용 `c`와 현재 시간 `T`를 읽는다.
2. `timeSpent = min(c, T)`를 소모한다.
3. `hpPaidUnits = c - timeSpent`만큼의 비용을 HP로 지불한다.
4. `timeRemaining = T - timeSpent` (음수 금지).
5. **실제로 시간으로 지불한 분량**에 대해서만 시간 자연 회복을 적용한다. HP로 지불한 분량에는 자연 회복이 없다.
6. 행동을 수행한다(이동/조사/전투 진입). 비용이 모자라 행동 불가라면 비용을 먼저 차감하지 않는다.

**경계 사례:** 시간 1만 남은 상황에서 비용 3의 전투에 들어가면 `시간 1 + HP 비용 2단위`로 결제한다. 이 혼합 결제는 아직 최종 합의되지 않았으므로 설정으로 교체 가능하게 한다. `[대안]` 원래 시간이 부족하면 전액 HP로 지불.

**HP 결제 단가:** `hpCostPerTimeUnit`는 `[미결]`. 전투·이동·조사 모두 시간비용 1당 동일한 HP 환산을 우선 실험한다. 별도 HP 통화를 만들지 않는다.

**누구의 HP를 소모하는가:** `[미결]`. **시험 기본 정책은 행동 시 전투 가능한 파티원 모두에게 자기 최대 HP의 일정 비율을 차감**하는 방식. 특정 인물 지정이나 별도 공용 탐험 HP는 사용자의 승인 없이 도입하지 않는다. 실험에서 타당하지 않으면 규칙 교체.

**자연 회복:** 시간이 실제로 경과한 탐험 행동에 대해 생존자의 HP를 최대HP까지 회복한다. 기존 전투 내 회복 카드가 있다면 효과 규칙만 적용, 탐험 시간이 흐르지 않는 동안 자연 회복은 0. `[미결]` HP0의 전투불능 캐릭터도 자연 회복으로 복귀 가능한가? **시험 기본 정책은 자연 부활 불가**.

**전투 진입 순서 `[제안]`:** 전투 직전 탐험 시간/HP 비용 결제 → 결제한 탐험 시간에 따른 자연 회복 → 전투 시작 및 전투 HP 피해 → 승리 시 탐험 복귀. 이 순서는 전투가 끝날 때 진입비용을 또 정산하지 않는다는 의미다. 전투 승리 후 기존 고정 회복(+3), 정비 회복(+9), 구간 완전 회복은 **새 자연 회복과 중복되어 과도한지 비교 후 선택**한다. 처음부터 무비판적으로 전부 더하지 않는다.

**정밀도:** 회복이 0.5% maxHP/단위라면 maxHP=30에서 단위당 0.15 HP. 매 행동마다 정수 반올림하면 누적 회복이 사라지거나 과장된다. 기존 HP 정수 엔진과 호환되도록 **고정소수점 내부 단위 또는 누적 소수 잔여 버퍼**를 사용하고 표시만 반올림한다. 전투 엔진의 HP 규약을 무단 변경하지 않는다.

### 3.3 전투와 원정 시간의 강제 분리

- 전투 1회 **진입 시 비용 1회**만 탐험 자원에 부과한다.
- 전투 1라운드든 50라운드든 추가 탐험 시간/탐험 자연 회복은 **0**.
- 전투 중 카드 사용, 턴 종료, 카드 애니메이션, 장시간 대기는 탐험 시간에 영향이 없다.
- `combatEntryCost`가 0보다 크더라도 `combatRoundCost=0`을 별도 불변조건으로 테스트한다.
- 전투는 기존 턴제/4인 공용 덱 엔진의 도메인 모델로 수행한다. 과거 개인 AG·실시간 일시정지 구조로 회귀하지 않는다.

### 3.4 전투불능과 실패

- `[확정]` 원정 실패 시 **이번 원정에서 획득한 골드/기타 손실 대상 자원의 일부만** 잃는다. 영구 해금 목록이나 이미 정산된 지상 보유량을 잃지 않는다.
- `[기존 전투 규칙]` 전투 중 **전원 전투불능**이면 패배.
- `[미결]` 개별 동료 한 명 HP0만으로 *원정 전체 실패*인지, 전원 HP0인지. **시험 기본값은 전원 HP0일 때 원정 실패**, 일부 HP0은 전투불능 표시와 잔존 파티로 진행. 이 정책은 반드시 나중에 사용자 확인.
- `[미결]` HP 부족으로 행동 자체를 시작할 수 없을 때의 UX. **시험 기본값:** 귀환 가능하면 `귀환/실패 위험 행동` 선택지를 제시, 그 외 아무 의미 없는 입력 반복 불가.
- `[미결]` 실패 손실 비율 `lossRate`와 손실 대상 자원 종류. 결과화면에는 원정 총획득/손실/실수령량을 반드시 구분해 표시.

## 4. 맵 생성 및 이동

### 4.1 데이터 모델

- **Expedition:** `seed, initialTime, timeRemaining, depthIndex, partyHP, runDeck, carriedLoot, preferredTraits, visitedHistory, status`.
- **DepthMap:** `depthId, biomeId, graphSeed, nodes, edges, entryNodeId, exitNodeId, mapRuleSet`.
- **Node:** `nodeId, logicalPosition{x,y}, sceneTemplateId, exitDirections, visitState, interactions, encounter, specialFlags`.
- **Edge:** `from, to, exitDirectionFrom, exitDirectionTo, traversalCost, edgeFlags`.
- **Interaction:** `id, kind, requiredTimeCost, resolved, lootTableId / scriptEventId`.
- **OperatorHint:** `depthId, activationCondition, directionOrArea, accuracyTier, triggered`.

노드의 `logicalPosition`은 엔진의 실제 3D 공간 좌표가 아니라 **방향 힌트/맵 표시용 논리 좌표**다. 배경은 2D 이미지로 표시한다. 같은 방향에 출구가 두 개 이상 생길 수 있다면 별도 도어 슬롯이나 식별 UI가 필요하며, 첫 구현에서는 노드당 방향 슬롯 한 개를 추천.

### 4.2 최단거리 하한(최우선 불변조건)

- 연결구까지의 거리는 **맨해튼 거리나 화면상 직선거리가 아닌 그래프 간선 수에 따른 최단 이동 횟수**로 계산한다.
- `shortestPathLength(entryNode, exitNode) >= minExitDistance`를 항상 만족해야 한다.
- `minExitDistance=15`는 **테스트 기본값일 뿐 미확정**. 15 간선이라면 주경로에 최소 16개 노드가 필요하다.
- 맵을 먼저 구성한 뒤 모든 지름길/순환 간선을 포함한 **최종 그래프에 BFS**를 실행한다. 지나치게 짧으면 지름길 제거/재생성.
- 출발점→연결구가 **도달 가능**해야 한다. 그 외 필수 스토리 노드·보상·전투·포털 등의 접근 가능성도 검증한다.
- `[제안]` 최소거리 하한 외에도 `preferredDistanceRange`와 `maxGenerationAttempts`를 둔다. 생성 실패 시 결정론적 안전 맵을 사용하되 원인을 로깅한다.
- 실제 연결구 진입이 불가능하게 막힌 맵, 역방향 출구가 사라진 맵, 존재하지 않는 노드로 가는 화살표를 절대 생성하지 않는다.

**권장 생성 절차(개념 의사코드):**

```text
GenerateDepthMap(seed, biome, minExitDistance):
    rng = SeededRNG(seed, depthIndex)
    repeat up to configured maxAttempts:
        mainPath = BuildWalkableMainPath(length >= minExitDistance)
        graph = AttachBranchesAndOptionalCycles(mainPath, rng)
        entry = mainPath.first
        exit = mainPath.last
        if not AllEdgesHaveValidDirectionsAndMatchingScenes(graph): continue
        if not AllRequiredNodesReachable(graph, entry): continue
        if BFS_Distance(graph, entry, exit) < minExitDistance: continue
        PlaceEventsByBudget(graph, rng)
        return graph
    return SafePrevalidatedFallbackGraph(minExitDistance, biome)
```

**주의:** 단지 ‘주경로에 15개의 방을 배치했다’는 검사는 부족하다. 옆길이 지름길이 될 수 있으므로 **완성된 맵의 최단거리**를 검사해야 한다.

### 4.3 2D 이미지와 방향 화살표

- 현재 노드에서 **실제로 연결된 방향만** 화살표로 노출한다(예: `↑`, `←`, `→`, 필요 시 `↓/뒤로`).
- 장면 배경의 문·통로와 화살표의 의미가 일치해야 한다. 초기에는 회색 임시 배경/표시 슬롯, 추후 `sceneTemplate × exitMask`로 아트 변형 가능.
- 같은 장소라도 열린 문 방향이 다른 경우 문 레이어/출구 마커를 분리해 처리한다. 모든 문 구조 조합에 별도 풀 일러스트를 요구하지 않는다.
- 이동 시 짧은 전환 연출 제공, 설정에서 단축/끔 허용. **시각 연출의 재생 시간은 탐험 시간과 무관**.
- 방문 노드는 지도에 표시한다. 최초 방문 여부와 이미 해결한 조사·전투는 원정 내에서 영속한다. 방문만으로 보상이 재생성되지 않는다.
- 같은 방향 버튼을 눌러도 위치가 이동한 후의 노드 연결 관계를 재평가한다. 연타/전환 중 중복 입력은 방지한다.

### 4.4 테마/심도 전환

- 연결구 발견→플레이어 선택→현재 심층 종료→다음 `depthIndex` 증가→**새 `biomeId` + 새로운 seed의 별도 맵** 생성.
- 병원 → 붕괴 도시 → 기차역처럼 완전히 다른 배경이 올 수 있다. 구체적 순서는 원정별로 변화한다.
- 이전 심층 노드·맵은 원정 기록에서 보존할 수 있지만, 새 심층은 별도의 지형이다.
- 위험도와 희귀 보상 기대값은 원칙적으로 깊이에 따라 증가한다. **강한 적 때문에 무조건 최심층 직행이 이득이 되어서는 안 된다**. 다만 모든 방을 피할 수 있다면 강한 적만으로 이를 보장할 수 없으므로 탐험 경로/전투 발생 구조로 검증한다.
- `[미결]` 최대 심도 및 한 원정의 끝 조건(보스/자원 소진/자발 귀환). 초기 프로토타입에서는 2~3개 심층만 테스트한다.

## 5. 지상 오퍼레이터와 탐색 힌트

**목표:** 맵을 대신 풀어주는 내비게이션이 아니라, **불완전하지만 믿을 만한 정보를 제공하는 등장인물**.

- 지상(수면 밖)에 오퍼레이터 캐릭터가 존재하며 무전으로 상황을 전달한다.
- 원정 중 특정 조건(이동 횟수, 발견 지점, 오래 연결구를 찾지 못함 등)에서 **간헐적으로** 무전이 표시된다.
- 무전 예시: `“현재 위치 북동쪽에서 연결구 반응이 확인됩니다.”`, `“오른쪽 통로 쪽에서 반응이 강해집니다.”`
- 기본 안전 심도에서는 방향 정보가 **거짓이 되지 않도록** 한다. 노드의 논리 좌표에 기반한 방위와 **실제 이동 가능한 경로의 첫 단계**를 구분한다.
- 예: 연결구 자체는 북동쪽에 있지만 실제 길은 왼쪽으로 돌아가야 함 → `“북동쪽 구역에 반응이 있습니다. 직행 경로는 확인되지 않았습니다.”`라고 말한다. 경로 첫 화살표를 말할 때는 BFS 첫 간선을 계산한다.
- 깊은 수면에서 통신 혼선·공간 왜곡을 도입한다면 **사전에 플레이어가 인지할 수 있는 경고**가 있어야 한다. 무작위 거짓말은 금지.
- 오퍼레이터 무전 자체는 시간 비용·체력 비용 없이 표시하는 것을 초기 기본안으로 한다. 가변적인 무전량을 추가 관리 자원으로 만들지 않는다.
- 2D 탐험 화면을 가리지 않는 작은 초상 + 한두 줄 문구 + 로그 기록. 반복 대사 쿨다운과 스킵/반복 듣기 지원.
- `[세계관 제안]` 오퍼레이터는 개인 현실정박장치(닻) 등의 탐사 신호를 분석해 방향을 추정한다. **닻의 구체적인 연결구 탐지 능력은 아직 확정 설정 아님**. 현 구현은 세계관 장치명을 데이터 로직에 하드코딩하지 않는다.

## 6. 카드 성장: 영구 해금과 원정 덱의 엄격한 구분

### 6.1 서로 다른 세 시스템

| 시스템 | 무엇을 바꾸는가 | 언제 유효한가 |
|---|---|---|
| **지상 골드 뽑기** | 새로운 `cardDefinitionId`를 **향후 보상 후보 풀**에 추가 | 영구 |
| **선호 계열 선택(0~3)** | 선택한 계열의 **보상 등장 가중치**를 높임 | 해당 원정 |
| **덱 특성(TFT식)** | **현재 원정 덱에 포함된 계열별 카드 사본 개수**로 단계 효과 활성화 | 해당 원정 중 덱 상태에 따라 실시간 |

**절대 하지 말 것:** 계열별 획득 횟수·사용 횟수를 여러 원정에 걸쳐 누적해 '숙련도 레벨'로 해금하는 방식. 사용자가 원한 시스템이 아니다.

### 6.2 지상 골드 뽑기

- 뽑기 결과는 새로운 카드 정의를 `permanentUnlockedCards`에 등록한다.
- 원정 시작 덱에 해당 카드를 자동 지급하지 않는다. 카드가 다음 **전투·탐험 카드 보상에서 후보**로 나타날 수 있게 한다.
- 같은 카드 정의를 두 번 해금해도 보상 풀에서 두 배 비중이 되지 않는다(영구 등록은 집합).
- `[미결]` 지상 뽑기 비용, 신규/중복 확률, 중복 보상, 카드 희귀도. **초기 프로토타입에서는 모든 해금이 결정론적으로 확인 가능하도록 개발자 메뉴 사용**, 이후 뽑기 UI 추가.
- 플레이어가 실력 외에 필수 확률 파밍을 강요받지 않도록 **기본 풀만으로 플레이/클리어 가능**해야 한다. 유료 뽑기 또는 현금결제 시스템은 이 설계 범위에 없다.

### 6.3 원정 선호 계열: 0~3개

- 원정 진입 전 고유 계열 ID에서 0~3개 선택. 중복 선택 금지.
- 선택 항목은 **오직 카드 보상 생성의 확률 가중치에만** 영향을 준다. 특성 카운트+1, 무료 시너지, 출발 덱 추가 없음.
- **선택하지 않은 계열도 계속 등장한다.** 보상 후보 풀 자체에서 제외하지 않는다.
- `[제안]` 한 번의 카드 보상에 후보 3장을 별개 사본이 아닌 **서로 다른 카드 정의**로 표시하되, 다른 보상에서 동일 카드를 재획득하는 것은 허용한다.
- `[시험값]` 기본 카드 가중치 `1.0`, 선호 계열 가중치 배수 `1.5`. 단, **0/1/2/3개 선택별 배수 차등화는 확정되지 않음**. 처음에는 같은 배수로 시험하고 필요 시 조정한다.
- `WeightedSampleWithoutReplacement(unlockedCards, rewardSlots, seed, preferredTraits, configuredWeights)` 이용. 후보 부족 시 명시적 대체 풀/빈 슬롯 처리, 무한 반복 금지.
- 카드를 많이 해금한 계열이 카드 정의 개수 때문에 과도하게 유리/불리해지는 문제를 계열 기준·카드 기준 확률 양쪽에서 모니터링한다. 필요 시 '먼저 계열을 추첨하고 다음 카드 선택' 방식 시험.
- `[미결]` 모든 계열이 출전 전 즉시 선택 가능인지, 지상 기능 해금이 필요한지. **개별 원정 누적 숙련도로 해금시키지는 않는다.** 초기 구현에서는 유효한 계열을 모두 선택 가능하게 두는 것을 추천.

### 6.4 TFT식 덱 특성: 정의와 계산

**가장 중요한 확정 규칙:**

> `traitCount[traitId] = 현재 원정 덱 안에서 traitId를 가진 카드 사본 개수 총합`

- 같은 카드 정의가 **4장** 있으면, 그 카드 계열의 특성 카운트는 **4**다.
- 서로 다른 이름의 카드 4장도 해당 계열 특성 카운트는 **4**다.
- 카드를 뽑기 더미에서 손패로 가져오거나, 손패에서 사용하거나, 전투 버림/보관/전투 내 소모 영역으로 이동해도 **원정 덱의 소유권이 유지되는 한** 특성 카운트는 변하지 않는다.
- 원정 덱에 **새 카드 사본 추가** 시 +1; 원정 덱에서 **영구 제거** 시 −1; 원정 내 카드 **강화**는 계열 변경 효과가 명시되지 않는 한 카운트를 바꾸지 않는다.
- 보상 후보로 '등장'한 것만으로는 +1이 아니다. 플레이어가 **카드 보상으로 실제 선택해 원정 덱에 추가**해야 한다.
- 원정 종료 시 해당 덱 및 시너지 카운트 초기화. 영구 누적 특성 숙련도 없음.
- `[제안]` 첫 버전에서 카드 정의 하나에 **대표 계열 하나(`primaryTraitId`)**만 둔다. 이후 다중 계열은 확정 정책(중복 계산 여부) 수립 후 도입. 공격·보호·순환 등 기존 기능 **태그**와 TFT 특성 **계열**을 혼동하지 않는다.
- 카드가 시작 덱에 포함되어 있다면 **출전 직후부터 카운트에 포함**된다. 별도의 '보상으로 새로 얻은 카드' 조건이 없다.

**카운트 예시:**

| 사본 | 계열 | 장수 | 기여 |
|---|---|---:|---:|
| `철벽` | 방호 | 4 | 방호 +4 |
| `수호` | 방호 | 2 | 방호 +2 |
| `강타` | 타격 | 3 | 타격 +3 |
| `잔진` | 축적 | 2 | 축적 +2 |

결과: **방호6 / 타격3 / 축적2**.

**시너지 임계값:** `[시험값]` 예를 들어 `2장/4장/6장` 도달 시 단계 활성화. 각 계열별 임계값과 효과는 **데이터에서 독립 설정**하고 10개 계열 공통 고정식을 강요하지 않는다.

**추가 설계 원칙:**
- 낮은 단계는 읽기 쉬운 효과, 높은 단계는 카드 운용을 바꾸는 효과를 우선 고려.
- 일단 **전투 도메인에서만** 덱 특성 효과를 적용하는 것을 추천. 탐험 시간/HP 비용까지 동시 수정하면 두 시스템의 밸런스 원인 구분이 어려워진다.
- 큰 계열 특성을 만들기 위해 약한 카드를 덱에 추가하면 **드로우 일관성이 떨어지는 기회비용**이 발생해야 한다. 오히려 카드를 제거해 카운트가 낮아지는 전략도 의미 있어야 한다.
- 기본 카드 덱 구성과 임계값의 관계에 유의. 예를 들어 기존 시험 출발 덱에 타격4, 보호4가 포함되어 있다면 출발하자마자 해당 계열의 일부 시너지가 켜질 수 있다. 이것은 계산 오류가 아니다. 계열 정의·임계값의 밸런스 문제다.

### 6.5 카드 계열의 종류

`[기획 방향]` 장기적으로 **약 10개 계열**을 구상. **10개 계열 이름·능력·임계값이 확정된 상태는 아니다.**

예시 데이터 후보: `타격/방호/제어/연계/축적/반격/순환/준비/전이/변칙`. 이 목록을 정식 확정 설정으로 취급하지 말 것. **첫 프로토타입은 3~5개만 실제 효과를 구현**하고, 데이터 구조는 10개 이상을 수용하도록.

**예시 시너지(확정 아님):** 방호 2장일 때 보호 부여량 +1, 방호 4장일 때 보호막을 완전히 소모한 뒤 특정 반격 등. 무조건 중복 적용/덧셈인지, 상위 단계 대체인지는 `stackingMode`로 명시한다. 숨은 중첩을 만들지 않는다.

## 7. 기존 전투 설계와 통합 규약

### 7.1 유지할 핵심 전투 계약

최신 실험 설계(2026-10-09, 플레이 시스템 v3)의 핵심은 다음과 같다.

- **4인 파티**, 카드의 캐릭터 귀속 없음, **공용 덱**.
- `카드 → 살아 있는 실행자 → 대상`의 수동 선택.
- 개인 행동게이지·개인 덱·활성 조작 캐릭터 교대 구조를 이번 새 전투 설계에 다시 도입하지 않음.
- 최신 시험 출발 덱은 **10장/4효과**(타격4, 보호4, 견제1, 억제1). 과거 문서에 등장한 20장 덱 등과 혼동하지 말고 **현재 저장소 구현을 먼저 감사**.
- 최신 시험 전투는 라운드 시작 공용 에너지4, 손패5, 적 의도 공개를 기본으로 함. **모두 이전 검증 설계의 시험값**이고 실제 저장소의 구현 완료를 의미하지 않음.
- 전투 새 시작 때 영구 원정 덱 사본/강화/HP는 이월, 손패·전투 일시 상태는 새로 초기화.
- 보상은 3장 중 1장/건너뛰기를 우선 보존. 더 깊은 층의 희귀도와 강한 카드는 이후에 확장.

### 7.2 이전 원정 구조와의 충돌 관리

기존 v3는 **2구간/8전투** 선형에 가까운 실험안을 제안했지만, 새 탐험은 **노드 탐험/연결구/깊이 진입/자발 귀환**으로 구조가 바뀐다.

- **P0~P6의 카드 전투 검증**은 그대로 실행 가능해야 한다. 옛 2구간 8전투 테스트는 ‘카드 전투 및 보상 검증용’으로 유지.
- 새 탐험 원정은 **별도 expedition mode**로 구현해 전투 엔진을 호출한다. 기존 경로를 한 번에 덮어쓰지 않는다.
- 기존 승리 후 전원HP3, 정비회복9, 중간 완전회복 등의 회복 조항은 새 시간 자연 회복과 **중복 밸런스 검증** 후 새로운 원정 모드에 포함할지 결정.
- 기존 서사·전투 전용 저장과 새로운 원정 저장은 버전/모드 키로 구별한다.

## 8. 보상, 위험과 경제

### 8.1 획득 자원의 종류

- **원정 중 일시적 성장:** 원정 덱에 추가한 카드 사본·강화·해당 원정의 덱 특성 단계. 귀환/실패 시 초기화.
- **귀환 후 보유 자원:** 골드 및 확정된 영구 재화. `[미결]` 그 외 자원 종류 및 교환처.
- **해금:** 영구 카드 후보 목록·스토리 열람 기록 등. 이번 원정 실패로 회수하지 않음.

**재화는 이중 보관해야 한다:**

`bankedGold` = 이미 지상에서 확보한 재화 (원정 실패 영향 없음)<br>
`runGold` = 현재 원정에서 모았으나 귀환/실패 정산 전인 재화

- 귀환 성공: `bankedGold += runGold`.
- 원정 실패: `bankedGold += CalculatePartialSalvage(runGold, lossRate)`.
- `lossRate`는 `[미결]`로 설정. 예: 40% 손실이라면 60% 정산, **예시를 확정값으로 취급하지 않음**.
- 골드는 지상 뽑기에서 소비. 지상 뽑기는 게임 내 재화 시스템만을 의미함.
- 모든 자원 변화를 명시적 원정 정산 로그로 남겨 중복 지급/재개 악용 방지.

### 8.2 위험·보상 곡선

- 심도가 높을수록 적 난도가 상승하고 기대 골드/보상 가치도 상승.
- 단, **깊은 층이 강한 적이라는 사실만으로** 무조건 깊이 직행이 최적이 아니게 된다고 보장되지는 않음. 회피 가능한 전투, 보상 획득 방식, 필수 통과 지점 등을 실제 플레이로 검증.
- 출발부터 최심층으로 무작정 진입하는 전략을 막으려고 **강제 사망·임의 함정**을 추가하지 않는다. 정찰 정보, 누적 빌드 성장, 실제 감당하기 어려운 전투 패턴으로 자연스러운 위험을 만든다.
- 시드/심도/테마에 따라 같은 자원이 순서만 바뀌는 경험이 되지 않도록 이벤트·보상·적 조합의 분포를 다르게 하되, **처음부터 수백 개 이벤트 제작 금지**.

## 9. 세계관·서사 접속(시스템을 위한 최소 계약)

### 9.1 작품의 중심 배경

- 1960년경부터 현실과 심층을 잇는 **검고 고요한 수면**이 나타남.
- **심도는 실제 수심이 아니라 현실의 공간·인과·법칙으로부터의 이탈 정도**를 뜻한다.
- 현실적합도는 인간과 기준 현실의 존재적 정합성. 항해사·잠수자, 개인 현실정박장치(닻), 고유 술식은 기존 세계관과 유지.
- `[신규 세계관 방향]` 수면은 **실현되지 않은 세계선/가능성들이 뭉치고 중첩된 공간**. 깊은 곳일수록 더 큰 분기와 이질적인 역사·공간이 뒤섞일 수 있음.
- **주의:** ‘역사적 분기의 영향력’과 ‘물리법칙 이탈 정도’는 동치가 아니다. 단순히 핵전쟁의 유무만으로 심도를 숫자 하나에 기계적으로 매핑하지 않는다. 현실의 선택지가 곧 물리적 평행우주라는 구체 이론, 마법이 가능성을 소모한다는 설정은 **아직 미확정**.
- **오프닝 문구:** **“사라진 가능성에 의미를 두지 말지어다.”** (문구 그대로 보존).

### 9.2 프롤로그와 심도 1

- 깊고 변화무쌍한 수면 전체와 달리 **심도 1은 상대적으로 관측·파악되어 왔다**.
- `[신규 스토리 연결]` 주인공 일행의 초기 회수 임무 대상은 **인간이 심도 1 수면의 특정 구역을 제어/안정화하기 위해 만든 장치**. 구체적인 효과 범위와 사고 원인은 아직 확정하지 않는다.
- 김도윤(C급 항해사), 정하린(B급 항해사), 최서윤(등대), 무명과의 사고, 현실적합도 97.62→79.41, 심도 기록 4.17 등 **기존 사건의 중심축을 무단 변경하지 않는다**.
- 프롤로그의 1장(기존 장면/스크립트)과 별도 반복 탐험 모드를 구분. 도윤의 잠수자 선발은 향후 프롤로그 스토리의 완결 과제이며 탐험 프로토타입 구현 때문에 스토리를 임의 확정하지 않는다.
- 김도윤의 술식 **「정박」**과 범용 현실정박장치 **「닻」**은 다른 개념. 혼동 금지.

## 10. 화면/UX 설계

### 10.1 탐험 화면 권장 영역

```text
┌──────────────────────────────────────────────────┐
│ [심도 2 / 기차역]         [남은 시간 64]  [귀환] │
│                                                  │
│               (현재 노드 2D 배경)                 │
│               [상호작용 가능한 물체]              │
│                                                  │
│        [←]           [↑]           [→]            │
│                                                  │
│  [도윤 HP] [하린 HP] [동료3 HP] [동료4 HP]         │
│  [덱 특성 요약]  [현재 확보 골드]  [지도]          │
│                                                  │
│  [오퍼레이터 초상] “동쪽에서 반응이 있습니다.”      │
└──────────────────────────────────────────────────┘
```

- 시간 >0 시 자원 지불을 **시간으로**, 0 이후 **HP로 전환**되는 것을 화면에 명확하게 표시.
- 행동 버튼에 예상 비용을 노출(이동 `시간 -1`, 소진 이후 `전원 HP -x` 등). 혼합 결제 규칙을 쓴다면 두 비용 모두 노출.
- 시너지는 `방호 3/4 → 카드 1장 추가 시 강화`처럼 **현재 단계/다음 단계**를 압축 표시하고 상세는 별도 패널.
- 같은 노드에서 조사할 수 있는 물체는 해당 물체에 아이콘/핫스폿 또는 명확한 조사 목록으로 제공. 의미 없는 픽셀 헌팅 지양.
- 이미 조사한 상자는 다시 열어 보상을 만들지 않음. 맵, 보상, 연결구 정보는 저장/복원 후에도 동일.
- 오퍼레이터 대사는 화면을 가로막는 강제 컷신이 아니라 짧은 무전으로 표시. 중요한 스토리 컷신만 별도로 연출.

### 10.2 귀환·실패 결과 화면

- **귀환:** 포털 연출(건너뛰기 가능) → 이번 원정 심도/탐험시간/전투/보상/정산 결과 표시 → 지상.
- **실패:** 원인(전멸 등)과 확보 골드, 손실 비율, 최종 보유 골드를 투명하게 표시.
- 두 경우 모두 원정 카드/원정 덱 특성 초기화 및 영구 해금 유지.
- 화면 전환 중 중복 클릭과 저장 도중 강제 중복 정산을 방지.

## 11. 기술 아키텍처 제안(실제 코드베이스 적응 필수)

**Codex는 저장소를 먼저 읽고 기존 프레임워크·코딩 컨벤션을 따른다.** 아래 TypeScript식 타입은 언어 독립적 **데이터 계약 예시**이며 TypeScript 도입 명령이 아니다.

```ts
type TraitId = string;
type CardDefinitionId = string;
type CardInstanceId = string;

interface CardDefinition {
  id: CardDefinitionId;
  name: string;
  primaryTraitId: TraitId;     // MVP: 사본당 대표 계열 하나
  functionTags: string[];      // 공격/보호 등 기능은 계열과 별개
  baseWeight: number;
}

interface RunCardInstance {
  instanceId: CardInstanceId;
  definitionId: CardDefinitionId;
  upgrades: string[];
  // 전투 중 이동하는 draw/hand/discard/retain/exhaust는 '원정 덱 제외'가 아님
}

interface TraitDefinition {
  id: TraitId;
  displayName: string;
  breakpoints: Array<{
    requiredCopies: number;
    effectId: string;
    stackingMode: 'replace' | 'stack';
  }>;
}

interface ExpeditionConfig {
  initialTime: number;           // e.g. 250, TEST ONLY
  minExitDistance: number;       // e.g. 15, TEST ONLY
  moveTimeCost: number;          // e.g. 1, TEST ONLY
  investigateTimeCost: number;   // e.g. 1, TEST ONLY
  combatEntryTimeCost: number;   // e.g. 3, TEST ONLY
  naturalHpRegenRate: number;    // e.g. 0.005, TEST ONLY
  overTimeHpCostRate: number;    // TBD
  failLootLossRate: number;      // TBD
  preferredTraitWeight: number;  // e.g. 1.5, TEST ONLY
}

interface ExpeditionState {
  seed: string;
  configVersion: string;
  timeRemaining: number;
  currentDepth: number;
  depthMap: unknown;             // actual project type
  currentNodeId: string;
  preferredTraitIds: TraitId[]; // 0..3
  runDeck: RunCardInstance[];
  partyHp: number[];
  runGold: number;
  phase: 'EXPLORING'|'COMBAT'|'REWARD'|'DESCENDING'|'RETURNED'|'FAILED';
}

// 계산은 '소유 중인 원정 덱 전체'의 사본 목록에서 직접 산출.
function CountTraits(runDeck, cardDefinitions): Record<TraitId, number>;
function GenerateDepthMap(seed, depthIndex, biomeConfig): DepthMap;
function ShortestPathLength(map, startId, targetId): number;
function PayExplorationActionCost(expedition, cost, action): TransactionResult;
function GetOperatorHint(map, currentNodeId, exitNodeId): OperatorHint;
function GenerateCardReward(unlockedCardIds, preferredTraits, seed): CardDefinitionId[];
function ResolveExtractionOrFailure(expedition, result): Settlement;
```

**권장 모듈 경계:**
- `ExpeditionController`: 상태 전환/원정 전체 진행.
- `MapGenerator + MapValidator`: 맵 생성/연결·거리 검증.
- `ExplorationActionService`: 시간→HP 비용, 자연 회복, 이동·조사.
- `OperatorHintService`: 정보의 내용/발동/기록.
- `CombatAdapter`: 기존 전투 엔진 입장, 결과 HP·보상 반영; **전투 라운드에서는 원정 시계 접근 불가**.
- `TraitCounter + TraitEffectSystem`: **원정 덱 사본 수**에 따른 단계 계산 및 전투 패시브.
- `CardRewardService`: 영구 해금 풀 + 선호 가중치 → 카드 후보 제시/선택.
- `AccountProgression + Settlement`: 골드 은행, 뽑기, 영구 해금/부분 회수.
- `SaveVersioning`: 원정 시드/이미 생성된 맵/이벤트 완료/덱 사본/시너지/정산 기록 복원.

**중요:** `CountTraits`는 전투 손패·버림·소모 카드를 직접 세면 안 된다. **원정 덱 소유 사본 목록 한 곳**이 단일 진실 공급원(SSOT)이어야 한다. 카드가 전투 도중 복제되더라도 '원정 덱에 영구 추가'되는 효과가 명시되지 않은 임시 사본은 특성을 늘리지 않는다.

## 12. 단계별 구현 계획 — Codex 작업 단위

> 원칙: 기존 전투/스토리 코드 삭제·대규모 리팩터링보다 **새 탐험 수직 슬라이스를 독립 실행**. 작업 단계마다 화면에서 동작과 테스트를 확인. 임시 아트로 먼저 재미 검증.

### E0. 저장소 감사 및 분리(가장 먼저)

1. 프로젝트 엔진/빌드/라우팅/현재 전투 진입점·상태/저장 경로/테스트 환경을 실제 파일로 확인한다.
2. 최신 게임 전투 설계와 현재 코드가 다른 부분을 표로 정리한다(구현 완료와 문서 설계 구분).
3. 기존 `tactical.html` 등 실험물을 덮어쓰지 않는다. 새 탐험 진입점 또는 feature flag 추가.
4. 이 문서의 `[미결]`을 설정값/정책 인터페이스로 선언하고 TODO에 근거를 명시한다.
5. 현 코드 동작을 보장하는 스모크 테스트를 수행한다.

**인수조건:** 기존 전투/스토리 진입이 변하지 않고, 새로운 탐험 실험으로 진입할 수 있다.

### E1. 화살표 이동 + 절차적 맵(전투 없이)

1. 간단한 임시 2D 배경/노드/화살표 UI.
2. 고정 시드 맵 생성, 노드 연결, 방문 표시, 지도, 연결구.
3. `minExitDistance` BFS 검증과 최단거리 하한 테스트.
4. 연결구 선택으로 다른 맵/테마 전환(임시 배경만 다르게).
5. 저장/복원 시 동일한 맵 구조 유지.

**인수조건:** 100~1000개 시드 반복 생성 시 시작/연결구 도달 가능, 최단거리 하한, 출구 유효성을 모두 만족. 시드가 같으면 항상 같은 맵.

### E2. 시간 + 자연 회복 + 시간 초과 HP 탐험

1. 행동 비용 트랜잭션 및 UI 미리보기.
2. 시간 소진 시 자동으로 HP 비용으로 전환, 음수 시간 금지.
3. HP 비율 회복의 누적 정밀도 검사, 전투 내부 자동 회복 차단.
4. 원클릭 지상 포털 귀환과 부분 손실 정산(설정 가능한 시험 비율).
5. 행동 불가 상태에서 UI 소프트락 방지.

**인수조건:** 경계 `T=2,c=3`, `T=0`, `T>c`, HP 부족, 귀환 직전, 저장/재개 경우 정확히 한 번 차감/정산.

### E3. 오퍼레이터 힌트 + 조사 + 획득 보상

1. 방향 힌트 트리거, 논리 좌표/경로에 따른 대사 표시.
2. 조사 1회 제한과 완료 상태 기록, 골드 획득.
3. 이미 탐색한 노드의 재방문에서 보상 중복 획득 방지.
4. 힌트 위치가 실제 맵 위치와 모순되지 않는지 검증.

**인수조건:** 무전이 없어도 연결구 도달 가능, 힌트가 유효하며 지도를 대신 풀지 않는다.

### E4. 기존 4인 카드 전투 연동

1. 기존 전투 엔진을 **어댑터로 호출**(원정 HP·덱 상태 전달).
2. 전투 진입 비용은 한 번만 부과하고 전투 중 탐험 시계 정지.
3. HP/카드보상/실패 결과를 탐험으로 복귀시킨다.
4. 기존 2구간 8전투 테스트·P0~P6 시나리오는 계속 실행 가능하게 보존.

**인수조건:** 3턴/30턴 전투가 동일한 원정 시간 비용을 쓰며, 같은 전투 중 자연 HP 회복 0.

### E5. 카드 계열·TFT식 시너지·출발 선호 계열

1. 카드 정의에 `primaryTraitId` 추가. 최소 3~5개 실제 테스트 계열.
2. 원정 덱 사본 카운터와 실시간 단계 효과.
3. 출발 전 0~3 계열 선택 및 카드 보상 가중치.
4. 게임 화면에 카운트/다음 임계점 표시.
5. 기존 전투의 카드/실행자 고유 효과와 시너지 효과 처리 순서 명시, 자동 테스트.

**인수조건:** 동일 카드4장→카운트4, 실제 덱 제거→−1, 손패/버림/전투 소모 이동→변화0, 선호 계열0/1/2/3 선택 및 다른 계열 출현 가능.

### E6. 영구 해금 뽑기 + 완전한 원정 수직 슬라이스

1. 지상 골드 은행/원정 골드 분리.
2. 골드 뽑기: 영구 후보 해금. 원정 덱 자동 부여 금지.
3. 2~3개 심층, 제한된 테마, 전투/조사/연결구/귀환/실패를 통합.
4. 귀환/실패 정산, 원정 덱 초기화, 카드 해금 보존.
5. 시드별 도달·시간·HP·특성 발동·골드 흐름 텔레메트리.

**인수조건:** '지상 시작 → 탐험 → 전투 → 보상/덱 특성 발동 → 다음 심층 → 시간0/HP 탐험 → 귀환 → 카드 해금 → 다음 원정에서 해금 카드 후보 등장'이 하나의 플레이로 동작.

### E7. 재미 검증 후 확대(자동 진행 금지)

- 탐험 시간 250/이동1/조사1/진입3/회복0.5%는 **초기 수치**로만 실험.
- 처음 2~3명 플레이 관찰 후 수정, 이후 5~8명으로 검증. 버튼 수·실제 판단 시점·깊이 진입 빈도·자발 귀환·관계없는 왕복 클릭 비율 기록.
- 전투 P0~P6 카드 재미 검증 결과도 별도로 보존.
- 기본 탐험이 지루하다면 배경 장수만 늘리지 말고 **선택이 일어나는 빈도, 방향 정보, 위험·보상 위치**부터 수정.

## 15. 실제 사용자 플레이 테스트에서 물어볼 질문

- 연결구 방향 무전이 **결정을 돕는가**, 아니면 안내를 따라가기만 하는가?
- 방문한 방 중 절반 이상이 판단 없이 동일 행동을 반복하게 만드는가?
- 시간이 0인 순간 플레이어가 **자발적으로** 더 조사하려 하는가?
- 깊은 심층을 무조건 피하거나 무조건 달리는 전략이 독점하는가?
- 원정 보상에서 약한 카드라도 **특성 임계점 달성** 때문에 선택한 사례가 있는가?
- 선호 계열 0개, 1개, 2개, 3개 선택이 모두 의미 있는가?
- 해금 카드가 늘어났을 때 오히려 원하는 전술을 만들기 더 어려워졌는가?
- 게임이 진짜 **수면에서 불가능한 세계를 발견하는 느낌**을 주는가? 또는 시간 숫자를 관리하는 반복 작업에 머무르는가?

**통합 성공 기준:** 카드 전투 자체의 판단 재미를 해치지 않으면서 탐험·무전·하강·덱 특성 선택의 추가가 플레이어의 재도전 동기를 실제로 증가시켜야 한다. 이를 측정하기 전에는 대규모 아트·새 캐릭터·계열 10종 전체 제작을 시작하지 않는다.

## 16. Codex 최종 작업 지시(이 섹션을 작업 요청으로 사용 가능)

> 기존 저장소를 먼저 검사하고 파일별 현황·프로젝트 엔진·전투와 스토리 진입점을 보고한 뒤, **기존 시스템을 파괴하지 않는 독립 탐험 프로토타입**을 구현하라. 위 GDD의 `[확정]` 규칙을 최우선으로 지키고, `[시험값]`은 설정에 분리하라. `[미결]`은 독단 확정하지 않고 명시적 임시 정책으로 다뤄라. 특히 전투 라운드에는 탐험 시간/자연회복이 절대 적용되지 않아야 하며, 4인 공용 덱·카드→실행자→대상 전투 구조를 유지하라. 먼저 E0~E2를 구현해 시드 재현, 노드 최단거리 불변조건, 화살표 이동, 시간→HP 전환, 귀환·정산을 테스트하라. 이후 E3~E6을 순서대로 통합하되 각 단계별 테스트 결과와 실제 플레이 방법을 보고하라. 대규모 자산 제작이나 전투/스토리 전면 재작성은 금지한다. E0 감사 결과 실제 저장소와 이 설계가 충돌하면 코드로 추측해서 덮지 말고 충돌 지점을 명확히 보고하라.

**설계 상태:** 탐험 및 특성 시스템의 **구현 착수용 GDD**. 사용자 결정 사항은 보존했으며, 미확정 수치·정책은 분리했다. **아직 재미 검증 완료 또는 최종 밸런스 확정 문서가 아니다.**
