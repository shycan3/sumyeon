# UI·UX 평가 및 발전 로드맵

평가일: 2026-10-07. 대상: `prototype/character.html?v=workspaceui1`.

## 결론

현재 업데이트는 긴 페이지를 하나의 작업 공간으로 묶고, 현재 방 선택과 상태를 함께 보여주는 데 도움이 됐다. 다만 화면 압축의 효과가 크고 읽기·비교·조작 연속성은 아직 충분히 검증되지 않았다. PC/390×844 동작 검사를 통과했다는 사실과 사용자가 이해하기 쉽다는 결론은 구분한다.

다음 목표는 **전투 사이에는 덱 선택의 결과를 쉽게 이해하고, 전투 중에는 캐릭터의 행동을 편하게 관전하는 UI**다. 사용자가 요청한 한 화면 구조는 유지한다. 모든 상세 설명을 동시에 축소하여 넣는 방식 대신, 핵심 판단과 확정 버튼은 바로 보이고 상세는 같은 작업 공간에서 조회하도록 한다.

이번 요청에서는 제품 UI를 추가로 변경하지 않았다. 실제 화면·코드·측정 결과를 바탕으로 개발 순서와 완료 조건을 정했다.

## 평가 근거와 한계

1. 코드/기존 구현 문서 검토, PC·모바일 스크린샷 확인.
2. 격리 브라우저의 1280×720, 390×844, 320×568, 844×390, 768×1024에서 거점·출발·지도·두 갈림길·전투·보상 측정. 사용자의 저장은 변경하지 않았다.
3. 별도 모바일 편성 조작과 팝업 이름/상태 확인.
4. 공식 게임 자료와 접근성 문서를 참고. 레퍼런스의 기능 사실과 우리 적용 제안은 구분한다.

측정은 기본 글자 크기·해당 출발 덱/상태의 표본이며 전체 기기/모든 저장/모든 조합을 보장하지 않는다. 사용자 이해도·오조작률·만족도는 아직 측정하지 않았다. 접근성 전체 적합성 감사도 아니다.

## 유지할 부분

- 지도에서 방의 혜택·기회비용·진입 버튼을 함께 제공하는 구조.
- PC의 현재 선택/상태 나란한 배치와 모바일의 고정 상태 요약.
- 카드 그림·이름·텍스트 특성 표기. 색만으로 정보를 구분하지 않는 방향.
- 빠지는 카드/들어오는 카드/최종 특성 변화와 명시적 교체 확정.
- 상세 조회에서 닫기·Escape·포커스 복귀를 제공하는 기반.
- 실측 기여도와 같은 초기 조건의 덱 수정 연습. 새 분석 엔진보다 이 데이터를 활용한다.

| 화면 후처리에 크게 의존 | 공통 MutationObserver가 생성된 DOM을 재배치하고 상세 내용을 이동·복원 | 현 재현만으로 모든 오류를 단정하지 않음. 명시적 화면/상태 구조로 단계적 교체 권장 |

1280×720의 현재 보상 3후보 선택/넘기기는 모두 완전히 보였다. 오래된 스크린샷의 잘림을 현재 모든 PC 보상 결함으로 일반화하지 않는다. 다른 화면 크기/보상 상태는 별도 검사한다.

## 제거·축소·추가 기준

제거/축소: 작은 글자로 화면을 맞추는 방식, 후보 카드 안의 세로 스크롤과 작업 영역 스크롤이 겹치는 구조, 단순 용어 설명마다 전체 화면 팝업을 띄우는 방식, 일반 관전의 수동 조작 노출, 화면마다 반복되는 장문의 규칙과 진단 지표.

유지: 원정 규칙/기회비용, 읽을 수 있는 효과/수치/특성, 명시적 교체 확정, 실측 기여도, 동일 조건 연습. UI 정리 때문에 게임 규칙/보상 조건/판정 정보를 없애지 않는다.

추가: 비교 후보 고정, 최종 덱 변화 미리보기, 편집 위치·포커스 보존, 편성 변경 되돌리기, 현재 선택/후보 수 표시, 변경한 덱과 실제 전투 기록의 연결. 신규 대시보드·화폐·상점·긴 튜토리얼은 이번 UI 로드맵에 추가하지 않는다.

## 순서대로 개발할 로드맵

### 1. P0 — 읽기와 핵심 행동 안정화

- 상태 요약이 주 선택 영역의 최소 높이를 침범하지 않도록 너비뿐 아니라 화면 높이에 따른 레이아웃을 정의. 짧은 화면에는 압축 상태/조회 버튼을 사용한다.
- 출발·전투 시작·선택·넘기기·확정·취소를 항상 접근 가능한 공통 행동 영역에 배치. 필요하면 한 방향 내부 스크롤을 허용하며 스크롤 불가 상태로 숨기지 않는다.
- 핵심 본문 14~16px, 보조 표기 최소 12px를 우선 설계 기준으로 시험. 중요한 모바일 행동은 약 44×44 CSS px 이상을 목표로 한다. 이 수치는 우리 제품 목표다.
- 단순 상세는 작은 설명창/고정 설명 영역으로, 긴 규칙/전체 기록만 팝업으로 분리. 팝업 이름·키보드 상태·포커스와 닫힘 이후 복귀를 고친다.
- 테스트를 페이지 scrollHeight 검사에서 주 행동의 실제 클리핑·최소 사용 영역·키보드 접근 검사로 확장한다.

완료 조건: 320×568/360×640/390×844/844×390/1280×720/태블릿에서 주 선택 영역이 소실되지 않음. 해당 화면의 주요 행동은 추가 설명 조회 없이 도달 가능. 텍스트 200% 확대와 키보드에서 기능 누락 없음. 불필요한 두 방향 텍스트 스크롤 없음.

[W3C Target Size Minimum](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)은 24px 및 간격 예외를 설명한다. [44px 기준](https://www.w3.org/WAI/WCAG21/Understanding/target-size)은 강화된 AAA 기준이며 모든 웹 UI의 AA 의무라고 부르지 않는다. [Reflow](https://www.w3.org/WAI/WCAG21/Understanding/reflow)는 작은 폭/확대에서 정보·기능을 잃지 않는 기준의 근거다.

### 2. P1 — 카드 비교와 편집을 한 흐름으로 연결

- 모바일도 후보 3~4장의 이름·역할·특성을 요약 목록으로 함께 확인. 탭한 후보의 설명을 한 고정 영역에 확대. 읽을 수 있는 카드 그림/효과는 유지한다.
- 선택 후보와 교체할 카드를 함께 고르면 정확한 최종 특성·기술 기능·명령시간 변화를 미리 표시. 단순 '추가 시 종류 수'와 실제 교체 결과를 혼동시키지 않는다.
- 카드 선택→교체/대기→확정의 의미를 명확하게 연결. 미리보기는 보상 획득·카드 상한·난수·저장·덱을 바꾸지 않는다. 제안 목록은 그대로 고정.
- 태세처럼 여러 항목을 바꾸는 편집 창은 한 항목 변경마다 닫히지 않고 완료까지 유지. 설명 조회와 편집 창을 구분한다.
- 편집 때 카드 선택/스크롤/필터/포커스를 보존. 캐릭터·특성·편성/대기 필터는 기존 작은 카드 풀에서 실제 탐색이 어려울 때 최소한으로 도입한다.
- 편성 변경 취소/되돌리기 제공. 되돌리는 범위는 다음 전투 전의 덱 변경이며 획득 보상이나 게임 난수를 되감는 기능이 아니다.

완료 조건: 마지막 후보/카드를 조정해도 처음으로 돌아가지 않음. 교체 전 실제 활성·하락 특성을 설명할 수 있음. 정확히 20장/사본 상한/원정 한정/저장 재현 유지. 조회 취소는 상태를 바꾸지 않음.

### 3. P1 — 풀오토 관전 화면 정리

- 기본 화면을 전장·동료 HP·현재 주요 스킬·예고 위험·다음 명령으로 구성. 조작 패널의 비중을 줄여 캐릭터 행동이 중심이 되도록 한다.
- 일반 화면의 수동 전환/직접 개입/카드 확정/대기를 개발·실험 도구로 이동. 게임 로직은 검증 도구에서 유지하며 도전은 오토 한정을 계속 지킨다.
- 배속·관전 정지·소리·연출 설정의 역할과 위치를 통일. 손패는 관찰 정보로 제공하고 사용 명령처럼 보이는 표현을 줄인다.
- 전투 직전의 덱·태세·오토 방침은 유지. 전투 중 바꾸지 못하는 것은 잠김 상태/이유를 명확히 표시한다.

완료 조건: 처음 접한 플레이어가 카드 입력을 요구받는 것으로 오해하지 않음. 주요 기술 사용자·대상·발동 특성을 관전 중 식별할 수 있음. 연출이 HP와 위험 예고를 가리지 않음. 위젯 때문에 전투 시간/난수/오토 판단이 변하지 않음.

### 4. P2 — 덱 변화의 결과를 이해시키기

- 결과 첫 화면에 이번에 바꾼 카드와 실제 사용/효과/연계 장면 1~3개를 요약. 세린 고정 타수와 큰 통계 표는 상세로 이동한다.
- 기존 실측 기여도와 전투 시작 기록/연습을 재사용. 손패 미등장·등장했지만 미사용·효과가 실제로 발생함을 구분한다.
- '이번 특성이 몇 번 발동했나', '추가 카드가 누구를 구했나' 등 기록 가능한 결과를 표시. 기록이 없는 효과는 추정하지 않는다.
- 같은 시작 조건의 이전 덱/현재 덱 비교를 기존 연습에 연결. 난수 소비 변화 때문에 완벽한 인과 실험은 아니라는 설명은 비교 화면에 짧게 제공한다.

완료 조건: 사용자 검사에서 바꾼 덱이 만든 실제 행동 차이를 한 가지 이상 말할 수 있음. 단일 카드가 승리 원인이라고 자동 단정하지 않음. 원정/영구 경험치/도전 성적에 연습이 영향을 주지 않음.

### 5. P2 — 식별 체계와 공통 화면 구조 마무리

- 카드=소유자 그림/이름, 특성=고정 색+아이콘+텍스트, 기능=공격/회복/보호/이동의 일관된 요약으로 분리. 색에 모든 의미를 맡기지 않는다.
- 선택됨/비교 중/편성됨/대기/진화를 공통 상태로 표시. 화면마다 다른 명칭과 버튼 위치를 정리한다.
- 정상 흐름과 개발 실험실을 분리하고 중복 설명·중복 진단 표기를 줄인다.
- 전역 DOM 후처리를 줄이고 명시적인 화면/패널/팝업 상태를 사용. 공통 상태·행동·카드 비교 컴포넌트로 단계별 화면을 교체한다. 일괄 재작성은 피한다.

이 기술 정리는 1~4단계를 구현하면서 함께 진행한다. 완료 조건: 조작/저장/화면 전환 회귀 없이 같은 정보가 같은 표현/위치에 등장. 색을 구별하지 못해도 상태와 특성이 식별됨.

## 검증 계획과 중단 기준

자동 검사: 다양한 높이/폭, 버튼의 실제 가시 영역, 글자 확대, 주 영역 최소 크기, 키보드/포커스, 팝업 이름/복귀, 카드 레일/필터 위치 보존, 미리보기 무부작용, 교체·취소·20장/상한, 저장, 모바일 방향 변경, 전투 정지/배속/연출.

사용자 검사: 보상 3장 비교 시간, 후보 왕복/팝업 재열기 횟수, 교체 후 특성 예측 오류, 편집 중 엉뚱한 버튼 클릭, 덱 변화 설명 가능 여부. 자동 검사로 이 지표를 대신하지 않는다. 개선 전/후에 같은 과제를 사용하고 기준선을 먼저 측정한다. 작은 사용자 표본의 결과를 통계적 입증으로 표현하지 않는다.

새 화면/탭/상태를 늘렸는데 후보 비교와 조작 오류가 줄지 않으면 기능을 더 쌓기 전에 정보 구조를 수정한다. 첫 구현 묶음은 1단계 읽기·영역 안정화이며, 다음이 2단계 비교·편집 흐름이다.
