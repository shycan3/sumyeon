# refineui1 업데이트 리뷰

2026-10-07. 직전 비판점 수정 업데이트를 코드와 격리 브라우저로 검토했다. 게임 구현은 변경하지 않았으며, 사용자 저장과 독립된 테스트 컨텍스트만 사용했다.

## 판단

편성 탐색, 관전 공간, 입력 동작, 과거 덱 비교가 개선됐다. 기존 결함을 상당 부분 해결한 업데이트지만, 카드 식별과 조회창 조작의 회귀가 남았다. 기능을 더 추가하기 전에 아래 네 가지를 정리하는 편이 효과적이다.

## 해결 확인

- 대표 스킬의 기술명·사용자·대사·초상화가 검사한 6개 화면에서 영역 안에 들어갔다. PC 1280×720 대표 스킬 표본은 스킬 영역 72px, 전장 영역 높이 251px였다.
- 카드 조회 summary의 Space 입력이 조회창을 열며 관전 정지 상태를 바꾸지 않았다. 손패 교체 후 포커스가 손패에 유지됐다.
- 실험 도구를 닫아도 기존 정지 상태가 유지됐다. 관전 정지가 수동 개입 횟수를 늘리지 않았다.
- 사용 횟수와 부분 측정 효과의 구분, 진화 전 과거 덱 재현과 원본 복원, 연습의 원정 데이터 비변경 검사를 통과했다.

재실행한 검사는 `refinement-check.cjs`, `refinement-browser-check.cjs`다. 브라우저 검사 크기는 1280×720, 390×844, 320×568, 844×390, 768×1024, 360×640이다. 이 통과 결과가 모든 카드 식별·장문·접근성 동작의 완성을 뜻하지는 않는다.

## 추가로 재현한 문제

### 1. 일반·진화 카드가 편성 목록에서 같은 모습이다 — 우선 수정

원정의 차단 방패 한 장만 진화시킨 다음 편성을 열었다. 일반·진화 그룹은 실제로 분리됐지만 두 행 모두 다음 텍스트를 표시했다.

> 차단 방패 / ◆ 호위 / 편성 1장 · 대기 0장

1280, 390, 320px 모두 동일했다. 진화 배지 DOM은 있지만 `editor-ui.css:1`의 `.deck-card-list .card-states{display:none!important}`에 의해 가려진다. 선택한 상세에는 진화 상태와 실제 수치가 정확하게 나온다. 따라서 계산 문제가 아니라 목록의 식별 문제다.

사용자는 두 행을 각각 열어야 어느 것이 진화 카드인지 알 수 있다. 카드의 상태를 명확하게 보여주겠다는 이전 UI 목표와 구현 문서의 “일반/진화 상태를 목록에서 확인” 설명을 충족하지 못한다.

**개선:** 목록에서도 작은 `일반 / 진화` 표시를 유지한다. `선택됨`처럼 중복되는 상태만 숨긴다. 검사도 배지의 DOM 존재 여부 대신 실제 가시성과 목록의 카드 구별 여부를 확인해야 한다.

### 2. 전황·기록 조회창이 겹치고 Escape로 닫히지 않는다 — 우선 수정

1280×720에서 전황 상세를 열고 Escape를 눌렀지만 열림 상태가 유지됐다. 전투 기록 summary로 키보드 포커스를 옮겨 Space를 누르면 두 창이 동시에 열린다. 두 창 모두 우하단 고정 위치를 차지하여 전황 상세가 전투 기록을 가린다. 다시 Escape를 눌러도 두 창이 유지됐다.

`character-app.js:126`은 Escape 대상으로 카드 조회와 실험 도구만 처리한다. `watch-ui.css:2`는 모든 열린 전투 details에 같은 고정 위치를 부여한다. 뒤의 화면은 어둡게 보이지만 해당 조회창들은 공통 dialog처럼 초점과 닫기를 관리하지 않는다.

**개선:** 전투 조회창은 한 번에 하나만 열고, 동일한 닫기 버튼과 Escape 동작을 제공한다. 조회창이 열렸을 때 초점 복귀도 같은 규칙으로 관리한다. 전황 정보를 숨기는 방향 자체는 관전 중심 게임에 적절하다.

### 3. 작은 화면에서 수량 변경 시 읽던 상세 위치가 초기화된다 — 다음 수정

320×568에서 전체 회복 카드 상세를 아래로 32px 스크롤하고 `− 한 장 빼기`를 눌렀다. 같은 카드 상세가 다시 렌더링되면서 스크롤이 0으로 돌아갔다. 목록의 위치 보존은 동작하지만 상세 안의 실제 스크롤은 보존되지 않았다.

`workspace-ui.js:12`가 저장하는 `.deck-selected`의 scrollTop은 이 경우 0이다. 실제 스크롤 요소는 `editor-ui.css:1`의 `.deck-selected .visual-card`다. 19장 오류 문구가 나타나 상세 높이도 169px에서 150px로 줄었다. 긴 효과와 수치를 확인하며 수량을 조절하는 작업에 반복 탐색이 생긴다.

**개선:** 같은 카드의 수량 변경에는 상세 article의 스크롤을 보존한다. 다른 카드로 선택을 바꿀 때는 상세를 맨 위에서 시작한다. 가능한 한 상세의 세로 스크롤 주체도 하나로 정리한다.

### 4. 성장 장면이 카드 기여와 아군 전투불능을 구별하지 않는다 — 다음 수정

첫 전투를 각 동료 HP 1로 시작한 격리 시나리오에서 실제 패배 사건을 검사했다. 결과의 “실제 효과 장면” 세 개 중 두 개가 적이 아군을 쓰러뜨린 사건이었다.

- `추격 사수 → 지원 사수 · 처치 타격 5`
- `추격 사수 → 세린 · 처치 타격 5`

적과 대상 이름은 사실대로 나오므로 피해 계산이나 저장 손상은 아니다. 다만 `result-story.js:8`이 모든 KO를 같은 `처치 타격`으로 표시하여 카드 기여 장면과 패배 계기가 섞인다. 코드 검토상 새 기본 회복 사건도 카드 원본 키가 없는 경우 `카드 연결 미기록`으로 표시하므로, 카드가 관여하지 않은 기본 행동과 기록이 부족한 과거 사건을 구별하지 못한다.

**개선:** 적 처치는 `적 처치`, 아군이 쓰러진 사건은 `아군 전투불능`으로 구분한다. 결과 요약에 카드 기여 장면과 실패 계기를 각각 배치한다. 새 사건에는 기본 행동/카드/적 행동의 출처를 기록하고, 과거 기록에만 출처 미기록 표시를 적용한다. “실제 사건”을 보여주는 방향은 유지해야 한다.

## 추가 UX 개선 판단

모바일 편성에서는 덱 특성이 별도 조회창 안에 있다. 화면은 간결하지만 “이 변경으로 특성 단계가 어떻게 달라지는가”를 확인하려면 편성과 조회창을 오가야 한다. 이는 오류가 아니라 다음 개선 과제다.

전략의 중심이 덱 구성과 오토 행동 변화인 만큼, 편성 확정 버튼 위에 작은 현재 특성 요약과 편집 전 대비 단계 변화를 표시하는 것이 좋다. 긴 설명은 기존 조회창에 두고, 같은 카드 사본 추가가 새 특성 종류를 늘리지 않는다는 것도 수치로 명확하게 보여준다. 작은 화면에 큰 카드 그림을 다시 넣는 것보다 우선할 만하다.

## 검증 증거와 범위

추가 감사 스크립트: `prototype/refine-review-audit.cjs`.
출력: `prototype/refine-review-audit.json`.
화면: `prototype/review-refine-editor-320.png`, `prototype/review-refine-drawers.png`, `prototype/review-refine-defeat.png`.

새 감사는 실제 일반·진화 사본, 실제 수량 조작, 키보드 조회 동작, 엔진에서 발생한 KO·회복 사건을 사용했다. 저체력 전투는 사건 분류를 재현하기 위한 의도적 시나리오이며 일반 원정의 난이도나 패배 빈도에 대한 근거는 아니다. 사용자 편성 시간·탐색 부담·성장 이해도는 아직 실측하지 않았다.

권장 순서는 **진화 식별 → 조회창 통일 → 상세 스크롤 → 결과 사건 분류 → 짧은 특성 변화 요약**이다.
