# 개발 로드맵 v7.0 — release6 이후

작성일: 2026-10-08

이번 주기의 목표는 **현재의 작은 프로토타입을, 준비를 바꾸면 싸우는 모습이 달라지고 같은 캐릭터로 다시 하고 싶은 게임으로 만드는 것**이다. 4인 파티·20장 덱·손패 5장과 풀오토를 기준으로 한다. 아래 번호는 새로운 개발 주기의 1~6이다.

## 출발점과 우선순위

v6의 기능 구현과 자동 검사는 마쳤다. 보상 비교, 특성·배치·방침, 경로 성장, 같은 조건의 연습, 동일 역할 교체, 궁극기, 제작 정의, 발견 기록을 다음 개발에 활용한다.

남은 문제는 서로 다르다.

- **재현된 전투 문제:** 같은 보스 시작 조건에서 진화한 회복 카드가 일반 사본 구성보다 불리한 선택을 만든 사례가 있다. 이를 궁극기 문제로 설명할 수는 없었다.
- **아직 원인을 구분해야 하는 균형 문제:** 5단계의 단순 경로·첫 보상 선택 16원정에서 의무관 3/8, 노아 2/8이 완주했고 노아+리아 4개 표본은 모두 실패했다. 이 수치는 최적 준비의 승률이나 모든 조합의 성능을 뜻하지 않는다.
- **사람이 확인해야 하는 경험:** 새 이용자가 원정 흐름을 이해하는지, 실패 후 바꿀 준비를 생각하는지, 전투 장면에서 캐릭터의 매력을 느끼는지는 미확인이다.

따라서 먼저 실패를 만드는 이유를 구분하고, 그 위에 빌드·상대·연출의 차이를 쌓는다. 소수 콘텐츠를 반복해서 즐길 수 있는지를 기준으로 다음 범위를 조절한다.

## 개발 순서

| 순서 | 개발 묶음 | 플레이에서 생길 변화 |
| --- | --- | --- |
| 1 · 적용·재현 수정/비교 | 원정의 실패 원인과 성장 역효과 수정 | 실패 후 바꿔볼 준비가 있고, 오토 오류가 준비의 가치를 가리지 않음 |
| 2 · 적용·비교 | 기존 캐릭터의 빌드 분화 | 같은 캐릭터가 보상과 덱에 따라 다른 방식으로 활약 |
| 3 · 적용·비교 | 서로 다른 공략을 요구하는 원정 | 출발 덱만 반복하기보다 이번 상대에 맞춰 성장 방향을 선택 |
| 4 · 적용·검사 | 대표 캐릭터 한 명의 표현 완성 | 보호·추격·대표 기술을 보는 순간 캐릭터의 성격과 강점을 느낌 |
| 5 | 준비·보상·복기의 결정 흐름 정리 | 한 화면에서 필요한 결정을 끝내고 곧바로 관전으로 돌아감 |
| 6 | 소규모 테스트판 묶음과 조정 | 처음부터 끝까지 독립적으로 플레이하고 다음 판의 개선점을 확인 |

## 1. 원정의 실패 원인과 성장 역효과 수정

**적용: supportfix1.** [회복 오류 수정·384회 원정·48회 경로 비교·검사와 한계](원정_실패와_지원판단_v7_1단계_검증.md). 알려진 진화 회복 역효과를 고치고, 실제로 쓸 수 있는 짧은 회복 대안이 없는 경우를 보호했다. 조합·방침·경로의 원인을 구분하고 생존 동료의 덱 준비 단서를 표시했다. 회복 경로 편향과 실제 이용자의 이해도는 남은 검토 항목이다.

**첫 개발 범위:** 이미 재현된 회복 카드 선택의 역효과를 고치고, 보호 방침·노아+리아·낮은 레벨 경로의 문제를 조사한다. 신규 전투 시스템을 추가하기 전에 진행한다.

작업:

- 보스 진입 HP·덱·배치·방침·시드를 고정해 일반/진화 사본의 선택을 비교한다. 회복 대상, 실제 회복량, 명령 점유 시간과 그 사이의 전투불능을 확인한다.
- 더 큰 전체 회복이 단일 위기 회복을 밀어낸 이유를 고친다. 실제 현재 효용과 시전 가능성을 비교하고, 숨은 미래 행동을 미리 아는 최적 오토를 만들지는 않는다.
- 노아+리아와 보호 방침은 카드 선택 오류, 화력/지원의 구조적 공백, 잘못된 교체, 누적 소모를 구분한다. 조합을 무조건 상향하거나 승률을 동일하게 맞추지 않는다.
- 낮은 레벨에서 회복·성장 경로를 선택할 근거가 각각 있는지 비교한다. 부상 상태와 만전 상태를 나누고 변경한 요소를 기록한다.
- 첫 원정은 핵심 결정에 짧은 설명을 붙이고 상세 분석을 접는다. 실제 이용자의 멈춤 지점을 확인하면 우선 수정한다.

완료 기준:

- 알려진 역효과 사례의 잘못된 판단이 수정되고, 다른 회복 상황에서 새 오류가 생기지 않는다. 진화가 모든 상황의 승리를 보장하는 기준은 아니다.
- 시험한 조합의 약점과 유효한 대응 사례를 설명할 수 있다. 실패 원인이 불명확한 사례는 별도로 남긴다.
- 플레이어가 바꿀 준비를 제시할 수 있는 패배와, 코드 오류로 생긴 패배를 구분한다.
- 기존 진행 중 원정·저장·공개 도전의 규칙을 보존한다. 판단 변경은 새 규칙 버전으로 적용한다.

## 2. 기존 캐릭터의 빌드 분화

**적용: noabuild1.** [노아의 보상 두 방향·216교전·세린 분기·호환성과 한계](캐릭터_빌드_분화_v7_2단계_검증.md). 밀착 보호와 주변 회복이 위치·분담·회복 범위를 바꾸며, 기존 기초 키트와 오토 공유 구조를 유지한다. 실제 플레이에서의 식별성과 원정 누적 균형은 남은 확인 항목이다.

**목표:** 성장한 카드는 더 큰 숫자와 함께 캐릭터의 행동·연계를 바꾼다.

세린의 기존 검무/수호 검무, 추격 릴레이와 호위·추격·공명을 먼저 활용한다. 새 이름의 성장 메뉴를 중복해서 추가하지 않는다.

작업:

- 세린의 추격과 보호 운용이 실제 표적 제거 순서·동료 보호·궁극기 준비에 어떤 차이를 내는지 정리한다.
- 그 결과를 바탕으로 리아 또는 노아 한 명에 운영 분기 두 가지를 시험한다. 예시는 리아의 단일 표적 집중/후속 연계, 노아의 위기 회복/피해 예방이다. 구체적인 효과와 수치는 구현 전 확정한다.
- 새 전용 보상 또는 기존 대표 기술 변형을 **합계 두 가지 이내**로 시험한다. 캐릭터마다 수십 장을 추가하지 않는다.
- 원정 보상으로 운영이 열리되 출발부터 기본 정체성과 대표 장면이 성립하도록 한다.
- 특성 완성, 카드 사본 비중, 방침이 각 분기의 장점과 비용을 만든다. 어떤 분기도 특정 한 장을 얻지 못하면 작동 불능이 되지 않게 한다.

완료 기준:

- 같은 캐릭터와 같은 상대에서 덱/운용 변경으로 관측 가능한 행동 차이가 생긴다.
- 양쪽이 유리한 상대나 조건, 감수하는 약점이 있다.
- 효과 실행·공통 오토 평가·저장·연습·연출 정의로 연결된다. 전용 AI 전체를 다시 작성하지 않는다.
- 사용자가 상세 로그 없이 차이를 알아보는지는 별도 플레이 결과로 기록한다.

## 3. 서로 다른 공략을 요구하는 원정

**적용: bossroutes1.** [최종 보스 2종·초기 공개·288교전·72원정·검사와 한계](최종상대와_준비경로_v7_3단계_검증.md). 낙하 수호자와 등불 지휘소가 다른 위협을 만들고, 정비 보상 제안이 공개된 상대를 반영한다. 6개 방과 기존 경로를 유지했다. 회복 경로 편향·실제 이용자의 준비 이해도는 남은 확인 항목이다.

**목표:** 매판 카드 목록과 시드만 바뀌는 상태를 넘어, 이번 판의 준비 목표가 달라진다.

작업:

- 기존 6개 방 길이를 유지하고 최종 보스 후보를 둘로 시험한다. 현재 낙하/직선 수호자를 재사용하고, 두 번째는 후열 지원 관계나 전열 돌파처럼 다른 준비를 요구하도록 만든다.
- 다음 위협과 최종 보스의 핵심 성격을 충분히 일찍 공개한다. 마지막 방에서 처음 알게 된 상성이 원정을 무너뜨리지 않게 한다.
- 각 보스에 최소 두 계열의 대응을 시험한다. 특정 캐릭터·이동 카드·수동 회피를 필수로 요구하지 않는다.
- 같은 출발 덱에서 다른 보상/경로가 다른 유효한 최종 구성으로 이어지는지 비교한다.
- 변주가 여전히 약하면 기존 선택 방 하나를 사건 방으로 교체하는 소수 예제를 시험한다. 기능을 바꾸는 보상과 공개된 대가를 짝지으며, 새 화폐·상점 경제를 한꺼번에 추가하지 않는다.

완료 기준:

- 보스와 경로의 공개 정보를 보고 준비 방향을 바꿀 근거가 있다.
- 한 구성으로 모든 위협을 자동 해결하는 것과, 특정 카드가 없어 답이 없는 것을 모두 점검한다.
- 방 수와 평균 진행 부담을 늘리지 않고 원정의 차이가 생긴다.
- 추가 적·보상이 기존 후보 풀을 희석하거나 특정 캐릭터의 키트를 무력화하는지 검사한다.

## 4. 대표 캐릭터 한 명의 표현 완성

**적용: serinlook1.** [세린 이미지 2개·추격/보호 자세·대표 타격·설정·검사와 제작 비용](세린_표현_v7_4단계_검증.md). 전체·간소·장식 연출 끔과 음량을 제공하고 실제 판정 정보를 유지한다. 서브컬쳐 캐릭터의 매력·청감·기억에 남는 장면은 실제 플레이 확인이 남아 있다.

**목표:** 서브컬쳐 방향의 제작 기준을 세린 한 명으로 실제 확인한다.

작업:

- 세린의 초상화·대표 카드 그림·전장 외형에 일관된 색, 실루엣, 표정을 적용한다.
- 이동·준비·타격·보호·마무리의 짧은 동작을 구분한다. 추격과 엄호가 같은 제자리 효과로 보이지 않게 한다.
- 대표 기술과 궁극기에 타격음·효과·짧은 대사를 연결한다. 간소 연출·반복 빈도·음량 설정도 제공한다.
- 기존 특성의 실제 발동에 짧은 연결 표현을 붙인다. 보호가 성공하고 후속 공격이 강화된 순간 등을 보여주며, 발생하지 않은 협동 장면을 연출하지 않는다.
- 풀스크린 전장, 위험 구역, 상태 정보가 연출에 가려지지 않게 한다. 초상화 표시로 전장 크기를 바꾸지 않는다.
- 자산 수, 변경 파일, 제작 시간과 검사를 기록해 다음 캐릭터의 현실적인 제작 비용을 추정한다.

완료 기준:

- 한 캐릭터의 기본 행동부터 궁극기까지 표현이 연결된다.
- 연출을 꺼도 판정 정보가 유지되고, 모바일과 반복 관전에서 안정적이다.
- 시청자가 기억한 기술과 캐릭터의 인상을 확인한다. 이 평가는 자동 검사나 효과 수치로 대신하지 않는다.

## 5. 준비·보상·복기의 결정 흐름 정리

**목표:** 전략을 생각하는 시간과 관전하는 시간이 자연스럽게 이어진다.

작업:

- 1~4에서 늘어난 선택을 기존 준비·보상 화면에 통합한다. 신규 관리 탭을 계속 쌓지 않는다.
- 전투 전에는 적의 핵심 위협과 현재 덱·배치·방침을 한 화면에서 확인한다. 예측을 확정 승리 표시로 만들지 않는다.
- 보상에서는 획득 카드, 빠지는 카드, 특성·기능 변화와 확정 버튼을 중심에 둔다. 같은 내용을 반복하는 설명을 줄인다.
- 결과는 이번 준비가 드러난 사실 한두 개와 다음에 바꿔볼 항목을 먼저 보여준다. 전체 기록은 필요할 때 열게 한다.
- 기존 덱 되돌리기·재준비·연습을 활용해 비교를 쉽게 만든다. 결과 추천이 항상 정답이라고 표현하지 않는다.

완료 기준:

- 출발·한 장 교체·전투 복기·재준비를 키보드와 터치로 일관되게 완료한다.
- 반복 클릭·레이아웃 이동·정보 중복을 실제 흐름에서 제거한다.
- 첫 이용자의 이해도와 익숙한 이용자의 반복 부담을 각각 확인한다.

## 6. 소규모 테스트판 묶음과 조정

**목표:** 현재 소수 캐릭터와 원정으로, 개발자의 설명 없이 플레이할 수 있는 테스트판을 만든다.

작업:

- 새 저장과 기존 저장, 레벨 1과 상한 레벨, 주요 조합, 성공·패배·귀환·재시도를 확인한다.
- 플레이 중 멈춘 화면, 선택한 보상/경로, 첫 전투불능, 대표 기술의 실제 효과를 비교한다. 기존 저장/검증 기록을 재사용하고 분석 전용 UI를 늘리지 않는다.
- 기본 제공 예제 원정과 여러 시드의 원정을 구분한다. 정해진 예제 완주를 전체 게임성의 증거로 삼지 않는다.
- 자산·저장·브라우저 호환·부하를 검증하고 실행 방법과 저장 안내를 포함해 테스트판을 묶는다. 실제 배포 방식과 대상 플랫폼은 이때 정한다.
- 실제 플레이에서 발견한 문제 중 이해를 막는 오류, 준비 변경의 효과를 가리는 문제, 관전을 방해하는 문제부터 수정한다.

완료 기준:

- 혼자 시작해 한 원정을 마치거나 실패 후 다시 준비할 수 있다.
- 다른 구성으로 다시 할 이유와 캐릭터의 대표 장면을 플레이 결과로 확인한다.
- 자동 검사 결과, 사람의 플레이 결과, 미해결 항목을 각각 기록한다.

## 범위와 순서 조정

1번의 재현 수정과 비교를 적용했다. 다음 기능 개발은 2번이다. 2번의 빌드 효과를 검증한 뒤 3번의 상대를 정하고, 4번의 표현 기준을 5번 화면에 반영한다. 실제 플레이 피드백은 각 단계에 도착하는 대로 적용한다. 피드백이 없는 동안에도 재현 조사·기능 제작·호환 검사를 진행할 수 있지만, 재미가 입증됐다고 표시하지 않는다.

이번 주기에서 파티 인원·캐릭터 목록을 확대하거나 계정·결제·새 영구 육성을 동시에 만들지는 않는다. 유물/장비 같은 독립 성장 축은 기존 카드·특성·대표 운용으로 매판 다른 구성이 충분히 만들어지는지 확인한 후 결정한다.

## 참고한 원리

- [Slay the Spire 공식 소개](https://www.megacrit.com/press-kits/slay-the-spire/)는 고유한 캐릭터 카드, 덱 구성, 다양한 전투와 절차적 경로를 함께 제시한다. 우리 게임의 2~3번에는 캐릭터의 정체성과 원정마다 달라지는 구성을 연결하는 원리만 적용한다. 규모를 그대로 복사하지 않는다.
- [TFT 공식 역할 개편 설명](https://teamfighttactics.leagueoflegends.com/en-us/news/game-updates/roles-revamped-and-item-changes/)은 역할에 맞는 임무와 자원 획득 방식으로 다양한 행동을 설계한다. 우리 게임에는 공유 역할 기반 위에 캐릭터별 작동 조건을 두는 참고로 활용한다. TFT의 마나 수치나 경제 규칙을 옮기는 제안은 아니다.

위 순서와 제작 범위는 레퍼런스의 요구사항이 아닌, 현재 프로토타입의 증거와 기획 목표를 바탕으로 한 설계 판단이다. 이전 적용 기록은 [v6.0 로드맵](개발_로드맵_v6.0.md)과 [6단계 검증](작은_출시_후보_6단계_검증.md)을 따른다.
