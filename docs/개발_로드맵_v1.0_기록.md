# 캐릭터 중심 게임 개발 로드맵 v1.0

갱신일: 2026-10-06. [캐릭터와 원정 카드 설계](캐릭터와_원정_카드_설계.md)를 구현하기 위한 계획이다. 기존 영구 카드 수집 계획은 [v0.1 기록](개발_로드맵_v0.1_기록.md)으로 보존했다.

현재 기존 브라우저 게임에는 기본 행동·태세·실제 적 카드 AI·수동과 오토·직접 개입·분기 지도·보상 교체·진화·회복·복기·저장이 있다. 이후 범위를 줄인 [세린 캐릭터 원정](../prototype/character.html)에 기초 4종·보상 2종, 목적 이동·추격·엄호·반격·대표 검무, 6개 방과 보상·진화 초기화를 구현했다. 기존 저장은 별도 버전으로 유지한다. 상세한 적용 범위와 한계는 [구현 기록](캐릭터_검증_버전_구현.md)을 따른다. 두 번째 고유 캐릭터·새 보스 기믹·정식 아트와 판매는 다음 범위다.

다음 개발은 **캐릭터 한 명의 매력이 자동 전투에서도 보이고, 원정마다 전용 카드 운영이 달라지는 짧은 완성형**을 목표로 한다. 날짜와 전체 캐릭터 수보다 실제 플레이 가능한 결과와 완료 기준으로 진행한다.

관전 표현 단계로 기본 행동·실제 검무 타격·보호/회복·효과음과 세 구성의 비교 체험을 추가했다. [관전 연출 구현 기록](관전_연출_체험_구현.md)을 참고한다. 현재 Canvas 프로토타입의 실제 관전 재미를 확인한 뒤 같은 역할의 두 번째 캐릭터와 교체 편성으로 차이를 검증한다.

## 1. 카드 수명과 캐릭터 데이터를 먼저 바꾼다

| 작업 | 결과 | 완료 기준 |
|---|---|---|
| 캐릭터 정의 | 캐릭터 ID·역할 태그·기본 AI·태세·기초 카드·보상 풀 연결 | 같은 역할도 다른 캐릭터 정의와 행동을 사용할 수 있음 |
| 보유와 시작 덱 | 기초 카드 권한으로 출발 복사본 생성 | 별도 영구 카드 복사본 수집 없이 덱 장수·계열 상한 충족 |
| 원정 보상 | 편성 캐릭터의 보상 카드만 후보에 등장 | 유효 후보·상한·넘기기·대기 목록·빠른 교체 작동 |
| 원정 종료 | 보상 인스턴스·진화 정리 | 성공·실패·귀환 모두 다음 판에 남지 않음 |
| 정비 방 | 기존 확보·조각 기능을 카드 선택/회복으로 변경 | 새 규칙에 영구 카드 확보나 조각 지급이 없음 |
| 저장 전환 | 규칙 버전과 기존 저장 보존 | 같은 원정은 같은 규칙으로 재개·정산하며 새 원정만 새 규칙 사용 |

기존 네 역할은 임시 기본 캐릭터 네 명으로 연결해 파티를 유지한다. 현재 코드의 역할 인덱스에만 의존하는 카드 시전자·기본 행동·레벨·태세·보상·화면을 함께 분리한다. 이름만 캐릭터로 바꾸고 카드를 역할 공용으로 남기는 방식으로 완료 처리하지 않는다.

이 단계에서 캐릭터 판매 화면이나 실제 결제를 구현하지 않는다. 보유 상태는 기본 제공 캐릭터와 검증용 해금으로 시험하며, 획득·판매 방식은 별도 결정한다.

## 2. 검사 원형 한 명을 전투 장면까지 완성한다

이름·최종 외형이 확정되지 않은 검사 원형으로 기본 이동·공격·피격·전투불능·승리 동작을 연결한다. 비평 후 첫 제작은 기초 4종·보상 2종으로 줄여 추격과 엄호·반격의 차이를 확인한다. 검증 뒤 보상 6종으로 확대할 수 있다. 대표 연속 공격은 기초 카드에 포함해 출발부터 볼 수 있게 한다.

이동 카드의 목표·행동·목적 유지·종료·새 명령 대체를 처리한다. 카드 실행을 우선하는 동안 일반 AI가 이동을 즉시 되돌리지 않게 하고, 종료 후 기존 태세로 복귀한다. 시전자와 대상이 쓰러지거나 무효해지는 경우에도 원정과 오토가 계속 진행돼야 한다.

대표 스킬 한 종은 준비 자세·이동·타격·마무리·효과음이 연결된 전용 연출을 만든다. 나머지 카드는 기본 동작과 효과 변형을 공유한다. 판정의 타격 순간과 시각·음향 강조가 맞고, 전장과 다른 캐릭터를 읽을 수 있게 한다.

**완료 기준:** 기초 카드만으로 캐릭터다운 행동이 보이고, 추격 보상과 엄호 보상으로 실제 움직임·대상·효과가 달라진다. 오토도 각 운영을 이해하며, 기본 역할 AI로 모든 캐릭터를 똑같이 움직이게 하지 않는다.

## 3. 짧은 원정에서 보상과 개입의 가치를 검증한다

`전투·보상 → 회복/진화 선택 → 전투·보상 → 정비 → 보스 → 결과`

첫 전투부터 사용할 이유가 있는 보상 카드를 제공한다. 같은 출발 덱에서 다른 카드 선택으로 이후 전투가 달라지고, 기본·보상 카드와 진화를 다음 전투로 이어간다.

첫 보스 기믹은 큰 공격 예고와 공격 후 잠깐의 노출이다. 오토는 기본 규칙에 대응하고, 사람은 명령 보유와 공격 집중으로 더 좋은 결과를 만들 수 있도록 한다. 예고·타격·노출을 화면에서 읽을 수 있게 하고, 기믹 대응에 이동 좌표 입력을 요구하지 않는다.

**완료 기준:** 카드 선택이 승률뿐 아니라 관전 장면을 바꾸고, 회복·진화·공격 준비에 서로 다른 선택 이유가 있다. 원정 종료 때 초기화되지만 캐릭터의 기초 경험과 다음 시도의 목적이 남는다.

검사는 동일 시드·파티·레벨·출발 덱·경로로 여러 보상 운영과 수동/오토를 비교한다. 봇 비교로 인간의 판단 우위를 입증했다고 보고하지 않는다. 숙련자의 개입 이득과 캐릭터 매력은 실제 플레이로 별도 확인한다.

## 4. 같은 역할의 두 번째 캐릭터로 차이를 확인한다

첫 검사와 같은 근접 태그지만 동료 보호와 반격을 기본으로 삼는 두 번째 캐릭터를 만든다. 기본 AI·태세·기초 키트·보상 풀·대표 장면을 달리하고, 공용 전투 규칙은 유지한다.

첫 캐릭터를 두 번째로 교체했을 때 시작 덱·원정 보상·자동 행동·동료와의 조합이 달라져야 한다. 동일한 카드 이름과 피해 수치만 바꾼 재사용으로 완료하지 않는다.

**완료 기준:** 둘 다 편성할 이유가 있고, 같은 적을 상대해도 화면에서 캐릭터를 구별할 수 있다. 한 캐릭터의 높은 수치가 모든 조합을 대체하는지 확인한다.

## 5. 한 구역과 캐릭터 체험을 연결한다

짧은 원정에서 확인한 규칙을 기존 분기 지도와 여러 적·강적·보상·회복·진화·정비 방에 확장한다. 10개 방은 기존 검증값이며, 반복 시 초반이 지루해지거나 보상 변화가 느리면 길이·분포를 조정한다.

캐릭터 체험 전투에서는 기초 키트와 대표 연출을 보여준다. 원정 보상 카드를 미리 사용하는 체험이라면 체험 전용 제공임을 표시해 실제 시작 덱과 구분한다. 획득 후 같은 대표 기술을 곧바로 사용할 수 있어야 한다.

**완료 기준:** 여러 원정에서 같은 캐릭터의 다른 운영과 다른 동료 편성이 성립하고, 체험에서 본 핵심 매력이 실제 보유 후 플레이에도 이어진다.

## 6. 정식 제작과 획득 방식을 결정한다

캐릭터의 실제 매력을 확인한 다음 대상 플랫폼·엔진·아트·세계관·첫 출시 규모와 캐릭터 획득·판매 방식을 결정한다. 가격·확률·중복 구매 성장 등을 현재 설계에서 자동 확정하지 않는다.

첫 정식 콘텐츠는 확인된 캐릭터·구역·보스와 저장·오토·조작을 목표 기기에서 완성한다. 추가 캐릭터 제작은 이 기준을 재사용하고, 각 캐릭터의 행동·키트·보상 풀·연출이 하나의 경험으로 연결되는지 확인한다.

## 독립적으로 완성할 수 있는 결과물

사용자가 요청한 구분에 맞춰 중간 피드백 없이 끝까지 만들 수 있는 결과물을 적는다. 최종 취향 확인과 같은 결과물로 중복 분리하지 않는다.

- 새 규칙의 작동하는 브라우저 원정: 캐릭터 정의·기초 덱·원정 보상·진화·정산·저장 전환.
- 개발자 초안 캐릭터의 관전 체험: 기본 행동·태세·목적 이동·기초 카드·보상 운영·대표 연출을 연결한 플레이 가능한 캐릭터.
- 카드와 개입을 사용하는 짧은 기믹 원정: 적 패턴·보상·회복·진화·보스·결과까지 연결.
- 규칙·진행·저장 검증과 개발자 기준 난이도 조정: 실제 엔진과 브라우저로 진행하고 실패 이유를 기록.

## 사용자 의견이 필요한 결과물

- 사용자가 의도한 매력과 일치하는 캐릭터·세계관·최종 시각 스타일.
- 목표 이용자의 실제 선호를 반영한 관전 재미와 숙련자 개입 가치의 평가.
- 캐릭터 획득·판매 방식, 영구 성장의 최종 범위, 정식 출시의 플랫폼·제작 규모·비용 확정.

먼저 독립 제작 가능한 체험을 만들고, 완성된 장면과 플레이 결과로 의견을 받는다. 작은 카드 수치·AI 주기·방 배치 때문에 제작을 반복해서 중단하지 않는다.
