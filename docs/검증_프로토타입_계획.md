# 검증 프로토타입 계획 v0.1

작성일: 2026-10-05

2026-10-06 업데이트: 한 구역 출정과 영구 수집·저장까지 연결한 브라우저 버전을 만들었다. 현재 실제 구현 범위와 검사 결과는 [플레이 버전 구현 결과](플레이_버전_구현_결과.md)를 따른다. 아래 계획과 첫 피드백은 이전 단일 전투에서 이어진 검증 기록이다.

간단한 [브라우저 전투 프로토타입](../prototype/index.html)을 구현했다. 자동 정지·대기·카드 소비·전투불능 카드 제외와 브라우저 조작 검사를 통과했고, 첫 사용자 플레이 피드백을 받았다. 추가 재미 검증과 출정 구현은 이후 단계다. 기준 설계는 [게임 기본 구조](게임_기본_구조.md)와 [전투와 출정 베이스](전투_베이스_설계.md)를 따른다.

## 1. 무엇을 확인할 것인가

기록과 재현 가능한 시험으로 규칙이 맞게 작동하는지 확인한다. 사람이 직접 플레이하면서 내린 선택과 체감으로 재미를 판단한다. 승률이나 피해량 하나를 높였다는 이유만으로 재미가 검증됐다고 보지 않는다.

핵심 가설은 다음 세 가지다.

- 자동 전투를 지켜보며 태세와 카드로 개입하는 것이 의미 있다.
- 바로 카드를 사용하거나 명령을 대기로 유지하는 선택이 상황에 따라 달라진다.
- 전투 사이에 HP를 유지하고, 획득 카드·강화·회복 경로로 이번 출정의 전략을 바꾸는 것이 재미있다.

## 2. 먼저 한 전투를 조작할 수 있게 만든다

아군 4명, 적 3명, 공용 덱 20장과 손패 5장을 검증값으로 사용한다. 공격·방어·회복·범위 공격 카드와 태세 전환, 공용 명령 회복, 시간 정지, 대기를 넣는다. 적도 기본 행동과 독립적인 카드 명령을 사용한다.

임시 캐릭터나 도형을 사용하되 이동, 공격 방향, 피해·회복, 카드 준비와 적의 예고가 화면에서 읽히게 한다. 이 단계에서 판단의 재미와 규칙의 명확성을 먼저 확인한다. 최종 3D 액션의 연출과 감각은 실제 애니메이션을 연결한 뒤 별도로 확인한다.

전투를 다시 시작하고 같은 초기 조건으로 재현할 수 있게 만든다. 초안 수치와 적의 구성은 데이터로 바꾸며, 처음부터 많은 콘텐츠를 제작하지 않는다.

### 정상 동작을 먼저 확인

- 완충 시 모든 전투 시간이 멈추고 선택 중에는 피해와 예고가 진행되지 않는다.
- 카드 확정이 정확히 한 번 소비되고, 해당 카드의 회복 시간이 다음 명령 시점에 반영된다.
- 대기는 READY와 손패를 유지하고 무료 드로우나 명령 축적을 만들지 않는다.
- 한 장 교체는 횟수만 소비하고 카드 총수·READY·전투 시간을 유지한다. 대체 카드가 없으면 손패와 횟수가 그대로 남는다.
- 보호 태세는 기본 공격의 표적 선호에 반영된다. 도발은 실제 발동 이후에만 단일 공격을 유도하며, 만료·전투불능·범위 공격에는 강제 유도가 적용되지 않는다. 예고된 대상 표시와 실제 피격 대상이 일치한다.
- 실제 효과가 발동한 방어만 타격에 적용되며, 이미 발생한 피해는 되돌리지 않는다.
- 전투불능·빈 손패·접근 실패 상황에서도 전투 진행이 막히지 않는다.
- 덱의 순환과 개별 카드의 소유·강화 상태가 서로 일관된다.

규칙 오류가 남아 있는 설정으로 재미를 비교하지 않는다. 회복 시간 설정을 바꿀 때에도 카드 총 수행 시간과의 기존 제약을 충족해야 한다.

## 3. 같은 기능을 서로 다른 상황에서 시험한다

| 시험 상황 | 플레이에서 확인할 것 | 설계를 다시 볼 신호 |
|---|---|---|
| 일반 교전 | 태세를 바꾸거나 카드를 사용한 효과가 보이는가 | 상황과 관계없이 같은 입력만 반복 |
| 적의 강한 공격이 다가옴 | 바로 공격할지, 대기했다가 방어할지 판단하는가 | 대기가 항상 불필요하거나 항상 정답 |
| 부상 아군과 약해진 적이 함께 있음 | 회복·방어·적 마무리 중 무엇을 먼저 할지 고민하는가 | 손패를 보지 않고 한 종류만 선택 |
| 여러 적 또는 위험한 후방 적 | 범위 공격·단일 공격·태세 전환의 가치가 달라지는가 | 서로 다른 카드와 태세의 결과가 비슷함 |
| 약한 마지막 적이 남음 | 빨리 끝내는 선택과 회복을 위한 지연의 차이가 있는가 | 적을 살려두고 전원 회복하는 행동이 반복적으로 가장 유리함 |

예를 들어 명령이 준비된 상태에서 적의 타격이 3초 뒤로 예고된 장면을 준비한다. 지금 회복 시간이 5초인 공격을 사용하면 그 타격 전에 다음 카드 명령을 얻지 못한다. 대기 후 방어를 사용하면 실제 방어 준비 시간과 유지 조건이 맞을 때 막을 수 있게 한다. 단순히 카드를 선택했다는 이유로 즉시 보호하는 시험은 하지 않는다.

같은 장면에서 손패, HP, 적 구성도 바꾼다. 대기와 공격 중 한쪽이 모든 장면에서 유리해지도록 맞추지는 않는다.

## 4. 체감과 기록을 함께 비교한다

먼저 조작에 익숙해지는 전투를 진행한다. 이후 같은 초기 전장과 덱을 기준으로 명령 회복 시간이나 기본 행동·카드의 효과 비중 중 하나를 바꿔 비교한다. 여러 수치를 동시에 바꿔 원인을 알아보기 어렵게 만들지 않는다.

설정 A와 B의 플레이 순서도 바꿔본다. 두 번째 플레이에서 나아진 이유가 설정 때문인지, 전투에 익숙해졌기 때문인지 구분한다. 몇 번의 작은 시험은 문제와 선호를 찾는 근거이며, 통계적인 결론으로 과장하지 않는다.

### 기록할 항목

- 실제 전투가 진행된 시간과 명령 선택으로 멈춘 시간을 따로 기록한다. 선택 시간 제한은 만들지 않는다.
- 사용 카드, 시전자·대상, 확정 시각, 다음 READY 시각을 기록한다.
- 대기 시작·재개 시각과 수동 재개 또는 새 적 예고 같은 재개 이유를 기록한다.
- 기본 행동과 카드가 만든 피해·실제 회복·차단을 출처별로 기록한다.
- 전투 종료 HP·전투불능과 마지막 적이 남은 이후의 전투 시간을 기록한다.

한쪽 원인이 모든 결과를 설명한다고 단정하지 않는다. 피해량 비율은 설계의 정답 수치가 아니라, 사람이 느낀 개입의 영향과 비교할 자료로 사용한다.

전투가 끝난 후 중요한 선택 두세 개만 되짚는다. 무엇을 기대했는지, 예상한 일이 실제로 일어났는지, 왜 그 카드를 골랐는지 확인한다. 매 명령마다 이유를 설명하게 해서 자연스러운 플레이를 방해하지 않는다.

강한 공격만 사용하기, 태세를 바꾸지 않기, 적을 남겨 회복하기도 비교한다. 이런 단순 전략이 여러 상황에서 항상 유리하면 선택의 의미를 다시 본다. 한 가지 전략의 승률만으로 재미를 판정하지 않는다.

## 5. 전투가 괜찮으면 짧은 출정으로 연결한다

두 번째 검증은 전투 세 번과 하나의 갈림길을 묶은 짧은 출정이다. 본 설계의 10개 방 완주 구조를 만들기 전에 필요한 연결을 시험한다.

`첫 전투·보상 → 회복 또는 강화 경로 선택 → 두 번째 전투·보상 → 카드 확보 → 세 번째 전투 → 성공 또는 실패 정산`

첫 전투에서 얻은 카드를 장수 제한 안에서 교체해 두 번째 전투부터 사용한다. 경로에서 적용한 회복 또는 개별 카드 강화가 이후 전투에 반영되는지 확인한다.

- 첫 전투의 피해가 갈림길 선택에 영향을 주는가?
- 같은 시작 덱도 새 카드와 강화 선택에 따라 운용이 달라지는가?
- 새 카드를 넣기 위해 기존 한 장을 빼는 선택이 의미 있는가?
- 강화된 카드 한 장과 같은 기술의 기본 카드가 정확히 구분되는가?
- 세 번째 전투에서 실패하면 앞서 확보한 카드만 남고 강화는 초기화되는가?
- 성공하면 남은 새 카드는 기본 상태로 확보되고 강화는 초기화되는가?
- 저장 후 이어서 진행하거나 확보 화면을 다시 열어도 카드가 복제되지 않는가?

회복과 강화 양쪽 경로를 비교하고, 성공·실패·전투불능이 남은 승리의 상태도 각각 재현한다. 기능 시험만으로 경로 선택이 재미있다고 결론 내리지 않는다.

## 6. 결과에 따라 바꿀 내용

| 발견한 문제 | 먼저 바꿀 내용 |
|---|---|
| 규칙과 결과가 다름 | 시간 처리·상태·소유 데이터 오류 수정 |
| 결과를 이해하기 어려움 | 예고·대상·효과와 명령 회복 표시 개선 |
| 카드 개입이 너무 약하거나 바쁨 | 카드 효과·기본 행동 효과·명령 간격 조정 |
| 같은 선택이 반복적으로 유리함 | 카드 조건·적 조합·보상과 경로의 가치 조정 |
| 마지막 적을 남긴 회복이 항상 유리함 | 적의 압박과 회복 효율을 먼저 검증·조정 |

이 조정으로 해결되지 않아 기존 재미를 크게 바꾸는 새 규칙이 필요할 때 다시 인터뷰한다. 정상 동작, 선택의 차이, 결과의 명확성, 다시 플레이하고 싶은 체감을 확인한 뒤 전체 분기 지도와 실제 액션 연출로 범위를 넓힌다.

## 7. 첫 사용자 플레이 피드백

- 간단한 전투 자체가 꽤 재미있었다.
- 대기는 사용하지 않았다. 공격 카드 한 장을 더 쓰는 편이 효율적이었다고 평가했다.
- 지원가 회복의 역할이 중요할 것 같다고 평가했다.

한 전투의 피드백이며 전체 전투에서 공격 우선이 항상 최선이라고 확정하지 않는다. 대기를 반드시 사용하게 만들기보다, 상황별 공격·회복·방어 선택의 가치를 비교한다. 당시 방패병 태세는 자신이 받는 피해량만 바꿨으므로, 이 부분은 의도한 태세 AI의 검증 결과로 취급하지 않는다.

추가 제안에 따라 전투당 2회의 한 장 손패 교체를 실험한다. 손패가 막혔을 때 선택이 살아나는지, 남은 횟수를 지금 쓸지 아낄지 판단하는지 확인한다. 항상 특정 카드만 찾는 입력이 되는지도 관찰한다. 2회와 명령 비용 없음은 설계자 실험값이며 최종 확정 수치가 아니다.

검사가 먼저 표적이 되고 방패병에게 옮기기 어렵다는 추가 피드백에 따라, 보호 태세의 기본 어그로와 4초 도발 카드를 넣었다. 방패병이 공격을 유도해 아군을 지키는 체감이 생기는지, 도발과 회복·차단을 함께 선택하는 의미가 있는지 확인한다. 아군 보호 위치와 피해 대신 받기, 압박의 이동·밀치기는 아직 미구현이다.
