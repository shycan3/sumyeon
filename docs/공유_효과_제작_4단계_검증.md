# 4단계 — 공유 효과 기반 지원가 제작 경로

적용: `authoring4`. 이 문서는 4단계 당시의 격리 검증 기록이다. 이후 일반 원정 편입은 [5단계 기록](실전_콘텐츠_편입_5단계_검증.md)을 따른다. 일반 원정에 새 캐릭터를 편입하는 5단계에 앞서, 격리된 지원가 제작 체험을 만들었다.

## 구현 범위

`prototype/support-lab.html`에서 지원가 자리를 노아로 교체한다. 파티는 기존 4명을 유지하고, 역할 AI·회복 평가·특성·효과 실행·관전 연출·원정·저장·연습을 재사용한다. 새 AI나 패시브, 궁극기를 추가하지 않았다.

| 카드 | 획득 | 효과 | 특성 | 연출 |
|---|---|---|---|---|
| 작은 봉합 | 기초 | 단일 회복 28 / 다음 명령 4초 | 공명 | 가벼운 회복 |
| 아직 아프지 않도록 | 기초 | 보호막 24, 4초 지속 / 다음 명령 4.5초 | 호위 | 보호 강조 |
| 모두에게 닿는 기도 | 원정 보상 | 전체 회복 18, 준비 0.35초 / 다음 명령 7초 | 공명 | 초상화·대사 |

기초 키트의 전체 회복을 제거하고 기본 행동의 속도·피해를 낮추어 예방과 단일 회복에 집중하도록 했다. 이 수치는 제작 검증용 출발점이다. 기존 지원가와의 실전 대체 관계나 승률 균형을 입증한 상태는 아니다. 원정 종료 후 보상과 진화는 초기화된다.

## 제작 정의와 등록

- `content-support-template.json`: 캐릭터, 완전한 기초/보상 키트, 특성, 공유 효과 수치, 연출·로컬 SVG, 출발 덱 변환과 강점의 대가를 함께 정의한다.
- `content-authoring.js`: 브라우저와 Node 검사에서 같은 schemaVersion 2 검증·등록 함수를 사용한다. 사수의 공격/연속 공격과 지원가의 단일 회복/전체 회복/보호막을 지원한다. 기존 schemaVersion 1의 Node 제작 경로도 유지한다.
- 잘못된 ID·특성·효과·수치·새 AI 필드·외부 이미지·불완전한 출발 키트·사본 상한 초과는 등록 전에 거부한다. 알 수 없는 효과를 자동으로 지원하지 않는다.
- 노아 카드 3장에 각각 SVG 그림을 연결했고, 보상 대표 기술에는 임시 초상화와 대사를 연결했다. 최종 상업 아트가 아니다.

일반 페이지는 제작 등록 모듈을 읽지 않는다. 제작 체험의 저장 키는 `afterglow-authoring-support-v1`이며 일반 원정 저장과 분리된다. 일반 페이지는 노아가 포함된 제작 저장의 가져오기를 거부한다. 제작 체험에서는 공개 도전을 열지 않는다. 일반 원정 편입에는 콘텐츠 버전과 교체 UI를 별도로 설계해야 한다.

## 검증 결과

- 실제 기초 덱 20장과 시전자 연결, 원정 보상 획득·교체·다음 전투 사용을 확인했다.
- 단일 회복, 보호막 피해 흡수, 전체 회복을 실제 실행기로 확인했다. 전투불능 대상은 회복되지 않고, 준비 중 시전자가 쓰러지면 회복이 취소된다.
- 준비 중 저장 복원 후 동일한 전투 결과, 원정 종료 후 키트 초기화, 연습 전투의 노아 참여를 확인했다.
- 1280×720, 390×844, 320×568에서 보상 UI·그림·초상화·대사·저장 복원·연습·일반 페이지 복귀를 검사했다. 대표 기술 연출 전후 전장 크기가 동일하고 가로 넘침이 없었다.
- 기존 제작 v1, 일반 콘텐츠 검사, 성장 비용과 궁극기 판단 검사를 통과했다. 기존 96개 전투 호환 기준도 유지한다.

검사: `content-support-audit.cjs`, `content-support-check.cjs`, `content-support-browser-check.cjs`.

## 다음 단계와 한계

5단계에서 기존 지원가와 같은 공유 카드 조건 및 각자 전용 키트 조건을 구분해 비교한다. 예방이 유리한 상대와 동시 피해·지속 피해에 약한 경우를 확인한 후 일반 원정 편입을 결정한다. 신규 보상이 후보를 과도하게 희석하는지도 확인한다.

현재 제작 체험은 JSON 편집과 검사 스크립트를 사용하는 개발용 경로다. 시각적 제작 편집기, 임의 역할 추가, 고유 패시브·새 자원·궁극기 제작은 지원하지 않는다. 새 효과는 실행·평가·취소·저장 검증을 먼저 확장해야 한다. 낮은 레벨의 회복 경로 편향도 이번 작업으로 해결한 것은 아니다.
