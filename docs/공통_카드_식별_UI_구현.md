# 공통 카드 식별 UI 구현

2026-10-07 · `character.html?v=identityui1` · UI 로드맵 5단계.

## 공통 표시

`CardVisuals.identity`, `features`, `state`, `trait`를 추가했다. 보상 후보/교체 비교, 편성/대기/폐기, 손패/기술 설명, 결과 카드 요약과 발견 기록에서 같은 소유자 이름·소유자 기호·카드명·특성·기능을 사용한다. 기존 스킬 그림은 유지한다. 새 캐릭터 초상화를 생성한 업데이트는 아니다.

특성은 고정 색과 ◆ 호위 / ↗ 추격 / ✦ 공명의 기호·텍스트를 함께 표시한다. 기능은 공격·회복·보호·이동·지원의 텍스트로 구분한다. 기능과 특성은 서로 다른 정보이며 도발과 회복이 공통 특성을 가진다고 같은 기능으로 표현하지 않는다. 피해 차단이 없는 이동 카드 `긴급 재배치`와 회복 수치가 없는 `위험 구역 구출`은 이동으로 표시한다.

선택됨/비교 중/편성됨/대기/진화는 테두리 색뿐 아니라 상태 텍스트로 표시한다. 여러 사본이 한 묶음에 있을 때는 편성/대기 장수를 따로 표시하며 실제 사본 버튼에서 편성에 넣기/편성에서 빼기를 결정한다.

원정 편성의 일반/진화 카드를 별도 묶음으로 분리했다. 카드 효과 설명과 보호막/지속/명령 수치는 실제 해당 진화 상태로 표시한다. 보호 감소·공격 강화의 비율을 피해 수치로 잘못 표시하지 않도록 공통 수치 생성도 수정했다. 전투 손패 상세의 명령 시간은 전투 규칙을 반영한 definition을 사용한다. 덱 편성 화면은 기본 명령 시간과 원정 규칙 별도 안내를 유지한다.

## 화면 갱신

전역 MutationObserver로 모든 DOM 변화를 감시하던 방식을 제거했다. `setContent`에서 기존 팝업을 닫고 화면 HTML을 교체한 뒤 `WorkspaceUI.refresh`를 명시적으로 호출한다. 모달 원본/복귀 포커스, 편집 스크롤·포커스, 태세 재열기는 기존 명시적 상태로 관리한다. 전투의 프레임별 갱신은 이 과정을 호출하지 않는다.

화면 분류/배치와 일부 공통 행동 영역은 기존 selector 기반 어댑터를 유지했다. 전체 화면을 새 프레임워크로 다시 작성한 것은 아니다. 실험 도구와 정상 관전 분리는 3단계 구조를 유지한다. 저장/전투 판정/AI/카드 수치/보상 난수를 바꾸지 않았다.

## 검증

- `card-identity-check.cjs`: 현재 캐릭터의 모든 기초/보상 카드에 소유자/이름/특성/기능, 텍스트 상태/진화 표시, 이동 카드 분류, 비율 수치, 전역 DOM 감시 제거.
- `card-identity-browser-check.cjs`: PC/320px에서 일반·진화 분리와 실제 수치, 취소 비변경, 관전 정지 중 기술 조회, 선택된 보상과 비교 카드 식별 일치.
- `compare-ui-browser-check.cjs`: 6가지 화면, 고정 행동/최소 읽기 영역, 보상 비교 비변경, 편성/되돌리기, 편집 스크롤·포커스, 여러 태세 수정.
- `workspace-ui-browser-check.cjs`: PC/모바일 팝업/행동/재렌더/편성/저장 재개.
- `watch-ui-browser-check.cjs`와 `watch-frame-browser-check.cjs`: 6가지 화면, 관전·도구·도전 제한과 실제 1배/2배 고정 단계 동일성.
- `result-story-browser-check.cjs`: 변경 결과와 이전/이번 덱 연습, 원정 분리, 저장 재개/보고서.
- `character-browser-check.cjs`: 실제 원정 완주/보상 사용/저장 불러오기/복구.

색 없이 읽을 수 있는 기호·텍스트를 제공했지만 색각 이상 사용자 실험이나 전체 보조 기술 적합성 감사를 수행한 것은 아니다. 1~5단계의 구현 틀을 연결했으며 다음은 플레이를 통한 정보 이해도/탐색 비용의 점검이 우선이다. 신규 UI 기능을 계속 추가하기보다 검증된 문제를 줄인다.
