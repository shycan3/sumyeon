# 역할군·캐릭터·파티의 다층 AI 설계

작성·적용일: 2026-10-06. 역할군·캐릭터 정책과 공통 실행기를 세린 원정에 적용했다. 현재 구현 계약과 검증은 [다층 AI 구현](다층_AI_구현.md)에 기록했다.

적용 전 [다층 AI 비평](다층_AI_비평.md)에서 지적한 카드 전환·제어권·틱 순서·점수 합성·저장 정책을 보완했다. 이번 범위는 기존 4인 편성과 캐릭터 정책 분리이며 임의 파티 편성은 후속 작업이다.

## 1. 가능 여부와 현재 출발점

현재 실시간 전투 엔진에서 규칙과 점수 기반의 다층 AI를 구성할 수 있다. 외부 AI API나 캐릭터별 학습 모델은 필요하지 않다. 캐릭터마다 판단 정책을 달리하면서 같은 전투 실행 규칙을 사용한다.

현재 `engine.js`의 `basicTarget()`·`basics()`는 역할별 기본 행동, `auto()`·`recommend()`·`tacticalScore()`는 공용 카드 판단을 맡는다. `character-engine.js`가 세린의 표적·반격·엄호·추격 평가를 추가하므로 분리할 기반이 있다.

이전의 엄호 선행 이동과 속도 임시 변경은 제거했다. `actor-ai.js`의 정책은 읽기 전용 전장 정보를 받고 실행할 데이터를 반환한다. 엄호·추격 실행과 카드 대상 선택의 `a1` 예외도 제거했다. 캠페인의 파티 생성·HP·레벨·통계 배열은 이번 범위인 고정 4인을 유지한다.

## 2. 책임 분담

| 구성 | 담당 | 직접 하지 않는 일 |
|---|---|---|
| 전장 정보 | 동일 시점의 위치·HP·공개된 효과·예고·시전 상태 제공 | 행동 실행·숨은 적 손패 조회 |
| 역할군 정책 | 접근·거리 유지·보호·기본 회복 등 기본 행동 후보 생성 | 좌표·HP·명령 자원 변경 |
| 캐릭터 정책 | 표적 선호·고유 호위 조건·반격·연계 가치로 후보 조정·추가 | 독립적인 이동 실행·공용 명령 소비 |
| 태세 설정 | 정책의 거리·위협·대상 가중치와 허용 행동 조정 | 별도의 행동 실행·자동 태세 변경 |
| 캐릭터 행동 결정기 | 현재 목적·실행 조건·후보를 바탕으로 이동과 기본 행동 확정 | 피해 수치를 임의로 적용 |
| 파티 오토 | 현재 손패의 카드·대상·시점을 비교해 공용 명령 한 번 확정 | 기본 이동을 매 프레임 지휘 |
| 공통 실행기 | 유효성 재검사 후 이동·기본 행동·카드 효과·자원 소비 적용 | 캐릭터별 판단을 중복 실행 |

역할군과 캐릭터 정책은 서로 다른 실행 주체가 아니다. 역할군의 기본 후보를 캐릭터가 수정하고, 결정기가 최종 행동을 정한다. 역할 태그가 여러 개여도 이동을 지시하는 역할 AI를 여러 개 병렬 실행하지 않는다. 기본 이동 정책 하나와 재사용 가능한 행동 후보를 캐릭터 정의에 연결한다.

## 3. 후보와 제어 범위

후보는 ‘무엇을 하려는가’를 표현하는 작은 데이터다. 예시는 다음과 같다.

```js
{
  actorId: 'party-member-id',
  source: 'character',
  goal: 'protect-ally',
  move: { mode: 'follow-ally', targetId: 'ally-id', distance: 55 },
  basic: { mode: 'attack-near-ally', targetId: 'enemy-id' },
  score: 0.65,
  reason: '부상 동료 주변의 위협 견제'
}
```

이동과 기본 행동은 한 후보 안에서도 구별한다. 엄호 위치를 유지하면서 근처 적을 공격할 수 있고, 사수는 거리를 벌리며 사격할 수 있다. 도발에 따라 공격 표적이 바뀌더라도 엄호 목적지가 곧바로 적의 위치로 바뀌지는 않는다. 공격 가능 거리 등 실제 실행 조건은 그대로 확인한다.

카드 돌진·밀침·충돌 보정은 추가 AI가 아니라 실행 규칙이다. 실행기는 일반 이동의 목적 하나를 받아 카드 이동·강제 이동·전장 경계·충돌 보정을 정해진 순서로 처리한다. 위치 변경의 여러 원인을 통제된 경로로 모으며, 모든 상황에 좌표 변경 한 번만 허용하는 식의 제한을 두지는 않는다.

## 4. 우선권과 목적의 유지

단순히 ‘캐릭터 AI는 언제나 역할 AI보다 우선’으로 정하지 않는다. 기본 후보와 개성은 함께 평가하고, 실제 실행 조건과 이미 확정한 명령의 제어 범위를 별도로 적용한다.

| 상황 | 처리 |
|---|---|
| 전투불능·실제 행동 불가 | 실행 불가. 일반 정책으로 우회하지 않음 |
| 확정한 카드의 접근·시전·타격 | 해당 카드가 제어하는 이동·행동을 실행 조건까지 유지 |
| 카드 종료 후 엄호·추격 목적 | 표시된 대상·기간·종료 조건을 유지하며 일반 후보를 제한 |
| 일반 행동 | 역할 후보를 캐릭터·태세 기준으로 평가해 선택 |
| 표적 전투불능·부재·목적 만료 | 해당 목적을 종료하고 즉시 유효한 행동을 재판단 |

새 카드에는 기존 목적과의 관계를 정의한다.

- 목적과 양립하는 카드: 엄호 위치에서 공격·회복 등을 실행하며 목적 유지.
- 목적을 대체하는 이동 카드: 유효성을 먼저 검사하고 명령이 수락되면 새 실행에 제어권을 넘김. 확정된 새 카드가 실패했다고 이전 목적을 자동 복구하지 않음.
- 양립하지 않고 중단도 허용되지 않는 카드: 사용 불가 사유를 표시. 개별 AI가 임의로 강제 취소하지 않음.

수동과 오토는 같은 전환 규칙을 사용한다. 오토는 엄호를 끝내는 손익까지 계산할 수 있고, 사람은 표시된 결과를 보고 직접 선택한다. 시전 취소·소비 환불은 AI 판단이 아니라 해당 카드의 기존 실행 규칙을 따른다.

## 5. 판단의 안정성

역할군·캐릭터 정책은 한 판단 시점의 공통 전장 정보를 읽는다. 후보를 생성하는 도중 좌표나 목적을 바꾸지 않고, 대상 위협을 평가하다 다른 AI의 행동 결정을 다시 호출하는 순환도 피한다.

세린의 일반 표적 선택은 시뮬레이션 시간 0.2초 간격으로 갱신한다. 유효 표적을 0.6초 유지하고 점수 차이가 0.08 미만이면 기존 표적을 유지한다. 기존 동료·적의 역할 정책은 기존처럼 매 틱 평가한다. 이동·타격·효과 처리는 작은 시간 간격으로 계속 실행하고 표적 사망·목적 만료·도발·태세 변경은 판단 주기를 기다리지 않는다.

역할 후보는 0~1 점수를 사용하고, 세린의 호위 성향은 같은 척도의 동료 주변 거리 점수로 후보를 조정한다. 강제 표적·목적은 점수 경쟁 밖에서 적용한다. 현재 표적 유지 기준은 초기값이며 관전 피드백으로 조정할 수 있다.

동점은 고정된 캐릭터·대상 ID 순서로 처리하고, 판단은 실제 시계가 아니라 전투 시각을 사용한다. 무작위 판단을 도입하는 경우 기존 전투 난수와 저장 상태를 사용한다.

## 6. 파티 오토와 수동 명령

캐릭터의 기본 행동 정책과 카드 정책을 구분한다. 캐릭터 정책은 현재 손패의 자기 카드에 대해 유효 대상·회복·피해·보호·연계·목적 전환 비용을 평가해 제안한다.

파티 오토가 카드 후보들을 비교해 지금 사용·준비된 명령 보유·허용된 손패 교체를 고른다. 공용 명령은 이곳에서 기존 `command()` 경로로 한 번만 확정한다. 캐릭터들이 각각 카드를 쓰거나 명령을 예약해서 공용 회복시간을 중복 소비하지 않는다.

수동에서는 파티 오토의 카드 확정을 멈추고 플레이어가 선택한다. 역할·캐릭터의 기본 행동은 기존처럼 전투 시간에 따라 수행된다. 직접 개입으로 시간을 멈춘 동안에는 모든 시뮬레이션 판단·실행·목적 시간이 함께 정지한다. 추천 대상은 제안이며 플레이어의 선택을 덮어쓰지 않는다.

## 7. 데이터·상태·저장

캐릭터 정의에는 기본 역할 정책 ID, 고유 정책 ID, 태세별 설정, 카드 평가 정책을 연결한다. 기능을 수정할 때 모든 캐릭터의 별도 엔진을 고치지 않도록 행동과 규칙을 재사용한다.

현재 정책은 `characterId`, 행동 실행은 고유 `actorId`를 사용한다. 카드 추천·자기 대상 제한도 카드에 연결된 시전자를 사용한다. 고정 파티의 최초 카드 연결과 캠페인 HP·레벨·피해 집계·화면·저장 검증은 역할별 4인 구조를 유지한다. 임의 파티 편성은 이 시스템들까지 변경하는 별도 작업으로 남긴다.

이후 행동에 영향을 주는 상태만 저장한다.

- 현재 목표·대상·유지 시작과 만료·다음 판단 시각.
- 카드 실행과 접근·후속 타격·확정한 목적 및 그 출처.
- 태세 예약·기본 행동 회복시간·반격 등 효과 상태.
- AI 구조 버전과 기존 전투 난수.

함수·전장 정보 복사본·전체 후보 목록은 저장하지 않는다. 전투 `aiVersion: 2`가 없는 이전 저장은 새 판단 상태를 초기화하고 목적·접근·시전·사건·시간·난수는 보존한다. 변환 이후 일반 판단은 새 규칙을 따른다. 같은 버전 안에서는 저장 후 진행이 끊김 없이 진행한 결과와 일치한다.

## 8. 적용 순서와 검증

1. **기존 행동을 유지하며 경계 분리:** 역할 기본 판단을 후보 생성으로 옮기고, 이동·기본 행동의 공통 실행 경로를 만든다. 명령·피해·카드 수치는 유지한다.
2. **세린 정책과 카드 목적 연결:** 속도 임시 변경과 고정 슬롯 예외를 제거하고, 엄호·추격·태세를 공통 목적과 정책으로 처리한다.
3. **파티 카드 판단 분리:** 현재 추천·점수·오토를 카드 후보 평가와 파티 확정으로 정리한다. 수동은 동일 유효성·실행 경로를 사용한다.
4. **같은 역할의 두 번째 캐릭터 검사:** 테스트용으로 같은 근접 정책을 쓰는 다른 캐릭터를 편성해 위치·표적·카드 소유가 섞이지 않고 개성만 달라지는지 확인한다. 새 캐릭터의 상용 콘텐츠 제작은 이 구조 검증과 별개다.

판단 구조만 분리하는 첫 단계는 같은 시드의 기존 진행을 비교한다. 판단 간격·표적 유지처럼 실제 행동을 바꾸는 단계는 결과가 달라질 수 있으므로 승률뿐 아니라 이동·표적 전환·보호 유지·카드 사용을 평가한다. 새 구조의 저장 후 진행은 저장하지 않고 계속한 경우와 동일해야 한다.

충돌 검사의 필수 상황은 엄호 중 새 이동 카드, 엄호 중 일반 공격, 도발과 추격 동시 적용, 목표 사망, 시전자 전투불능, 태세 예약, 오토 직접 개입·수동 전환, 목적 유지 중 저장 후 복귀다. 디버그 기록에는 선택한 이동과 기본 행동의 출처·대상·이유·목적 우선권을 남겨 충돌 원인을 확인한다.

첫 적용 범위는 세린과 기존 동료의 판단 구조 정리다. 카드 종류·캐릭터 수·전투 성장 규칙을 동시에 늘리지 않는다. 기능이 동작한다는 것과 캐릭터의 매력을 살리는 좋은 판단이라는 것은 실제 관전에서 별도로 평가한다.
