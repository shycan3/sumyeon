# 밸런스 패치 전후 자동 관찰 방법

수정 전 기록을 보존한 채 같은 원정 시작 조건을 수정 후에도 실행하고 비교한다. 원정 결과가 어떻게 달라졌는지 조사하는 도구이며, 카드나 적 수치 하나의 인과 효과를 증명하는 실험은 아니다.

현재 CLI의 `current`는 적 능력치 상향 버전 2, `previous`는 1차 패치 버전 1, `legacy`는 최초 버전 0이다. 아래 1차 패치 재현 명령은 `previous`를 사용한다. 출력 폴더가 이미 있으면 새 이름을 지정해야 한다. [능력치 상향과 비교 결과](적_능력치_상향_2026-10-10.md)를 별도로 보존한다.

조우 콘텐츠는 별도의 `--content current|previous`로 선택한다. 현재 콘텐츠는 신규 지원 적·분산 타격·세 보스가 있는 `voyage-2`, 이전 콘텐츠는 `voyage-1`이다. 과거 능력치 상향 규칙 2를 기존 지도 그대로 재현할 때는 `--balance current --content previous`를 함께 명시한다. 아래 규칙 0·1 명령은 콘텐츠를 생략하면 기존 `voyage-1`을 선택한다. 밸런스와 콘텐츠의 `current`는 서로 다른 옵션이므로 기록에서 두 버전을 함께 확인한다.

## 1차 패치 표본

- 시드 31~32, 6개 역할 중 4명인 순서가 고정된 15개 편성, balanced/aggressive/cautious 3개 정책: 버전당 90원정.
- 일반 난이도, 브레이크 끔, 최대 1,500단계·60턴.
- `prototype/study-results/balance-patch-1-before`는 패치 전 전체 모듈을 읽은 프로세스가 수집했다. 수정 이후 저장된 소스로 이전 버전을 역추정한 기록이 아니다.
- `prototype/study-results/balance-patch-1-after`는 패치 소스를 별도 프로세스로 읽어 수집한다.

수정 전 표본은 89승·1패, 630전투 중 629승·1패였다. 중단·오류·HP 검산 불일치는 없었고, 시드 32의 balanced / 항해사·도선사·측심사·인양사 보스 패배를 다시 재현했다.

수정 후에는 85승·5패, 630전투 중 625승·5패였다. 두 버전 모두 중단·오류·HP 검산 불일치 0이며, 90개 원정 시작 조건의 짝을 모두 찾았다. 밸런스 버전은 기록이 없는 기존 0에서 `voyage-balance-1`로 바뀌었다.

| 관찰 | 수정 전 | 수정 후 |
|---|---:|---:|
| 정예 쌍둥이 전투 | 26 | 30 |
| 쌍둥이의 광역 예고를 본 전투 | 5 | 25 |
| 쌍둥이의 실제 광역 적용을 관찰한 전투 | 4 | 9 |
| 쌍둥이 평균 HP 피해 | 5.12 | 4.20 |
| 쌍둥이 평균 턴 | 3.42 | 3.40 |
| 쌍둥이 패배 | 0 | 0 |
| 파수꾼·관측자 보스 패배 | 1 / 45 | 5 / 45 |

패치 후 새 패배 4회는 모두 파수꾼·관측자 보스에서 발생했다. 새로 패배한 원정은 모두 보스 진입 덱이 달라졌으며, 정예 쌍둥이가 강해져서 패배했다고 말할 수는 없다. 전체 원정에서 경로가 같은 짝은 66/90, 성장 선택과 최종 덱이 같은 짝은 각각 4/90이었다. 같은 쌍둥이 노드·적 패턴 전투 22쌍 중 공개 진입 상태가 완전히 같은 짝은 없었다.

따라서 지금 확인한 변화는 쌍둥이 예고가 훨씬 자주 노출되었다는 점이다. 전체 난이도와 보스 패배 증가는 덱·원정 성장 분기와 오토 판단을 함께 조사해야 한다. [전후 비교 보고서](../prototype/study-results/balance-patch-1-comparison/report.md)에서 구역별 표본과 제한을 확인할 수 있다.

## 실행

```powershell
node prototype/party-expedition-study.cjs --start 31 --seeds 2 --all-parties --policies all --balance previous --out prototype/study-results/balance-patch-1-after
node prototype/party-expedition-balance-compare.cjs --before prototype/study-results/balance-patch-1-before --after prototype/study-results/balance-patch-1-after --out prototype/study-results/balance-patch-1-comparison
node prototype/party-expedition-balance-compare.cjs --self-test
```

`--before`와 `--after`는 여러 폴더 또는 `runs.jsonl` 입력을 받아 같은 쪽의 여러 배치를 합칠 수 있다. 결과 폴더에 기존 비교 파일이 있으면 덮어쓰기를 거부한다.

새 시드 51~52로 분리한 후속 검증은 다음 명령으로 실행한다. 두 배치는 같은 수정 후 코드를 읽고 `--balance`만 달리하여 기존 규칙과 1차 패치 규칙을 비교한다. 역사적 수정 전 배치와 달리, 이전 코드를 별도로 실행한 결과라고 설명하지 않는다. `legacy`는 기존 규칙 버전 0, `previous`는 `voyage-balance-1`이며 같은 코드에서 실행한 양쪽의 소스 해시는 같다.

```powershell
node prototype/party-expedition-study.cjs --start 51 --seeds 2 --all-parties --policies all --balance legacy --out prototype/study-results/balance-patch-1-holdout-before
node prototype/party-expedition-study.cjs --start 51 --seeds 2 --all-parties --policies all --balance previous --out prototype/study-results/balance-patch-1-holdout-after
node prototype/party-expedition-balance-compare.cjs --before prototype/study-results/balance-patch-1-holdout-before --after prototype/study-results/balance-patch-1-holdout-after --out prototype/study-results/balance-patch-1-holdout-comparison
```

후속 검증은 이전 90원정과 구분해 기록하고 원래 684회 관찰 표본에 합산하지 않는다. 새 시드에서도 같은 신호가 반복되는지 조사하는 검증이며, 2개 시드만으로 전체 난이도를 확정하지 않는다.

## 짝과 표본

시드, 순서가 있는 편성, 정책 이름, 난이도, 브레이크, 단계·턴 상한이 모두 같은 기록끼리 짝지어진다. 소스 SHA-256, 콘텐츠 버전, 밸런스 버전은 패치에 의해 달라질 수 있으므로 매칭 조건에 넣지 않고 각 입력의 원래 값과 변경 파일을 출력한다. 이전 기록에 밸런스 버전이 없으면 0으로 표시한다.

같은 쪽에 같은 조건·소스로 같은 결과가 중복되면 한 번만 집계한다. 같은 쪽에 서로 다른 소스 버전이나 다른 결과가 섞이면 임의 선택하지 않고 오류를 내므로 버전별 입력을 나누어야 한다. 실패 재생처럼 `excludeFromCoverageTotals` 또는 `paired-failure-diagnostic`으로 표시된 기록은 전체 원정 표본에서 제외한다.

승리·패배·중단·오류는 따로 집계한다. 중단·오류를 포함한 짝과 완료된 전후 원정 짝도 따로 표시한다. 평균은 각 버전에서 완료된 전투만 포함한다.

## 기록과 검산

- 실제 HP 피해·회복·자기 소모는 행동의 실제 이벤트를 다시 합산한다. 전투 진입 HP + 회복 − 피해 − 자기 소모가 전투 종료 HP와 일치하고 저장 지표도 일치하는지 확인한다.
- 전투불능은 실제 `downed` 이벤트를 센다. 보호 흡수량, 도구 사용량, 턴수는 원래 전투 기록에서 가져온다.
- 구역·노드·적 패턴이 같은 전투끼리 짝을 찾고, 공개 진입 상태가 같았는지 따로 확인한다. 공개 상태가 같아도 기록에 없는 난수 내부 상태와 뽑기 순서까지 동일하다고 주장하지 않는다.
- 광역 예고, 준비 실행, 실제 광역 피해 적용을 구분한다. 보호가 전부 흡수한 공격도 실제 피해 이벤트가 있으면 적용으로 센다. 피해 이벤트가 없으면 예고를 실행으로 추정하지 않는다.

`comparison.json`에는 원래 소스 해시, 버전별 전체 표본, 구역·적 패턴별 표본, 원정 짝과 경로, 전투 짝과 진입 상태·실제 피해가 들어 있다. `pairs.csv`는 원정 단위 전후 요약이다. `report.md`는 읽기 쉬운 표와 해석 제한이다.

## 1차 패치에서 주의할 해석

정예 쌍둥이의 준비와 광역 행동을 한 턴 앞당기는 변화와, 브레이크를 끈 원정에서 브레이크 전용 카드를 보상·상점·이벤트 후보에서 제외하는 변화가 함께 들어간다. 적 HP와 피해 수치, 전투 오토 판단은 바꾸지 않는다.

후보 카드가 달라지면 보상 선택뿐 아니라 이후 덱, 경로 선택, 난수 소비, 보스 진입 체력이 달라질 수 있다. 전후 승패와 피해 차이는 패치 전체의 관찰 결과다. 그것을 정예 행동 시점 하나의 효과나 특정 카드의 성능으로 직접 돌릴 수는 없다. 먼저 경로·성장 선택·덱의 일치 비율과 구역별 도달 표본을 함께 읽는다.

자동 정책이 승리하는 비율과 사람이 흥미로운 결정을 발견하는 비율은 다르다. 이 비교를 근거로 바꿀 지점을 좁힌 뒤 P0~P6의 직접 플레이 관찰로 재미를 확인한다.
