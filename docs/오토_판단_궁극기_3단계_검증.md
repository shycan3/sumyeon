# 오토 판단과 궁극기 이해 — autoclarity3

적용일: 2026-10-08. 로드맵 v6의 3단계 구현·검사 기록이다.

## 수정과 표시

궁극기의 기존 위기 지원 검사는 아군 HP가 25% 이하이고 **손패 어딘가에** 유효 지원 후보가 있으면 궁극기를 막았다. 그러나 카드 오토가 실제로 선택하는 것은 다른 최상위 공격 카드일 수 있었다. 또한 궁극기가 예고 시전자를 처치하는 3순위 대응이어도 이 검사를 통과하지 못했다.

새 일반 원정의 공격/보호 방침에서는 다음과 같이 수정했다.

- 실제 최상위 카드가 유효 지원일 때만 그 지원을 우선한다. 선택되지 않을 지원 후보 하나가 더 강한 궁극기를 막지 않는다.
- 궁극기의 대응 순위가 지원 카드보다 높으면 비교를 계속한다. 같은 순위의 위기 지원은 계속 우선한다.
- 기존 10% 가치 우세 기준, 명령·시전자 조건, 발동 간격, 카드 두 번 조건, 전투당 두 번 제한은 유지한다. 준비 즉시 강제 발동하지 않는다.
- 판단과 이유 관측이 같은 순수 함수의 비교 결과를 사용한다. 손패 밖의 다음 카드와 미래 난수를 확인하지 않는다. 카드·기본 행동 AI 전체나 적 AI를 변경하지 않는다.

버전은 `autoUltimateVersion: 1`이다. 새 일반 원정과 전략 체험에 적용하며 진행 중 원정과 기록된 연습은 기존 버전을 유지한다. 이전 `balanced` 방침은 기존 궁극기 운용을 유지한다. 공개 도전의 규칙도 그대로다.

관전 화면의 기존 높이 22px 게이지를 재사용한다. `준비·명령`, `준비·기술`, `준비·카드`, `발동 가능`, `궁극 실행` 등의 짧은 상태를 표시하며, 준비 완료와 현재 발동 조건을 구분한다. 자세한 이유는 접근성 설명·툴팁과 접힌 전황 상세에 표시한다. 게이지·전장 높이를 늘리지 않았다.

이후 생성하는 일반 궁극기 전투에는 보유 관측을 자동 기록한다. 구형 원정의 다음 전투에도 관측만 추가하며 판단 버전은 바꾸지 않는다. 결과 화면의 상세 로그에서 명령 회복·시전자 잠금·카드 횟수·발동 간격·위기 지원·적 차단·현재 카드 우세를 확인한다. 이미 저장된 과거 교전에 관측을 소급 생성하지 않는다.

## 검사와 비교

`auto-clarity-check.cjs`:

- 선택되지 않을 후순위 지원 때문에 궁극기가 막히는 조건과 높은 순위의 예고 처치 궁극기를 막는 조건을 격리하여 재현했다. 수정 후 궁극기를 수락한다.
- 같은 순위의 실제 위기 지원은 유지한다. 공유 명령·게이지를 한 번만 소비하고 손패는 소비하지 않는다.
- UI·판단 조회가 전투 상태와 난수를 바꾸지 않는다. 준비/발동 조건/실행 상태를 구분한다.
- 실행 중 저장 복원과 종료까지의 정확한 이어가기, 새/구형 원정 버전, 잘못된 버전·저장 거부를 확인했다.

`auto-clarity-study.cjs`와 `auto-clarity-results.json`:

- 교차사격 돌파와 집중 추격, 레벨 1 만전 출발, 두 사수, 세 출발 덱, 공격/보호, 시드 7/37, 수정 전후로 **96전** 비교했다.
- 양 버전 모두 48전 중 33승, 실제 궁극기 발동 22회였다. 해당 표본에서 수정 전후 행동 차이는 없었다. 이번 오류 조건이 이 표본에서 승패를 뒤집었다고 주장하지 않는다.
- 자동 선택 순간에 실제 최우선 궁극기로 결정했지만 수락하지 않은 횟수는 양쪽 모두 0이었다. 이것은 내부 선택의 실행 신뢰성 검사이며, 모든 전략적으로 좋은 기회를 인식한다는 증거는 아니다.
- 발동까지 준비 상태로 보유한 최장 시간은 11.30초였다. 주된 관측 이유는 공유 명령 회복이었다. 기다림 자체를 오류로 처리하지 않았다.
- 같은 덱·적·시드의 공격/보호 24쌍 중 23쌍에서 카드 사용 또는 궁극기 흐름이 달랐다. 공격 17/24승·궁극기 12회, 보호 16/24승·궁극기 10회였다. 특정 방침의 보편적 우세로 해석하지 않는다.
- 2단계의 레벨 3 성장 회귀 두 사례를 같은 경로·보상 규칙으로 양 버전에서 원정 재실행했다. 호위·시드 63·보호와 공명·시드 7·공격은 모두 여전히 실패했다.
- 호위 사례의 실제 보스 진입 HP·최종 덱을 고정하고 진화 여부만 제거하니 일반 사본 구성은 승리(팀 HP 36.37), 진화 구성은 패배했다. 카드 사용은 단일 `회복`과 진화된 `치유의 파동` 선택에서 달랐다. 즉 이 사례를 궁극기 운용 오류로 설명할 수 없다.
- 공명 사례는 같은 보스 시작 조건에서 일반/진화 사본 모두 패배했고 카드 사용도 같았다. 앞선 전투의 소모·덱 교체를 함께 확인해야 한다.

`auto-clarity-browser-check.cjs`, `ultimate-browser-check.cjs`:

- 1280×720, 390×844, 320×568에서 상태·접근성 설명, 준비/실행 중 동일한 전장 크기, 관전 정지·저장·재개, 결과 관측, 컷인·연습, 가로 넘침·스크립트 오류를 검사하고 화면 이미지를 확인했다.
- 모바일에서 긴 준비 설명이 잘리는 문제를 확인한 뒤 짧은 상태 문구로 줄였다. 상세 이유는 그대로 제공한다.

기존 `identity-compat-check.cjs` 96전 전체 추적, 1단계 관측 검사, 2단계 진화·회복 저장 검사와 콘텐츠 정의 검사도 통과했다. 기준 추적을 다시 생성하지 않았다.

## 남은 판단

궁극기를 무조건 빨리 쓰게 하거나 오토를 최적 플레이로 강화한 업데이트가 아니다. 잘못된 지원 거부 조건을 고치고 현재 판단을 읽게 만드는 범위다. 기존 보호·추격·거리 유지·회복 연출과 움직임을 재사용하며 새 애니메이션은 추가하지 않았다.

진화한 전체 회복이 단일 위기 회복을 밀어내는 사례와 낮은 레벨의 회복 경로 편향은 남아 있다. 이를 숨기고 3단계가 전체 균형을 완성했다고 판정하지 않는다. 위기 기준·회복 효과/명령 시간·덱 교체를 다음 균형 검토에서 따로 비교해야 한다.

다음 기능 묶음은 4단계의 필요한 공유 효과 제작 경로 확대다. 1~3 이후의 플레이 점검도 병행하여, 사용자가 준비/보유 이유와 자신의 덱이 만드는 전투 흐름을 이해하는지 확인한다. 자동 검사로 관전 재미와 캐릭터 애착을 증명하지 않는다.
