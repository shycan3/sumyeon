# 전체 원정 자동화와 전투 관찰

사용자의 요청: 노드·보상까지 자동으로 고르는 원정을 반복하고, 이긴 전투와 패배한 전투의 피해·카드 사용을 비교한다. 일반 플레이의 저장과 분리된 개발용 연구실로 구현했다. P0~P6의 재미 판단은 사람의 실제 경험으로 유지한다.

## 실행

브라우저: `http://127.0.0.1:8765/party-expedition-lab.html`. 게임 도움말의 ‘자동 원정 연구실’ 링크로 이동할 수도 있다. 시작 시드·시드 개수·편성·정책·난이도·브레이크를 정하고 실행한다. 일시정지·재개·중단을 제공한다. 완료한 원정과 중단한 진행의 JSON, 전투별 CSV를 내려받을 수 있다. 일반 게임 저장을 읽거나 덮어쓰지 않는다. 탭을 새로고침하면 메모리의 연구 기록은 사라지므로 필요한 기록은 먼저 내려받는다.

터미널에서 20개 시드 × 표준 3편성 × 3정책을 실행하는 예:

```powershell
node prototype/party-expedition-study.cjs --seeds 20 --policies all --out prototype/study-results/initial-180
```

모든 15편성을 비교하는 예(10 × 15 × 3 = 450회):

```powershell
node prototype/party-expedition-study.cjs --start 101 --seeds 10 --all-parties --policies all --out prototype/study-results/all-parties
```

한 배치는 최대 500회, 원정당 기본 1,500결정·전투당 60라운드까지 실행한다. 상한과 사용자 중단은 패배가 아닌 `aborted`, 실행 오류는 `error`로 남긴다. CLI는 완료 원정을 `runs.jsonl`에 즉시 기록한다. Ctrl+C도 현재 원정을 중단 기록으로 남기고 요약을 작성한다.

CLI에서 `--out`을 생략하면 실행 시각을 붙인 새 하위 폴더를 만든다. 이미 실험 파일이 있는 출력 폴더는 덮어쓰지 않는다. 다른 출력 폴더를 지정하면 이전 로그와 나란히 보존할 수 있다. 옵션 오타도 실행 전에 거부한다.

## 자동 선택의 범위

시작 유물, 연결된 노드, 카드 보상과 건너뛰기, 정예 유물, 회복·강화·제거, 상점 카드·유물·도구·각인, 사건의 교환·복제·선택, 중간 계약과 거절, 전투의 카드·실행자·대상·선택형 효과·도구·손패 버리기·라운드 종료까지 게임의 실제 Run API를 호출한다. 적 수치와 보상을 실험을 위해 조작하지 않는다.

균형·공세·신중 정책은 경로 위험, 카드·유물 평가, 회복·도구 사용 문턱을 달리한다. 기본 전투 평가기는 기존 제품 오토를 공유한다. 세 개의 독립된 숙련 플레이어나 공격·수비·제어 빌드의 검증으로 취급하지 않는다. 카드 평가는 비용 대비 효과, 공개 덱과의 연계, 중복과 덱 크기를 사용하는 초기 휴리스틱이다. 현재 공개 손패와 적 의도, 공개된 지도·상점·보상 후보만 판단에 사용하며 미래 추첨 결과와 뽑을 카드 순서는 보지 않는다.

## 무엇을 기록하는가

- 원정: 시작 시드·편성·정책 버전·규칙, 모든 선택과 이유, 제시 후보, 재화·HP 변화, 최종 상태·덱·유물.
- 새 기록의 비전투 선택: 실제로 추가·제거·수정된 카드 사본 ID와 전후 값, 유물·도구 변화. 지도 후보에는 공개된 적 수치와 경유지·사건도 보존한다. 초기 210회와 coverage-450은 이 추가 필드 이전 기록이므로 사본별 획득 추적을 소급하지 않는다.
- 전투 진입: 구역·노드·조우·일반/정예/보스, 적의 실제 체력과 공격 수치, 아군 HP, 덱의 사본·강화·각인, 유물·도구·시작 에너지 제약.
- 행동: 카드 종류·사본·강화·각인·지불 에너지·선택형 효과·실행자·대상, 행동 전후 공개 손패·의도·HP·보호, 실제 엔진 이벤트.
- 결과: 승리/패배/중단/오류, 소요 라운드, 적이 깎은 실제 HP, 보호로 흡수한 피해, 자해 비용, 실제 회복, 생성한 보호, 카드 사용, 도구 소비, 동료 사망.
- 원인별 피해: 적 개체별·피격 동료별 피해를 보존한다. 두 감시자의 피해는 한 조우의 결과로 합산하되 각 공격자도 조회할 수 있다.

`damage.amount`는 HP를 실제로 깎은 양이다. 적이 HP 12인 동료에게 명목 피해 80을 가하더라도 80의 HP 손실로 부풀리지 않는다. `absorbed`는 실제 보호 흡수다. 약화·처치로 취소된 공격까지 모두 합한 잠재 피해는 이 둘의 합과 다르다.

전투 종료의 실제 Battle HP와 전투 후 Run HP를 둘 다 보존한다. 귀항 등불·정비 회복이 적에게 받은 피해를 숨기지 않는다. 현재 고정 최대 HP 규칙에서 ‘진입 HP + 전투 회복 − 적 HP 피해 − 자해 = 종료 HP’를 매 전투 확인한다. 예측용 preview 이벤트와 종료 전투가 남긴 오래된 이벤트는 기록하지 않는다.

카드별 피해·회복·생성 보호는 그 행동에서 실행자와 유물이 함께 만든 즉시 효과다. 방어 카드가 생성한 보호와 나중에 실제로 흡수한 피해를 동일하게 취급하지 않는다. 지속·노출·예약의 후속 효과는 과거 카드로 임의 소급하지 않고 원본 이벤트로 남긴다. `roundStats`의 라운드는 결정을 내린 라운드이며, endRound에 이어지는 다음 라운드 시작 효과도 그 결정에 포함된다. `energyGained`는 명시적 효과 이벤트의 획득량이고 기본 라운드 회복 2까지 합친 수치는 아니다.

## 보고서 읽기

`manifest.json`은 설정·정책 설명·수집 코드와 게임 소스의 SHA-256을 기록한다. `runs.jsonl`은 원정당 한 줄의 전체 로그, `battles.csv`는 전투별 요약, `summary.json`과 `report.md`는 비교 보고서다. 기록한 선택 명령은 같은 시드의 새 Run에 재생할 수 있다.

여러 배치의 후보 제시→채택→보유→손패 도달→사용과 적 의도 공개→실제 적용을 비교하려면 [추가 분석 방법](자동_원정_추가_분석_방법.md)을 따른다. 신규 후보 순번 대조 정책은 `node prototype/party-expedition-baseline-study.cjs --out prototype/study-results/새_대조_실험`으로 실행한다. 제품의 세 정책과 같은 전투 오토를 쓰되 시작 유물·경로·보상·정비를 단순한 후보 순번으로 선택하는 원정 운영 대조군이다. 더 높은 난이도나 강제 저체력 시작을 만들지 않는다.

조우 종류뿐 아니라 구역·편성·정책·난이도·브레이크가 같은 전투끼리 묶는다. 승리와 패배의 평균을 각각 제공한다. 완료 평균에서 중단·오류를 제외하고 해당 횟수는 별도 표시한다. 표본 수와 구역 도달 원정 수도 보여 후반 전투의 생존자 편향을 확인한다.

자동 경고는 완료 표본 5개 이상에서 패배 비중 20% 이상, 평균 2턴 이하·HP 피해 2 이하의 전승, 평균에 비해 큰 상위 10% 피해 등을 찾아 후속 관찰을 제안한다. 이 문턱은 조사 우선순위용 초기 가설이고 목표 밸런스 수치가 아니다. 경고가 없다고 균형이 검증된 것이 아니다.

카드 사용과 승리는 연관이지 인과가 아니다. 좋은 덱에서만 선택되는 카드, 죽기 직전에 사용한 방어, 뽑히지 않은 카드, 정책이 저평가한 카드의 사용률을 수치 변경의 직접 근거로 삼지 않는다. 같은 시드를 쓰더라도 다른 경로와 선택으로 난수 소비가 달라져 후반의 조우·보상·손패까지 완전히 같은 대조군은 아니다.

## 검증

`node prototype/party-expedition-simulation-check.cjs`는 실제 피해/흡수/반격/자해/회복/전투 후 회복 분리, 오버킬, 다중 적 조우, 오래된 이벤트 중복 방지, 승패별 통계, 실행 상한과 오류 구분, 공개 정보만 보는 결정, 동일 시드와 저장 복원·선택 재생, CSV, 실제 전체 원정 흐름을 검사한다. 적 체력·공격력·보상과 일반 게임 저장 형식은 이 작업에서 바꾸지 않았다.
