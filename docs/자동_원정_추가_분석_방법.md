# 자동 원정 추가 분석 방법

기존 `runs.jsonl`을 다시 플레이하지 않고 읽어, 여러 실험의 관찰 결과를 합산하는 도구다. 원본 로그와 엔진 수치는 변경하지 않는다.

## 실행

```powershell
node prototype/party-expedition-study-analysis.cjs --self-test

node prototype/party-expedition-study-analysis.cjs --input prototype/study-results/initial-180 --input prototype/study-results/all-parties-30 --out prototype/study-results/combined-analysis
```

`--input`은 여러 번 지정할 수 있으며 실험 폴더 또는 `runs.jsonl` 파일을 받는다. 같은 폴더의 `manifest.json`이 있으면 소스 해시와 정책 버전을 읽는다. 결과는 `analysis.json`과 `analysis.md`다. 큰 로그는 `readline`으로 한 원정씩 읽는다. 전체 원본 로그를 메모리 배열에 넣지 않는다.

## 확인할 내용

- 승리·패배·중단·오류를 구분한다. 완료 전투의 평균에 중단·오류 전투를 섞지 않는다.
- 전투 시작/종료 HP와 실제 피해·회복 이벤트를 다시 검산한다. 보호 흡수와 전투 후 회복은 HP 피해 및 전투 회복과 구별한다.
- 편성·정책별 실제 HP 피해, 쓰러짐 이벤트, 쓰러짐 없이 끝난 원정을 확인한다. 쓰러짐은 영구 사망이 아니며 회복 뒤 다시 쓰러지면 별도 이벤트다.
- 구역·적 조합별 완료 전투의 평균 부담을 확인한다. 후반은 도달한 원정만 관찰한다는 생존자 편향이 있다.
- 카드 후보 제시→채택→후속 기회→이후 보유→이후 손패→이후 사용을 확인한다. 다음 완료 전투가 없는 채택은 별도 분리한다.
- 전투마다 덱 보유→손패 도달→사용을 별도로 확인한다. 카드가 없었거나 뽑히지 않은 전투를 사용 실패로 세지 않는다.
- 적의 공격·광역·준비 의도가 공개된 횟수와 실제 피해/준비 이벤트가 발생한 횟수를 구별한다. 준비 후 다음 라운드의 공개 패턴이 실제 적용되었는지도 확인한다.

## 카드 통계의 분모

전투 보상 후보는 `phase: reward`, `method: chooseReward`의 `candidates` 문자열 배열이다. `args[0]`은 채택 카드 종류이고 `null`이면 건너뛰기다. 상점 구매·사건 교환/복제·시작 덱은 이 후보/채택 표에 포함하지 않는다.

후속 추적은 카드 종류 단위이다. 기존 초기/coverage 배치에는 카드 사본 ID 변화 정보가 없고, 이번 분석은 신·구 로그를 같은 종류 단위로 처리한다. 새 수집기의 `inventoryChanges.cards.added/removed/changed`가 있는 배치에서도 개별 사본 추적은 이번 집계의 범위에 넣지 않는다. 따라서 같은 종류의 기존 카드나 다른 경로의 획득을 완전히 분리할 수 없다. 동일 원정에서 보상을 선택한 구역보다 뒤의 완료 전투만 후속 기회로 센다.

한글 카드 이름은 저장 로그를 우선 사용하고, 미사용 카드처럼 로그에 이름이 없으면 현재 카탈로그의 이름만 보완한다. `nameOrigin`으로 출처를 구별한다. 후보·효과·수치·사용 통계는 원본 로그 기준이며 현재 카드 효과로 과거 전투를 다시 계산하지 않는다.

| 비율 | 분자 | 분모 |
|---|---|---|
| 제시→채택 | 해당 종류 채택 사건 | 해당 종류 후보 제시 사건 |
| 채택→후속 보유 | 이후 완료 전투에서 종류를 보유한 채택 사건 | 이후 완료 전투가 있는 채택 사건 |
| 후속 보유→손패 | 이후 손패 도달이 확인된 채택 사건 | 이후 보유가 확인된 채택 사건 |
| 후속 손패→사용 | 이후 사용이 확인된 채택 사건 | 이후 손패가 확인된 채택 사건 |
| 전투 보유율 | 덱에 해당 종류가 있는 완료 전투 | 해당 조건의 모든 완료 전투 |
| 전투 손패 도달률 | 손패 도달이 확인된 보유 전투 | 해당 종류를 보유한 완료 전투 |
| 전투 사용률 | 사용이 확인된 보유 전투 | 손패 도달이 확인된 보유 전투 |

원정 전체에서 해당 종류가 단 한 번이라도 쓰였다는 사실로 각 채택 사건을 성공으로 세지 않는다. 채택 구역 뒤에서의 관찰만 사용한다. 반복 제시/채택은 사건별, 전투 내 반복 뽑기/중복 카드는 종류별 한 번만 센다. 기본 행동은 덱 카드가 아니므로 제외한다.

## 적 의도를 읽을 때

`endRound`는 죽은 적의 의도를 건너뛴다. 공격 대상이 이미 쓰러졌다면 그 공격은 다른 동료에게 옮겨가지 않는다. 반격으로 적이 쓰러지면 같은 광역 공격의 일부나 이후 적의 의도가 생략될 수 있다. 보호로 모두 흡수되어도 실제 `damage` 이벤트가 있으므로 공격 적용으로 센다.

완전히 억제되어 유효 피해가 0이면 `hit`는 피해 이벤트를 남기지 않는다. 따라서 `zeroEffectiveDamageWithoutEvent`는 피해 0 조건 관찰이며 실제 공격 실행을 확정하는 항목이 아니다. `noApplicationObserved`도 반격·죽은 대상·전투 종료 등의 원인을 임의로 확정하지 않는다.

미래 라운드에 나올 예정인 패턴은 추정하지 않는다. '광역 적용 없는 완료 전투'에는 일찍 처치한 경우와 완전히 억제한 경우 등이 함께 있다. `analysis.json`의 기회별 분류를 같이 읽어야 한다.

## 중복과 비교 조건

시드·편성 순서·정책·난이도·브레이크·콘텐츠·정책 버전·실행 상한·전체 소스 해시가 같은 원정은 첫 번째만 집계한다. 조건이 다르면 제거하지 않고 다른 `cohort`로 분리한다. 같은 기본 식별자가 서로 다른 소스 해시에 나타나면 중복 후보 경고도 표시한다.

`manifest.json`이 없으면 입력 경로를 소스 식별자로 사용한다. 서로 다른 파일 사이의 중복 여부는 확정할 수 없다. 전체 합계는 명시적으로 조건을 합친 기술 통계이며 층화된 결과가 인과 비교를 보장하지는 않는다.

`excludeFromCoverageTotals:true` 또는 `studyType:paired-failure-diagnostic` 표식 자료는 입력에 포함해도 전체 원정 집계에서 자동 제외한다. 제외 건수는 `excludedDiagnosticRecords`와 보고서에 표시한다. 같은 원정 진입 상태를 복제한 진단은 독립 원정 표본이 아니므로, 해당 결과는 별도 `failure-probe` 보고서에서 읽는다.

낮은 채택·사용률은 약한 카드의 증거가 아니다. 후보 제시가 적었는지, 덱에 남았는지, 손패로 들어왔는지, 자동 정책이 그 효과를 평가하는지 먼저 확인한다. 승률은 사람의 재미를 증명하지 않는다.

## 검사

`--self-test`는 현재 실제 엔진으로 짧은 원정을 완료하고 중복 제거, HP 회계, 보상/손패 분모를 검산한다. 실제 `endRound`로 완전 억제와 보호 흡수 뒤 반격을 실행하여 이벤트 없는 공격과 실제 적용을 구별하는지도 검사한다. 검사 중의 전투 상태 구성은 독립 fixture에만 적용하며 저장된 실험과 게임 소스는 변경하지 않는다.
