# 7단계 — 작은 완성판의 원정 흐름

버전: `slice1`. 기존 6방 원정과 네 명 파티를 유지한다. 새로운 경제·캐릭터·특성을 추가하는 대신 준비→관전→성장→보스→복기→재준비 흐름을 다듬었다.

## 적용 내용

- 출발·경로·배치·보상·성장·정비 화면에 현재 할 일을 한 줄로 설명한다. 자동전투 화면에는 안내 패널을 추가하지 않아 전장 공간을 유지한다.
- 보상 안내는 대기 카드가 자동으로 전투에 들어가지 않는 점과 20장 편성 규칙을 설명한다. 기존 능력·특성·교체 손익 비교를 재사용한다.
- 최종 결과에서 패배 전투를 우선 선택해 첫 전투불능, 범위 공격 피격, 준비한 궁극기 보유 여부를 실제 기록으로 보여준다. 기록이 부족하면 미기록이라고 설명한다.
- 해당 전투의 독립 연습으로 바로 연결한다. 배치·보호 구성·공격/보호 방침 중 하나를 바꾸는 비교를 제안한다. 관측된 장면을 패배의 확정 원인으로 표현하지 않는다.
- 이전 출발 덱과 사수 선택을 출발 준비 화면에 불러온다. 직접 수정한 뒤 출발할 수 있다. 보상·진화·운용 분기는 가져오지 않으며 새 시드와 현재 캐릭터 레벨을 사용한다. 같은 전투를 통제하여 비교하는 기능은 별도 연습에 둔다.
- 출발 덱 기록이 없거나 공개 도전이면 불러오기 버튼을 제공하지 않는다. 현재 원정을 진행 중이면 덮어쓰지 않는다.
- 관전 화면에서 대사·초상화를 매번/주요 장면/첫 사용으로 조절한다. 기존 전체/간소 연출 및 배속과 함께 사용할 수 있다. 설정은 기존 브라우저 저장을 재사용한다.
- 기존 캐릭터 초상화·무기 동작·대사와 기본/강조/궁극기 연출을 재사용한다. 새 이미지나 음성을 제작한 단계는 아니다.

## 검사

`expedition-flow-check.cjs`는 두 사수와 세 출발 컨셉의 기초 덱 복원, 보상·진화 유입 차단, 이전 저장·공개 도전, 기록별 제안 우선순위를 확인한다.

`expedition-flow-browser-check.cjs`는 1280×720, 390×844, 320×568에서 실제 UI로 출발→준비→자동전투→보상/정비→보스→최종 결과→연습→새 출발을 진행한다. 완주 검사는 시드 7·레벨 5·회복 경로를 사용했다. 별도 HP 1 조건의 실제 패배에서 첫 전투불능 제안과 당시 HP를 유지한 연습 연결을 확인했다. 이는 화면 흐름 검사이며 일반 난도·승률 검증이 아니다.

궁극기 중간 저장 후 재접속, 일시정지와 배속·연출 빈도 유지, 전장 크기 유지, 가로 넘침·브라우저 오류를 검사했다. 기존 `ultimate-browser-check.cjs`의 세 화면 크기 검사도 통과했다. 관전·결과 화면을 이미지로 확인했다.

## 사람의 플레이로 남은 확인

이번 적용은 완성 구간의 기능과 흐름을 연결한 것이다. 외부 설명 없이 첫 원정을 이해하는지, 실패 뒤 실제로 다른 구성을 시도하는지, 궁극기를 오래 보유하는 판단이 자연스러운지, 캐릭터 대표 장면이 즐거운지는 플레이로 확인해야 한다.

회복 경로 편향, 최대 레벨 난도, 전투가 빨리 끝나 대표 기술을 못 보는 경우의 균형은 이번 UI·흐름 검사로 해결되었다고 판정하지 않는다. 8단계의 대량 콘텐츠 제작 전에 이 작은 완성판으로 확인하고 필요한 부분만 조정한다.
