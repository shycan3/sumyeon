# 작은 출시 후보 · 6단계

적용 URL: `http://127.0.0.1:8765/character.html?v=release6`

기능 구현과 자동 검사는 완료했다. 실제 이용자의 첫 원정 이해도와 반복 플레이 동기는 아직 검증하지 않았다. 전체 출시 준비가 완료됐다는 의미는 아니다.

## 이번에 적용한 것

발견 목표를 세 개로 제한했다. 목표를 달성해도 능력치·재화·전투 보상을 주지 않는다.

| 목표 | 인정하는 근거 |
| --- | --- |
| 특성의 완성 | 교전 승리 + 해당 특성 2단계 + 실제 특성 발동 기록 |
| 두 가지 운용 | 자동 운영의 공격·보호 방침으로 각각 교전 승리. 같은 상대일 필요는 없음 |
| 새로운 힘 | 원정 전용 보상 기술을 사용해 실제 피해·회복·보호막 흡수·차단·피해 분담·이동 효과 발생 |

홈에서는 다음 목표 하나와 완료 수만 보여준다. 발견 기록에서 전체 목표와 대표 기술 기록을 살펴본다. 보상 기술 활용은 패배한 교전에서도 인정하지만, 승리·특성 완성 목표는 패배를 인정하지 않는다. 연습과 제작 체험은 영구 발견 기록에 포함하지 않는다.

세린·리아·노아의 대표 기술/궁극기가 실제 효과를 냈다면 초상화, 카드 이름, 기존 사용 대사, 교전 누적 효과를 기록한다. 단순 선택·시전 취소·효과 없는 회복은 대표 기술 기록을 만들지 않는다. 같은 기술은 효과 종류가 같고 누적 수치가 더 큰 기록만 갱신한다. 피해와 회복의 크기는 강함을 비교하는 척도가 아니다.

결과 화면의 ‘같은 조건으로 재전투’는 저장된 시작 조건으로 연습을 여는 기능이다. 전투 영상이나 특정 타격 시점의 재생 기능은 아니다. 발견 기록의 초상화·대사는 기존 기술 연출과 같은 정의를 사용한다. 신규 고품질 아트·음성·모션을 제작한 단계는 아니다.

보스 승리 화면의 완료 버튼은 바로 원정을 마친다. 불필요했던 중간 완료 화면을 거치지 않는다. 패배 결과에서는 대표 기술보다 재준비 제안을 먼저 보여준다. 재준비 설명에 사수와 지원가 선택 복원을 모두 표시했다. 홈 카드 도감에도 리아·노아의 보상 기술이 포함된다.

## 저장과 호환

`meta.discovery`에 발견 ID와 기술별 작은 요약만 보관한다. 중복 호출은 목표나 수치를 누적하지 않는다. 원정 기록 10개가 밀려나도 이미 확인한 발견은 유지된다. 구형 저장은 남아 있는 원정 기록 최대 10개에서만 복원한다. 더 오래되어 삭제된 기록은 복원할 근거가 없다.

저장 검사는 알려진 목표·특성·카드·실제 소유 캐릭터와 유한한 수치를 확인한다. 기존 전투 실행, 카드 수치, 성장 경험치, 보상 후보에는 발견 모듈이 개입하지 않는다. 기존 진행 중 원정의 콘텐츠 규칙은 보존한다.

## 자동 검사 결과

- `discovery-check.cjs`: 실제 효과 기준, 시전 취소·패배, 중복 기록 방지, 잘못된 소유자·저장 거부, 구형 기록 복원, 10개 원정 이후 유지, 연습 격리, 모듈 유무 간 전투·레벨·경험치 일치.
- `release-flow-browser-check.cjs`: 1280×720 키보드와 390×844·320×568 터치. 출발→첫 보상 교체→진화→정비→보스→완료→연습→재준비를 실제 UI로 진행. 전투 중 일시정지 저장/재로드 일치, 실제 대표 기술 기록, 가로 넘침 없음, 실제 패배 후 재준비 확인.
- 위 전체 원정 검사는 레벨 3·고정 시드의 완료 가능한 구성이다. 별도 패배 검사는 레벨 1·보호 방침으로 실제 전투를 수행했다. 첫 이용자가 레벨 1에서 원정을 완주할 수 있다는 검증으로 해석하지 않는다.
- `release-stability-browser-check.cjs`: 손상 원본 덮어쓰기 방지와 복구 사본 보관. 관전 900회 그리기에서 전투 상태·DOM 개수 유지, 20회 연출 초기화에서 이전 초상화/대사 상태 제거. 이 실행 환경의 그리기 평균은 배치별 약 1.1~2.1ms였다. 저사양 실제 기기나 장시간 메모리 안정성의 보장은 아니다.
- `support-content-check.cjs`, `support-strategy-check.cjs`, `identity-compat-check.cjs`: 기존/신규 지원가·사수, 보상·저장·연습, 서로 유리한 전투 사례와 기존 96전 실행 호환 유지.
- `battle-viewport-browser-check.cjs`: 일반/제작 화면의 10개 화면 크기 조합에서 전체 전투 화면, 위험 구역 표시, 조작·연습·거점 복귀 유지.
- `watch-frame-browser-check.cjs`, `content-support-browser-check.cjs`: 실제 프레임 실행의 속도·일시정지, 3개 크기에서 제작 체험·초상화·대사·저장 복원 유지.

## 사람의 플레이 확인과 다음 수정

1. 새 저장·레벨 1에서 별도 설명 없이 출발, 카드 교체, 보스/패배 결과까지 이해하는지 확인한다. 어디서 멈췄는지부터 수정한다.
2. 실패 후 제안을 읽고 카드·배치·방침 중 하나를 스스로 바꾸는지, 재전투에서 그 차이를 알아보는지 확인한다.
3. 같은 캐릭터로 다른 컨셉을 시도하고 싶은지, 대표 기술 기록이 캐릭터의 매력을 떠올리게 하는지 확인한다. 기록 수치를 크게 만드는 숙제처럼 느껴지면 목표와 표시를 줄인다.
4. 노아+리아와 보호 방침의 원정 안정성, 낮은 레벨의 휴식 선택 편향, 진화 정비 회복의 대가를 집중 확인한다. 5단계에서 발견한 균형 문제를 이번에 해결했다고 단정하지 않는다.

이 결과로 다음 수정 범위를 정한다. 계정·결제·대량 캐릭터·파티 확대를 이어 붙이기보다 첫 원정의 막힘과 조합 변화의 체감을 먼저 확인한다.
