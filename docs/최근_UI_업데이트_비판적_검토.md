# 최근 UI 업데이트 비판적 검토

2026-10-07 · 대상 `character.html?v=identityui1`. UI 1~5단계 구현을 검토했다. 제품 코드와 사용자 저장은 변경하지 않았다. 격리 브라우저를 사용했고 재현용 검사/측정/스크린샷만 추가했다.

## 판단

이전의 주요 행동 잘림, 편집 레일 초기화, 카드 정보 불일치 등은 개선됐고 보상→교체→전투→결과→연습의 연결도 마련됐다. 그러나 조작의 정확성·기록 해석·캐릭터 관전의 핵심 품질에는 아직 결함이 남는다. 자동 검사 통과는 실제 사용성과 감상 경험의 완료를 뜻하지 않는다. 기능을 더 늘리기보다 아래 순서로 수정하는 편이 적절하다.

## 확인된 결함

### 1. 대표 기술 사용자·대사가 잘림 — 우선 수정

`watch-ui.css`는 기존 76px/66px 기술 영역을 38px, 높이 600px 이하에서는 28px로 제한한다. 기존 사용자/기술명/대사 세 줄을 그대로 넣는다. 실제 시드 1 첫 교전 5.02초에 잔광 검무가 발동했을 때 슬롯 clientHeight 36px, scrollHeight 48px였고 사용자 이름과 대사가 잘리는 화면을 확인했다. 같은 실제 프로필의 대표 연출을 320×568/844×390에 재현하면 26px 슬롯에서 사용자·대사·32px 초상화가 잘렸다.

화면 전체가 넘치지 않아도 중요한 내부 텍스트는 잘린다. 사용자가 원하는 캐릭터/기술 감상 목적과 직접 충돌한다. 작은 화면에서는 사용자+기술명 한 줄과 의도적으로 선택한 대사 한 줄 등 별도 레이아웃을 정의하고, 대표 기술은 읽을 수 있는 연출 공간을 확보해야 한다. 큰 DOM을 작은 높이에 그대로 잘라 넣는 방식을 제거한다.

근거: `recent-ui-skill-audit.cjs/json`, `recent-ui-real-skill-audit.cjs`, `critique-skill-actual-1280.png`. 실제 교전은 시드 1이며, 3규격 상세 경계 측정은 동일 프로필 재현 표본이다.

### 2. Space 단축키가 조회창 키보드 조작을 가로챔 — 우선 수정

`현재 손패 · 기술 정보 보기` summary에 포커스를 두고 Space를 누르면 창은 닫힌 상태이고 전투는 일시정지된다. 전역 keydown이 summary의 기본 동작을 막고 관전 정지를 실행한다. 버튼/링크는 예외 처리하지만 summary는 제외하지 않는다.

summary 등 조작 요소에서는 기본 키보드 동작을 존중하고, 전투 배경에 포커스가 있을 때만 관전 단축키를 처리한다. Enter/Space/Escape 각각으로 조회·도구·선택창을 검사해야 한다.

### 3. 전투 중 손패 교체 때 포커스가 사라짐 — 우선 수정

손패 카드에 포커스를 놓고 전투를 7초 진행하면 activeElement가 카드 DIV에서 BODY로 바뀐다. 손패·준비·카드 사용 가능 조건이 바뀔 때 hand 전체 innerHTML을 교체하기 때문이다. 편성 화면의 위치 유지가 전투 조회에는 적용되지 않았다.

남아 있는 카드 ID의 포커스와 조회 선택을 보존한다. 조회하던 카드가 소모되면 기술 설명을 고정하거나 명확한 대체 포커스를 제공한다. 실시간 업데이트를 멈춘 테스트만으로 이 동작을 검증할 수 없다.

### 4. 과거 저장의 상세 기여도에서 거짓 미등장 표시 — 우선 수정

시드 1 교전의 17초 스냅샷에서 insights만 제거해 예전 저장의 측정 이전 상태를 재현했다. 기존 stats 사용 기록을 유지하여 재개하면 결과에서 잔광 검무/빛을 좇는 걸음/차단 방패는 총 사용 1회지만 상세 표에는 손패 미등장·0회가 표시된다. 새 ResultStory는 일부 미기록으로 처리하지만 BattleInsights.panel의 상세 표는 같은 규칙을 사용하지 않는다.

기존 전체 사용 기록과 측정 구간의 효과 기록을 구분한다. 알 수 없는 손패 등장 여부는 미기록으로 표시하고, 전체/구간 사용 수를 명시해야 한다. 같은 데이터의 상태 판정도 공통화해야 한다.

근거: `recent-ui-partial-audit.cjs`. 전체 사용 1, 부분 used 0의 기록을 비교했다.

## 설계상 한계 및 개선안

### 5. 전장이 넓어 보이지만 실제 그림은 작음 — 관전 우선 개선

1280×720에서 canvas 요소는 약 1212×208px지만 고정 960:390 비율의 contain 표시로 실제 그림은 약 513×208px다. 가로 폭의 약 42%만 전투 그림으로 사용한다. 320×568에서는 280×240px 영역 중 실제 그림은 280×114px다. 넓은 빈 영역이 캐릭터의 가독성과 움직임 감상으로 연결되지 않는다.

단순 CSS 박스 확장 대신 전장 비율, 카메라 확대/초점, 배우·이름·HP의 최소 표시 크기를 조정한다. 전체 전장 조회와 중요한 행동의 가까운 연출을 구분하는 방법도 가능하다. 이번 측정만으로 이전 버전 대비 정확한 증가/감소율을 주장하지 않는다.

### 6. 덱 편성은 읽히지만 탐색 비용이 큼 — 선택 UX 개선

390px 원정 편성 표본은 12개 그룹을 가로 레일에 표시하며 viewport 360px에 scrollWidth 약 3727px이다. 한 번에 약 한 카드만 확인하므로 전체 비율/종류/교체 대상을 비교하려면 여러 번 왕복해야 한다. 첫 카드 조작 버튼은 이 규격에서 보였다. 이를 모든 모바일에서 버튼이 숨는 결함으로 일반화하지 않는다.

편성/대기 장수를 볼 수 있는 작은 목록, 소유자·특성 필터를 제공하고 선택 카드만 큰 상세로 표시하는 방식이 적합하다. 보상 후보 요약과 편성 탐색의 서로 다른 구조도 맞출 수 있다. 왕복 횟수/비교 시간은 아직 사용자에게 측정하지 않았다.

### 7. 성장 결과는 정확한 합산에 가까우나 원인 설명이 부족함 — 기록 연결 개선

일반/진화/사본 효과는 카드 종류별 합산이고, 특성 장면은 변경 카드와의 관계보다 마지막 두 이벤트를 고른다. 문구의 한계 안내는 적절하지만, '덱을 바꿔 무엇이 달라졌는가'를 강하게 설명하기에는 부족하다. 도발 등 수치로 합산하지 않는 지원도 요약에서 빛나기 어렵다.

대표 사건의 실제 카드·대상·효과를 연결하고, 그 연결이 없는 경우는 교전 전체 장면으로 구분한다. 현재 recap은 heal/shield/protect/block/counter의 대상·카드·시간을 갖고 있어 우선 재사용할 수 있다. 특정 카드가 승리 원인이었다고 추정해서는 안 된다.

### 8. 변경 전 덱 비교가 흔한 진화에서도 막힘 — 분석 도구 개선

기초 카드 3사본 중 한 장만 진화해도 현재 보유 풀에 일반 3사본이 없어서 변경 전 덱 버튼이 비활성화된다. 실제 재현에서 heal 한 장 진화 후 이전 덱 비교가 막혔다. 현재 제한은 문서화된 의도이고 원정 지급 결함은 아니지만, 성장 비교의 주요 순간에 핵심 도구를 쓰기 어려워진다.

원정 보유 풀과 분리된 과거 교전 스냅샷으로 '과거 덱 재현 실험'을 만들 수 있다. 실제 기록된 카드/진화 상태만 사용하고 원정에 지급하지 않으며, 비교는 현재 교전의 동일 조건에서 실행한다. 이 기능의 결과도 난수 소비 차이와 함께 해석한다.

### 9. 실험 도구 닫기가 정지 상태를 바꿈 — 동작 단순화

전투를 정지한 상태에서 도구를 열었다가 아무 명령 없이 닫아도 전투가 재개된다. '닫으면 오토 복귀'라는 설명과 구현은 일치하므로 미고지 버그라고 부르지 않는다. 다만 정보창 닫기와 진행 상태 변경을 묶어 두면 뜻밖의 행동이 될 수 있다. 닫기는 기존 정지 상태를 유지하고 명시적인 오토 재개를 별도로 제공하는 편이 일관된다.

기본 설정에서 수동 전투를 계속 선택할 수 있다는 점도 풀오토 정상 흐름과 실험 도구 분리의 남은 부분이다. 사용자 설정/과거 저장을 보존하며 일반 제품 흐름에서는 오토를 기본으로, 수동은 검증 도구로 분리할 수 있다.

### 10. 공통 컴포넌트 도입과 별개로 배치 규칙은 복잡함 — 후속 기술 정리

전역 DOM 감시는 제거했지만 workspace 분류/재배치와 모든 nonbattle summary의 팝업 변환은 여전히 selector/태그 기반이다. CSS도 7개 파일과 추가 override/important에 걸쳐 있다. 대표 기술 클리핑처럼 한 화면 최적화가 기존 연출 요구를 덮을 수 있다.

화면 유형과 primary/secondary/action/detail 위치를 명시하고, 중복 CSS를 컴포넌트별로 정리한다. 전체를 새 프레임워크로 재작성할 필요는 없다. 페이지 넘침뿐 아니라 실제 글자/초상화 경계와 실시간 포커스도 검사한다.

## 권장 작업 순서

1. 대표 스킬 클리핑, Space 충돌, 손패 포커스 손실, 부분 기록 오표기를 묶어 수정.
2. 전장 실제 표시 크기·카메라·주요 행동 연출을 개선.
3. 편성 탐색을 작은 전체 목록+선택 상세로 정리하고, 결과 사건·과거 덱 비교를 연결.
4. 확인된 사용 흐름에 맞춰 CSS/배치 규칙을 정리하고 실제 플레이의 카드 비교 시간/왕복 횟수/해석 오류를 측정.

고정 행동 영역, 보상 조회 비변경, 정확한 교체 특성 계산, 일반/진화 분리, 원정과 연습 분리는 유지한다. 정상 조작/원정 완주 검사의 통과는 유효하지만 이번 부정 사례를 포함하지 않았고 재미나 이해도를 인증하지 않는다.
