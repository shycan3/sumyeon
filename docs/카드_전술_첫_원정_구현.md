## 구현 범위

[설계 v0.1](카드_전술과_캐릭터_교전_설계_v0.1.md)의 판단 흐름을 기존 실시간 엔진과 분리해 구현했다. 2인·공유 덱 12장·손패 5장·행동력 3으로 세 번의 전투를 진행하는 독립 실험이다.

- 균형·공격·보호 출발 덱. 첫 다섯 장은 동일해 처음 판단을 비교할 수 있고, 이후 카드 비율이 달라진다.
- 카드 선택 → 대상 → 사용. 한 장씩 확정하며 결정 중에는 전투 상태가 진행되지 않는다.
- 카드 사용 후 자동 드로우 없음. 턴 종료 때 남은 손패를 버리고 새 손패를 받는다.
- 아군 기본행동 1회씩 → 적의 공개 행동. 기본행동 도중 목표가 죽으면 임의로 재타겟하지 않는다.
- 결속 피해 감소와 다음 기술 1회 강화, 보호, 유효 회복, 반격 1회, 전열·후열 견인.
- 전열·후열 구역 공격과 개체 대상 공격 구분. 이동은 개체 공격 자체를 취소하지 않는다.
- 적의 공격이 매 턴 +2 증가. 보호·회복만 반복하는 정체를 막기 위한 임시 비용이다. 적 회복량은 이 증가와 결속의 피해 감소를 적용하지 않는다.
- 체력 절반 이하 보스는 다음 턴 의도 생성 때 공개된 강공격으로 전환한다.
- 모든 카드에 호위·추격·공명 특성 표시. 단계 보너스와 궁극기는 아직 넣지 않았다.
- 첫 두 승리에서 공격·보호·전체 회복 보상 중 하나를 기존 카드 한 장과 교체하거나, 카드 대신 생존자 HP 8 회복.
- 보상 비교에 시전자·비용·효과·특성을 함께 표시. 동일 카드는 장수로 묶고 한 사본만 교체한다. 덱 12장은 유지된다.
- 전투불능 캐릭터의 카드만 해당 전투에서 제외. 부활은 없으며 사망자를 휴식으로 회복시키지 않는다.

캐릭터 이름과 능력은 테스트 표현이다. 프롤로그의 대사·세계관·장면·정식 카드 목록을 변경하지 않았다. 일러스트를 추가 제작하지 않고 캔버스 임시 캐릭터와 기술 기호를 사용했다.

## 화면과 실행

전장은 화면 전체의 고정된 캔버스다. 손패·행동력·예고·피해 예측·선택 패널은 그 위에 표시된다. 스킬 문구가 나타나도 캔버스 크기가 변하지 않는다.

일반 교전은 기본 베기와 적 공격, 카드 기술은 돌진·결속 선·보호·회복·실제 이동으로 표현한다. HP·의도·턴 표시는 연출의 해당 효과에 맞춰 갱신하며, 다음 턴 표시가 이전 교전 중 먼저 나오지 않는다. 연출 1배·2배·끄기는 규칙과 결과에 영향을 주지 않는다.

데스크톱은 손패 다섯 장을 나란히 표시하고, 모바일은 손패만 가로 스크롤한다. 상세 대상과 보상 비교는 실제 버튼으로 조작한다. 전투 기록과 도움말은 필요할 때 연다.

이번 원정은 저장하지 않는다. 기존 풀오토 원정의 데이터·저장·파일을 연결하거나 덮어쓰지 않는다.

## 검증

`prototype/tactical-check.cjs`: 11개 규칙 검사 통과.

- 공격 연계: 결속→충격참으로 HP 28 사냥꾼 처치, 하린 공격 취소. 후열 도윤은 주술사 피해 8을 받음.
- 보호 대응: 엄호→견인→짧은 베기 후 하린 피해 2, 도윤 피해 없음. 사냥꾼 HP 13, 주술사 HP 18이 남음.
- 비용 부족·대상 오류·종료 후 입력은 상태와 자원을 변경하지 않음.
- 미리보기·턴 종료 예측은 원본 상태와 난수값을 변경하지 않으며 실제 결과와 일치.
- 반격·보호 차감·고정 목표 취소·사망 카드 제외·전투 종료 처리 확인.
- 25개 시드의 유효 카드 사용에서 미리보기 상태와 실제 상태 비교.
- 세 출발 덱 × 세 시드, 총 9개 3전투 경로를 개발용 한 턴 탐색기로 확인. 모두 휴식 선택 조건에서 완주. 공격 덱은 대체로 빨랐고 보호 덱은 더 많은 턴을 사용했다.

경로 탐색기는 손패·공개 의도만 사용하는 개발 검사다. 게임의 플레이어 오토 모드로 제공하지 않는다. 모두 완주했다는 결과는 사람이 재미있게 판단한다거나 세 덱의 성능이 균등하다는 증거가 아니다.

`prototype/tactical-browser-check.cjs`: 1366×768 / 390×844에서 실제 버튼 조작으로 3전투 완주.

- 카드와 대상 선택, 사용 중 중복 입력 방지, 결정 중 상태 정지.
- 스킬 문구 전후 캔버스 크기 고정, 카드 예측 표시.
- 보상 효과·특성 비교, 한 사본 교체, 다음 전투 반영, 휴식, 최종 결과.
- 기존 저장 표식 보존, 페이지 오류 0, 페이지 가로·세로 넘침 없음.
- 화면을 직접 검토해 예측 패널의 하단 UI 겹침과 모바일 보상 목록 중복을 수정.

주요 파일: `prototype/tactical.html`, `tactical-core.js`, `tactical-app.js`, `tactical.css`. 결과 기록은 `tactical-results.json`, 화면 검토 이미지는 `tactical-battle-*.png`, `tactical-reward-*.png`, `tactical-result-*.png`다.

### 사진 참고 전투 구도 · perspective1

2026-10-09 요청에 따라 아군을 왼쪽 가까이에 크게, 적을 오른쪽 먼 공간에 작게 배치하는 낮은 시점의 2.5D 구도로 변경했다. 임시 캐릭터의 비율을 길게 조정하고, 바닥·기둥·벽에 원근을 넣었다. 깊이 순서로 캐릭터를 그려 겹침을 처리하고, 돌진과 견인은 이동 거리에 따라 표현 크기가 달라진다. 위험한 구역은 캐릭터 발밑 표시로 표현한다.

그림과 카메라 좌표는 별도 `tactical-stage.js`에 두었다. 전열/후열 판정, 카드 비용·피해·턴 규칙은 바꾸지 않았다. 스킬 문구 전후 전장 크기 고정과 실제 3전투 완주를 데스크톱·모바일에서 다시 확인했다. 모바일에서는 가까운 캐릭터의 발·HP가 하단 예상 패널에 가리지 않게 전장 여유를 두었다.

### 다음 구조 검증
