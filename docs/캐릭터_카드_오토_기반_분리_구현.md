# 캐릭터·카드·오토 제작 기반 분리 — 4단계

2026-10-08 · identity1

## 적용 범위

현재 네 명·20장 덱·역할별 기본 행동·공격/보호 방침·원정 규칙과 수치를 유지하면서 전투 식별과 기술 재사용 기반을 정리했다. 정식 시험 캐릭터·새 카드·궁극기는 추가하지 않았다. 반복 역할과 새로운 기술 이름은 검사 환경에서만 등록한다.

| 구분 | 표현 | 책임 |
|---|---|---|
| 캐릭터 | characterId / 캐릭터 카탈로그 | 이름·기초/보상 키트·고유 AI 선호 |
| 역할 | role | HP·기본 공격·사거리·이동·공통 역할 AI |
| 파티 자리 | slot 0~3 / party | 레벨·HP·태세·배치·피해 통계의 배열 위치 |
| 전투 개체 | a0~a3, e0… | 현재 행동·효과·표적·전투불능·이벤트 연결 |
| 카드 사본 | id / key / characterId / source / upgraded | 원본 기술·획득 경로·진화 상태·원래 키트 출처 |
| 카드 시전자 | casterSlot → 전투 actor | 편성한 캐릭터가 실제로 기술을 실행 |

`a1`은 두 번째 파티 슬롯을 뜻하며, 역할 1이나 세린을 뜻하지 않는다. 같은 역할도 서로 다른 전투 개체와 HP·피해 통계를 갖는다. 카드의 characterId는 기존 저장에서 쓰던 키트 출처로 유지하고 casterSlot을 별도로 추가했다.

## 시전자와 원정 연결

CharacterData.defaultParty / character / validParty / bindCard / canCast가 식별과 호환을 처리한다. 기존 일반 기초·지원 기술은 카드 정의의 역할이 같은 캐릭터에게 지정할 수 있다. 세린의 여섯 고유 기술은 별도 시전자 규칙으로 세린에게 제한한다. 효과 종류 자체가 전용/공유 여부를 결정하지 않는다. 새 캐릭터의 전용 기술도 기존 효과를 쓰면서 소유 제한만 따로 지정할 수 있다.

시전 슬롯이 없으면 출처 캐릭터를 찾고, 없으면 유일한 호환 시전자를 찾는다. 여러 호환 시전자 중 자동 선택이 필요한 상황은 거부하고 명시적 슬롯을 요구한다. 잘못된 슬롯·역할·전용 소유자·중복 캐릭터 파티는 거부한다. 현재는 같은 캐릭터의 복수 출전과 파티 인원 확대를 허용하지 않는다.

새 일반 원정은 identityVersion 1, party와 카드의 casterSlot을 저장한다. 준비 중 assignCaster API가 호환 시전자로 변경할 수 있으며 전투 중에는 잠근다. 현재 UI는 역할별 한 명이라 새 시전자 선택 컨트롤을 추가하지 않았다. 원정 시작 API는 기존 네 명의 슬롯 순서를 바꿀 수 있다. HP·회복 상한·태세·배치 표시·공간 기술 범위·기본 사거리·영구 레벨과 경험치 반영은 실제 슬롯의 캐릭터/역할을 사용한다.

독립 연습·배치 비교는 기록된 파티와 사본 시전자를 그대로 재사용한다. 카드 외형 도구는 실제 시전자 또는 파티를 받아 시전자 이름을 표시할 수 있다. 원정 결과의 전투 기록도 당시 파티를 보존한다.

## 기술 효과와 AI 선호

CharacterData.skill / registerSkill에서 다음 효과 프로필을 정의한다.

| 공통 효과 | 기존 적용 | 공통 데이터 |
|---|---|---|
| chaseStrike | 빛을 좇는 걸음 | 적 공격 후 카드의 hold 시간 추격 |
| retreatStrike | 간격 베기 | 적 공격 후 거리 벌리기 |
| counterWard | 받아치기 | 자기 대상·보호막·반격 피해 |
| comboStrike | 잔광 검무 | 적 대상·추가 타격 간격·행동 회복 |
| executeChain | 이어지는 섬광 | 부상자 마무리·추가 돌진 피해/지연/추격 시간 |
| coverWard | 너의 곁으로 | 다른 동료 대상·이동·기존 피해 분담·반격 피해 |

실행, 유효 대상, 오토 점수와 처치·연계 판단, 카드의 기능/3타 표시, 행동 덮어쓰기, 저장된 추격·엄호·반격 출처 검사가 카드 이름 대신 이 프로필을 사용한다. 추가 타격은 새로 연결한 카드 key와 사본 ID를 유지하며 세린 카드로 위장하지 않는다. 기본 피해·회복·보호막·효과 지속·특성과 공간 효과는 기존 정의/실행기를 계속 사용한다. 프로필 종류·카드 kind·대상·필수 수치·연속 타격 간격/회복이 맞지 않으면 등록을 거부한다.

역할 AI는 공통 임무를 제안한다. 캐릭터 AI는 명시적인 선호 데이터로 같은 점수 척도에서 표적을 바꾼다. 현재의 세린 ‘부상 동료 주변 위협 견제’를 woundedAllyThreat 프로필로 옮겼다. 새 이름별 조건을 추가하지 않고 다른 캐릭터에도 연결할 수 있다. 카드의 추격·엄호 이동 목적과 도발 제약은 기존 우선순위를 유지하고, 실행 권한은 엔진 한 곳에 둔다.

실행 중 중단·차단·사망·효과 만료와 후속 타격 정리는 기존 공통 행동 처리기를 재사용한다. 대사·초상화·색·그림은 카드/캐릭터별 표현 데이터로 남겨 정체성을 유지한다. 특수한 미래 효과를 모두 처리하는 범용 편집기나 임의의 여러 효과 조합 문법은 만들지 않았다.

## 호환과 검사

식별 정보가 없는 과거 원정·전투는 역할별 고정 시전 규칙을 유지한다. 고정 공개 도전은 이전 식별 규칙으로 시작한다. 새 식별 규칙의 파티·전투 개체·카드 시전자가 불일치하면 저장 복원을 거부한다. 원본 저장을 자동으로 덮어쓰는 일괄 변환을 하지 않는다. 기존 전투·특성·오토·원정 규칙 버전은 그대로 보존한다.

검사 결과:

- 수정 전에 저장한 96개 전투 기준과 수정 후의 1초 간격 상태 스냅샷 및 최종 상태 해시가 일치했다. 출발 덱 3개·시드 2개·공격/보호 2개·적 4종·전투 규칙 0/1을 포함한다. 새 식별 메타데이터만 제외하며 표적·이동·이벤트·카드 순서·HP·통계·로그는 비교한다. identity-compat-baseline.json은 덮어쓰지 않는다.
- 검사 캐릭터를 기존 사수와 함께 넣어 같은 역할의 다른 캐릭터/슬롯/시전자/HP·피해 통계를 확인했다.
- 새 이름으로 등록한 검무·받아치기·엄호·추격을 엔진과 역할 AI의 새 이름 분기 없이 실행했다. 3타·후속 추격·보호막·피해 분담·반격·시전 대상·새 key 유지·저장 복원을 검사했다.
- 역할 기본 선호와 캐릭터 선호의 다른 표적, 도발의 최종 제약을 확인했다.
- 기존 네 명의 슬롯 순서를 바꾼 원정의 캐릭터 레벨·기초 카드 시전자·HP/회복 상한·경험치·저장/복원을 확인했다.
- 실제 브라우저 1280×720, 390×844, 320×568에서 바뀐 순서의 준비 배치·이름·역할·레벨·전투 저장·연습 표시와 가로 넘침을 검사했다. 모바일 준비 화면도 이미지로 확인했다.
- 기존 캐릭터 원정·3단계 제안/정비/복기·2단계 적 대응/독립 연습·보상 비용 4개 크기·고정 도전 24회·추격 릴레이 288전 검사를 통과했다.

핵심 도구: prototype/identity-system-check.cjs, identity-compat-check.cjs, identity-browser-check.cjs.

## 다음 범위

반복 역할의 전투와 연습은 표현할 수 있지만 영구 보유 캐릭터 목록과 원정 보상 풀·캐릭터 선택 UI는 정식 네 명 기준이다. 등록된 검사 캐릭터를 영구 원정에 임의로 출전시키지는 않는다. 다음 5단계에서 동일 역할 시험 캐릭터 한 명의 정식 키트·출발 편성·호환 카드·보상/저장·대표 행동을 연결하고, 같은 공유 카드에서도 고유 행동과 약점이 구별되는지 검증한다.

이번은 구조 변경이므로 회복 경로 편향과 최대 레벨 난도를 조정하지 않았다. 기존 3단계에서 기록한 균형 한계는 계속 남아 있다.
