# 8단계 1차 — 콘텐츠 제작과 검증 기준

적용 버전: `content1`. 대량 제작 전에 같은 형식으로 정의하고 검사하는 첫 제작 흐름을 만들었다. 플랫폼·캐릭터 판매·결제·성우 범위는 아직 확정하지 않는다. 현재 소규모 프로토타입에서 상업적 제작 비용이나 수익성을 입증한 단계가 아니다.

## 제작 경로

| 종류 | 재사용하는 것 | 추가로 확인할 것 |
|---|---|---|
| 기존 효과의 캐릭터 | 역할 AI, 기본 수치, 공유 기술, 카드 평가·특성, 행동 잠금 | 소유 시 기초 키트, 출발 덱 호환, 고유 인상·대가, 보상, 저장, 초상화·대사 |
| 기존 효과의 적 | 적 역할 AI, 표적 선호, 기존 카드, 위치·주기 | 서로 다른 대응 방법, 준비 화면 설명, 조건을 통제한 비교 |
| 새 패시브·자원·효과 | 식별·저장·관전의 기존 구조 | 실행 규칙, AI 평가, 취소·사망, 연쇄 상한, 저장 버전, 실제 효과·연출 검사 |

재사용형도 밸런스와 아트 작업이 필요하다. 새 효과형은 전투 엔진과 오토·저장까지 작업 범위가 커진다. 작업 시간을 추정해 숫자로 고정하기보다 수정한 영역과 검증 범위를 기록한다.

## 캐릭터 제작 양식

`prototype/content-character-template.json`은 제작 전용 예제다. 단일 공격 기초 카드와 공유 3타 보상 카드를 가진 사수 한 명을 **별도 Node 프로세스에서만** 등록한다. 실제 게임의 캐릭터 목록이나 유저 저장을 바꾸지 않는다.

필수 항목:

1. 안정적인 캐릭터 ID, 역할, 두 태세, 기초 카드와 원정 보상 목록.
2. 기본 행동 수치와 기존 캐릭터 대비 대가. 상위 수치만 늘리는 구성은 출시하지 않는다.
3. 카드 ID·효과·명령 시간·준비 시간·사본 상한·획득 경로·설명. 모든 카드에 유효한 특성이 있어야 한다.
4. 공유 기술 프로필. 현재 자동 제작 예제는 사수 자리의 단일 공격·연속 공격을 지원한다. 새 AI·패시브·효과는 자동 통과시키지 않는다.
5. 연출 중요도와 그림 제작 항목. 예제의 `shared-shot`은 제작 분류 문자열이며 자동으로 아트를 생성하거나 런타임 그림에 연결하는 기능은 아니다.
6. 출발 덱에서 바뀌는 기초 카드와 사용할 파티 자리. 소유 시 기초 키트가 함께 제공되어야 한다.

검사 명령:

```text
node prototype/content-character-audit.cjs
node prototype/content-character-audit.cjs <제작-정의.json>
node prototype/content-authoring-check.cjs
```

검사는 JSON만 읽으며 제작자가 제공한 코드를 실행하지 않는다. 별도 환경에서 등록한 다음 소유·기초 덱·역할 AI·보상 기술의 실제 피해·전투 중간 저장 복원·원정 저장을 검사한다. 특성 누락·잘못된 효과·새 AI·중복 ID·연속 타격 순서·출발 덱 오류를 거부한다. 통과가 출시나 게임성의 완성을 의미하지 않는다.

라이브 적용 시에는 등록 순서(카드→공유 기술→캐릭터→시전자 규칙→연출), 출발 선택 UI와 덱 변환, 보상 후보, 실제 카드 이미지, 관전 초상화·동작·대사, 새 캐릭터 저장과 기존 저장을 확인해야 한다. 현재 사수 선택 UI를 모든 역할로 확장하거나 파티 인원을 늘리지는 않았다. 궁극기의 새 준비 조건은 별도 기능 검증이 필요하다.

## 전체 목록과 적 정의 검사

`prototype/content-catalog.js`의 제작 버전은 1이다. 현재 목록의 특성·기초 키트·획득 경로·사본 상한·시전자·연출 식별을 검사한다. 새 적 정의는 ID·버전·의도·대가·2~4개 대응 방법·실제 전투 정의로 구성한다. `validatePack`과 `record`를 함께 사용하여 기존 저장·연습 규칙에 맞는 전투를 만든다.

```text
node prototype/content-audit.cjs
node prototype/content-audit.cjs <적-정의.json>
node prototype/content-check.cjs
node prototype/content-browser-check.cjs
```

실패 시 종료 코드는 1이다. 알 수 없는 상위 필드·미지원 버전·한 가지뿐인 대응·잘못된 좌표·존재하지 않는 효과·적의 플레이어 궁극기 사용을 거부한다. 이 검사는 저장 규칙 호환 검증이며 모든 적 전술의 설계 오류를 판정하는 도구는 아니다.

## 첫 확장 체험 — 교차사격 진지

거점의 **새 전투 체험**에서 지원 사수 또는 리아로 시작한다. 전열 차단과 양쪽 사수의 개전 지원가 추격을 기존 효과로 조합했다. 광역으로 함께 압박하거나, 한쪽을 집중 제거하거나, 도발·보호로 버티며 전열을 돌파하는 구성을 비교한다. 기본 추격 덱·공격 방침·추천 배치의 실제 자동전투를 기준으로 제공한다.

체험은 레벨 3·시드 81001·만전 체력으로 고정하며 덱·배치·방침을 연습에서 변경할 수 있다. 보상·경험치·영구 성장 기록은 지급하지 않는다. 진행 중인 원정과 저장은 그대로 유지한다. 기존 원정 경로·적·보상 풀을 바꾸지 않았다.

72전 비교(두 사수 × 세 덱 × 두 방침 × 세 시드 × 레벨 1/3)는 모두 승리했다. 레벨 1에서 호위·추격·공명 평균 종료 시간은 각각 약 30.63·27.44·24.07초였다. 다른 구성의 전투 흐름은 나왔으나 **도전 난도나 균형을 입증하지 못했다.** 현재는 제작·연습 흐름을 확인하는 쉬운 체험이며 일반 원정 편입을 보류한다. 한 적을 추가한 표본으로 이전 모든 구성의 우열을 판정하지 않는다.

각 비교 전투의 중간 저장 복원 후 전체 상태가 일치했고, PC·모바일 3개 크기에서 두 사수 체험·덱 변경·실제 결과·거점 복귀를 확인했다. 원정 상태와 브라우저 저장은 체험 전후 그대로였다. 기존 7단계의 완주·패배·재준비 검사와 기존 96전 추적 비교도 유지한다.

## 다음 확장 기준

- 우선 이 체험에서 덱·배치의 차이가 읽히는지 확인하고 난도를 조정한다. 일반 원정 편입 시 콘텐츠 버전을 올리고 기존 원정은 보존한다.
- 신규 보상·캐릭터는 해결 방식의 차이를 먼저 검증한다. 단순 상위 카드, 필수 전용 캐릭터, 원정 보상의 영구 소유로 바꾸지 않는다.
- 성장 목표·기록 확장과 플랫폼·획득/판매·아트·음성 범위는 후속 항목이다. 현재는 무료 시험 캐릭터 소유 규칙이며 상업적 권리·계정·결제 체계를 구현하지 않았다.
- 7단계의 첫 원정 이해도·관전 재미·궁극기 보유 체감, 기존 회복 경로 편향과 상한 난도는 여전히 플레이 및 균형 검증이 필요하다.
