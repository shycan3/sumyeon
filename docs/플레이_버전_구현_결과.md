# 브라우저 플레이 버전 구현 결과

작성일: 2026-10-06

후속 설계 안내: [캐릭터와 원정 카드 설계](캐릭터와_원정_카드_설계.md)는 보상 카드의 영구 수집을 원정 한정 획득으로 변경한다. 아래는 기존 규칙의 구현과 검증 기록이며, 새 캐릭터 구조·보상 초기화가 구현됐다는 뜻은 아니다. 최신 제작 순서는 [개발 로드맵](개발_로드맵.md)을 따른다.

셀프 평가 후 수정한 현재 규칙과 검증 방법은 [셀프 피드백 개선](셀프_피드백_개선.md)에 기록했다. 아래 초기 검증 수치는 개선 전 버전의 결과다.

사용자가 중간 피드백 없이 가능한 분야를 함께 만들도록 요청한 범위에 따라, 단일 전투를 거점·덱 편성·출정·영구 수집·저장까지 연결했다. [게임 실행](http://127.0.0.1:8765/), 조작과 검사 방법은 [README](../prototype/README.md)에 정리한다.

## 플레이할 수 있는 전체 흐름

`거점·덱 편성 → 무작위 출정 경로 → 전투·카드 보상·덱 교체 → 회복 또는 강화 → 카드 확보 → 최종 보스 → 성공/실패 정산 → 수집한 카드로 다음 출정`

열 개 방을 방문하며 네 번째·여덟 번째 방에서 새 카드를 영구 확보하고 마지막 방에서 보스와 싸운다. 경로의 방 선택지 배치·적 조합·보상 후보는 출정마다 달라진다. 파티는 네 역할로 고정하고 덱은 역할 비율을 자유롭게 정한다.

## 요구와 구현·확인 근거

| 분야 | 구현 | 확인 근거 |
|---|---|---|
| 전투 고도화 | 역할별 태세·보호·도발·밀치기·거리 유지·회복·둔화, 공용 명령과 대기·리롤 | `engine.js`, 규칙 검사와 브라우저 조작 |
| 준비시간 | 일반 즉발·강한 기술 준비와 기존 준비시간 설정 | `data.js`, 즉발/지연 효과 검사와 두 설정의 실제 출정 완주 |
| 적 AI | 실제 손패·덱 순환·명령 회복, 공개 전장에 따른 카드·태세 판단 | `engine.js`, 적 카드 소비 기록·덱 검사와 실제 교전 |
| 덱·카드 | 카드 20종, 개별 카드 20장 덱·5장 손패, 편성 제한·프리셋 | `data.js`, 덱 유효성·중복·역할 간 교체 검사와 화면 조작 |
| 출정 | 10개 방·분기 선택·일반 적 5종·강적·최종 보스 | `campaign.js`, 서로 다른 지도 검사와 실제 보스 완주 |
| 획득·강화·회복 | 후보 3장 중 1장, 다음 전투 편성, 개별 카드 1회 진화, HP 유지·복귀 | 규칙 검사, 브라우저 보상 교체·강화·경로 진행 |
| 수집·레벨 | 두 확보 지점·성공/실패 정산·강화 초기화, 레벨 상한 5 | 확보 중복 방지·실패 손실·상한·다음 출정 검사 |
| 저장·이어하기 | 전투와 출정 자동 저장, JSON 내보내기/가져오기, 입력 검사 | 전투 중 새로고침·보상 후보 보존·저장 파일 복원·잘못된 파일 거부 |
| 화면·안내 | 거점·지도·수집·설정·설명·전투/출정 결과, 키보드·배속 | 브라우저 화면 검토·키보드 확정·작은 화면의 가로 넘침 검사 |

구현 파일은 `prototype/data.js`, `engine.js`, `campaign.js`, `app.js`, `style.css`, `index.html`로 분리했다. 기존 단일 전투는 `lab.html`에 보관하고 기존 규칙 검사도 유지했다.

## 검증 결과

- `node prototype/smoke.cjs`: 덱·지도·시간 정지·대기·적 손패·리롤·도발·차단·보호·전투불능·범위 공격·각 카드 실행·보상·강화·확보·실패·레벨·저장·실제 보스 출정 검사 통과.
- `node prototype/browser-check.cjs`: 실제 브라우저에서 편성·설정·전투 조작·대기·키보드 확정·새로고침·보상 교체·진화·두 확보 지점·보스 완주·수집·파일 저장 복원·잘못된 파일 거부·작은 화면 검사 통과.
- `node prototype/legacy-smoke.cjs`: 보관한 이전 단일 전투의 검사 통과.
- 두 준비시간 설정과 안전/위험 경로를 각각 12개 시드로 실행했다. 현재 자동 전략에서 안전 경로는 두 설정 모두 12회 완주했고, 위험 경로는 일반 즉발 설정에서 1회, 기존 준비시간 설정에서 0회 완주했다. 이 전략은 새 보상을 적극적으로 덱에 넣지 않고 강적을 연속 선택하므로, 모든 위험 경로나 플레이어 전략의 승률을 뜻하지 않는다.

자동 전략은 실제 기본 행동·카드·피해·회복 판정을 사용한다. 별도의 규칙 검사에는 확보·실패 등 특정 상태를 직접 구성하는 사례도 있으며, 실제 전투로 이어지는 출정과 브라우저 검사를 함께 사용해 전체 진행을 확인했다.

## 이번 버전의 설계 선택

첫 명령은 5초, 일반 카드 효과는 즉발을 기본으로 정했다. 강격·화살비·일부 특수 기술은 준비시간이 있으며 설정에서 기존 준비시간으로 비교할 수 있다. 적 공격은 대응 가능한 예고를 제공한다. 명령 회복·손패 교체 2회·도발 4초·회복 방 30% 등 수치는 첫 플레이용 기준값이다.

방패병 보호는 가까운 아군의 최종 피해 20%를 한 번만 대신 부담하며, 옮긴 피해에 보호자의 추가 피해 감소를 적용하지 않는다. 도발은 범위 공격을 바꾸지 않는다. 전투 80초 이후 적의 압박이 단계적으로 증가하도록 정해 마지막 적을 남겨 회복을 반복하는 행동에 비용을 줬다. 이 수치와 압박 방식은 후속 플레이 피드백에 따라 조정할 수 있다.

브라우저 한 구역의 플레이와 재도전이 가능한 상태다. 최종 재미·선호·난이도의 확정은 사용자의 플레이 피드백으로 이어가며, 정식 플랫폼·세계관·최종 아트·상용 출시 범위는 별도의 제작 방향 결정으로 남긴다.
