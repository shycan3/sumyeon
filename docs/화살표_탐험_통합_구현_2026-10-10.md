# 원정·탐험·덱 특성 통합 구현

기준: [사용자 제공 Exploration GDD 0.1](SUMYEON_Expedition_System_GDD_2026-10-10.md). 추가 결정: 선택 전투와 필수 전투를 함께 둔다. 작성일: 2026-10-10.

## 실행과 범위

`prototype/`에서 `python -m http.server 8765 --bind 127.0.0.1` 실행 후 `http://127.0.0.1:8765/exploration.html`을 연다. 기존 `party-expedition.html`, `party-v3.html`, 스토리·과거 실험 진입점은 계속 독립 실행한다. 새 저장 키는 `sumyeon-exploration-session-1`이며 은행·해금·현재 원정·정산을 하나의 레코드로 저장한다.

E0~E6의 기능을 연결했다. E7을 위한 직접 플레이 응답·원정 로그 내보내기·시드 실험 도구도 제공한다. **사람 2~3명, 이후 5~8명의 실제 재미 관찰은 아직 수행하지 않았으며, E7의 재미 통과를 주장하지 않는다.** 대규모 아트와 계열 10종 확대는 그 관찰 이후의 작업이다.

## 구현 구성

- `exploration-map.js`: 시드별 심층 그래프, 방향 슬롯, BFS 검증, 발견 지도, 좌표 기반 무전.
- `exploration-core.js`: 원정·지상 상태, 비용·회복 소수 버퍼, 조사, 전투 연결, 보상, 하강, 귀환·부분 회수, 해금, 저장 검증.
- `exploration-combat.js`: 기존 전투의 독립 하위 클래스, 원정 덱 사본 특성·조건부 발동·프리뷰·복구.
- `exploration-policy.js`: 현재 손패와 공개된 적 의도만 읽는 자동 전투 정책. 미래 카드/다음 적 의도는 평가하지 않음.
- `exploration-app.js`, `exploration.html`, `exploration.css`: 지상 준비·2D 배경·화살표·전투·결과·설정·관찰 UI.
- `exploration-check.cjs`, `exploration-browser-check.cjs`: 도메인·실제 UI 통합 검사.
- `exploration-study.cjs`: 두 정책의 결정론적 원정 시뮬레이션과 개별 결과 기록.

## 미결 항목의 시험 정책

최종 설정이 아니다. `DEFAULTS`, `TRIAL_POLICIES`, 카드 특성 데이터로 분리하고, 출시·세계관 규칙으로 선언하지 않는다.

| 항목 | 현재 시험값/정책 | 위치·교체 방식 |
|---|---|---|
| 시간 | 65 | DEFAULTS.initialTime / 지상 시험 설정 |
| 연결구 최단거리 | 15간선 | minExitDistance / BFS |
| 심층 | 3개, 최심층 수문장 후 자발 귀환 | maxDepth(1~3) |
| 이동/조사/교전/하강 | 1/2/3/1 | 각 비용 설정 |
| 자연 회복 | 실제 소비 시간당 최대HP의0.5%, 생존자만 | regenRate / applyCost |
| 시간 초과 HP | 비용1당 생존자별 최대HP의3% | hpCostRate / TRIAL_POLICIES.hpDistribution |
| 시간 부족 | 남은시간+나머지HP | costPolicy='mixed'; 전액HP 대안도 지원 |
| 개인 전투불능 | 기본은 전원 전투불능 때 실패 | failurePolicy='all-downed'; 'any-downed' 시험 정책 분리 |
| 전투 귀환 | 금지 | TRIAL_POLICIES.combatEscape |
| 승리 직후 회복 | 0 | TRIAL_POLICIES.victoryHealing; 기존 원정 고정 회복을 중복 적용하지 않음 |
| 실패 손실 | 이번 원정 골드40%; 손실은 정수 내림 | lossRate; 지상 은행/해금 손실 없음 |
| 선호 계열 | 0~3개, 각 ×1.5 | preferenceWeight; 개수별 별도 배수 없음 |
| 계열 분류 | 대표 특성1개; 기능 분류와 ID·표시 이름 구분 | traitFor + TRAITS |
| 특성 단계 | 2/4/6; 낮은 수치효과는 상위로 대체, 조건부 단계는 추가 | 계열별 breakpoints와 stackingMode |
| 해금 | 기본24종 + 골드12로 미해금1종 | unlockCost / 개발자 해금 도구 |
| 중복 해금 | 시험에서는 중복 없이 신규만 | TRIAL_POLICIES.unlockDuplicates |
| 추가 영구 재화 | 없음 | 골드 외 자원은 사용자 결정 전 도입하지 않음 |
| 맵 생성 | 유효한 격자 간선으로 직접 구성 + 최종 BFS + 검증 실패시 결정론적 안전맵 | 순환 간선도 검사; 수백 회 무작위 재시도 불필요 |

문서 예시의 시간250은 출시값이 아니므로, 3심층의 경로·조사·교전 합계 안에서 시간0/HP 탐험을 확인할 수 있는65를 기본 시험값으로 사용한다. ‘더 재미있다’는 수치 검증 결과로 해석하지 않는다. 화면에서250으로 바꿔 비교할 수 있다.

소수 HP를 전투 엔진에 직접 넣지 않는다. 회복/지불의 백만분의1HP 잔여 버퍼를 보관하며 정수분만 기존 HP에 적용한다. 최대HP에서 회복을 저축할 수 없고, HP0은 자연 회복에서 제외된다.

## 다섯 시험 덱 특성

기존 카드의 기능 이름(돌파·수호·교란·순환·정비)과 별도로 격류·등불·잔향·해류·정비망 ID를 부여했다. 현재는 기존 기능 분류와 1:1로 매핑하되 두 데이터 계약은 분리되어 있다. 카드별 primaryTraitId를 바꿔도 기능 태그나 기존 카드 동작을 바꾸지 않고 특성 카운트만 변경할 수 있다. 어댑터의 DEFINITIONS에 primaryTraitId·functionTags·baseWeight를 제공하며 기존 전투의 카드 정의를 직접 변경하지 않는다.

| 특성 | 2장 / 4장 (대체) | 6장 (추가, 라운드당1회) |
|---|---|---|
| 격류 | 직접 피해+1 / +2 | 노출된 대상 돌파의 첫 직접 타격+4 |
| 등불 | 보호+1 / +2 | 보호가 있는 대상에게 유료 수호 후1장 뽑기 |
| 잔향 | 약화+1 / +2 | 약화된 대상에게 유료 교란 후1장 뽑기 |
| 해류 | 첫 유료 순환 뒤 추가 뽑기1 / 2 | 선행 카드 지출2 이상일 때 유료 순환 후 에너지1 회수 |
| 정비망 | 회복+1 / +2 | 다친 대상에게 유료 정비 후1장 뽑기 |

처리 순서: 원정 덱에서 단계 결정 → 해당 카드 기본 효과에 낮은 단계 보정 → 기존 캐릭터 조건/카드 연계·노출 처리 → 격류 조건부 첫 타격 보정 → 보호/HP 피해 → 기존 실행 특성 → 뽑기·자원형 조건부 특성 → 저장. 같은 순서를 프리뷰·실제 실행·복구가 공유한다. 유료 카드 조건과 라운드당 제한은 화면 설명에 명시한다. X코스트의 고정 특성 보너스는 X 배율 계산 뒤에 적용하며, 캐릭터 특성의 별도 보호에는 중복 보정하지 않는다. 시작 덱에는 격류5/등불4/잔향1이 있으며 즉시 일부 단계가 켜지는 것이 정상이다.

## 재현 명령과 검증의 한계

```powershell
node prototype/exploration-check.cjs
node prototype/exploration-browser-check.cjs
node prototype/exploration-study.cjs 30
node prototype/party-expedition-rules-check.cjs
node prototype/party-expedition-integration-check.cjs
```

브라우저 검사는 기존 설치된 playwright를 먼저 사용하며, 없으면 Codex 개발환경의 런타임 경로를 사용한다. SUMYEON_PLAYWRIGHT_MODULE로 모듈 경로를 지정할 수 있다. `SUMYEON_BASE_URL`로 서버 주소를 바꿀 수 있다. Node 도메인·시뮬레이션에는 외부 라이브러리가 필요 없다.

30개 도메인 검사, 1242px·390px 원정 UI 및320px 실패·귀환 연출 검사, 기존 규칙16·기존 통합23개 검사를 확인했다. 새 모드의 자동 실험은 정책·시드 표본에 대한 기술 증거다. 사람의 재미, 계열/캐릭터 균형, 최적 전략의 다양성이 입증된 상태는 아니다. 30개 시드에 직접 하강/조사 우선 두 정책을 적용한60개 기술 실험은 모두 정상 귀환했다(직접 하강 심도3:30, 조사 우선 심도2:6·심도3:24). 자발적 귀환을 승리로 바꾸어 계산하지 않는다. 전체 시스템이 연결되어 있으므로 이후 실제 한 판 관찰로 원정 시간·초과HP 단가·조사 밀도·계열 보상을 조정한다.

## 2026-10-11 조사 가독성 개선

사용자 관찰: 화면 아래의 술식 기록 카드가 눈에 띄지 않았다. 조사 카드를 방향 버튼 사이 중앙으로 이동하고 실행 버튼을 강조했다. 원정 규칙과 저장 형식은 바꾸지 않았다. 브라우저 검사에 중앙 배치와 이동 버튼 비겹침 검증을 추가했으며, 1242px·390px 원정 흐름 및 320px 실패/귀환 검사를 통과했다. 이 관찰은 UI 수정의 근거이며 E7 전체 재미 관문 통과를 뜻하지 않는다.
